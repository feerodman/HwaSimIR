TCP多核传输（>=v2.4.0）

ZRDDS提供TCP多核传输功能，支持用户为读者或写者指定所使用的核，实现绑核传输，当用户为某一个读者或写者配置了多个核时，该实体将会创建同样数量的线程，并一一绑定用户所指定的核，进行多核并发传输，此特性可极大提高ZRDDS在TCP传输模式下性能。当前此特性只支持C、C++版本。

掩码值说明

在绑核时，需要指定所绑核掩码值的十进制数值，掩码值、需指定的十进制值、与对应CPU序号关系如下：

CPU序号 对应掩码值 掩码值对应十进制
0 0x00000001 1
1 0x00000010 2
2 0x00000100 4
3 0x00001000 8
... ... ...

默认情况下，需要通过设置上述掩码对应的十进制值进行绑核。除去此种方式外，ZRDDS为用户提供sysctl.global.use_cpu_id配置项，当设置此配置项为true时，支持直接使用CPU序号代替掩码。 注意：当CPU数量超过32时，必须使用sysctl.global.use_cpu_id进行配置。

配置说明

发送端配置说明

发送端主要有如下配置：

所属实体 配置项 含义 默认值
dpf sysctl.global.net.tcp_send_batch_len 小包并包发送，指定并包发送长度 0
dp sysctl.global.use_cpu_id 使用cpu序号代替掩码 false
^ usertraffic_receive_addresses 使用TCP多核传输时，地址头需使用tcpv4_cc N/A
dw sysctl.dw.asynchronous_send_thread_max_flush_delay<td>使用TCP多核传输并开启小包并包发送时，自动发送周期 {0,100000000}
^ sysctl.dw.asynchronous_send_thread_affinity_masks 使用TCP多核传输时，发送端绑核掩码。可通过设置多次来绑多个核 N/A

  • sysctl.global.net.tcp_send_batch_len

    默认值为0，表示不启用小包并包发送，即不考虑用户此次要发送的包的大小，直接发送。 当设置了指定值，例如设置值为N，表明当用户要发送的包大小积攒到N时，再统一发送。 例如用户第i（i从1开始）次发送的数据大小为ni当n1 + n2 + ... + nk > N时，发送n1到nk-1包，否则将第k次发送数据暂存不进行发送。 以具体数值为例： 设置sysctl.global.net.tcp_send_batch_len值为8388608（8M）

    用户第一次发送数据大小为5M，此时要发送数据未到达指定发送大小8M，则此包将暂存下来，此次并不进行发送。

    用户第二次的发送数据大小为4M，此时要发送数据大小为5M+4M > 8M，由于最大发送数据量为8M，而此时累计数据量为9M，因此并不能一次将两包全部发送，此时只发送第一包大小为5M的数据，暂存第二包大小为4M的数据。

    用户第三次的发送数据大小为4M，此时要发送的数据大小为4M+4M = 8M，由于最大发送数据量为8M，而此时累计数据量刚好为8M，因此可一次将两包全部发送，此时暂存数据大小为0。

  • sysctl.global.use_cpu_id

    默认为false，表示不开启此功能，此时需要使用CPU掩码值的十进制指定要绑定的CPU。 当配置了sysctl.global.use_cpu_id可配置项时，可直接使用序号值代替掩码值，例如： 当用户指定使用CPU0时，可直接填入数值0； 当用户指定使用CPU1时，可直接填入数值1； … … 注意：当CPU数量超过32时，必须使用sysctl.global.use_cpu_id进行配置。

  • usertraffic_receive_addresses

    用户数据使用的地址监听列表，设置方式可参照ZRDDS用户手册10.30。

  • sysctl.dw.asynchronous_send_thread_max_flush_delay

    用于设置使用TCP多核传输并开启小包并包发送时的自动发送周期。默认值为100ms，当不配置sysctl.global.net.tcp_send_batch_len时，此配置项无效。此配置项用于应对用户数据未达到sysctl.global.net.tcp_send_batch_len所设置的值，且无新数据发送时，之前积压的数据无法及时发送的情况。设置sysctl.dw.asynchronous_send_thread_max_flush_delay为T，则表明每隔时间T，就将未发送的用户数据全部发送，不论积压数据是否达到sysctl.global.net.tcp_send_batch_len所设置的值。

  • sysctl.dw.asynchronous_send_thread_affinity_masks

    使用TCP多核传输时，发送端绑核掩码。可通过设置多次来绑多个核。例如在配置文件中设置4次sysctl.dw.asynchronous_send_thread_affinity_masks，且值分别为0,1,2,3（此处以开启sysctl.global.use_cpu_id为例）。则在发送过程中，ZRDDS将创建4个发送线程，并分别绑定CPU0，CPU1，CPU2，CPU3进行数据发送。即设置n次sysctl.dw.asynchronous_send_thread_affinity_masks，ZRDDS会为用户创建n个发送线程，分别绑定sysctl.dw.asynchronous_send_thread_affinity_masks所设置的值。

接收端配置说明

接收端主要有如下配置：

所属实体 配置项 含义 默认值
dp sysctl.global.use_cpu_id 使用cpu序号代替掩码 false
^ usertraffic_receive_addresses 使用TCP多核传输时，地址头需使用tcpv4_cc N/A
^ tcp_receive_thread_affinity_masks 使用TCP模式传输时，接收端绑核掩码。可通过设置多次来设置多个可绑核 N/A

  • sysctl.global.use_cpu_id

    与发送端配置说明中一致。

  • usertraffic_receive_addresses

    与发送端配置说明中一致

  • tcp_receive_thread_affinity_masks

    与发送端sysctl.dw.asynchronous_send_thread_affinity_masks配置相似，不同之处为此处为接收线程绑核且tcp_receive_thread_affinity_masks仅指定接收端可绑哪些核，接收线程数量不取决于此配置项的设置次数，仅取决于与之匹配的发送端线程数量。
