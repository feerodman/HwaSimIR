# 并发传输特性说明

## 数据类型以及通信实体

当前并发传输特性仅支持新增的内置数据类型 `DDS_ConcurrentZeroCopyBytes`，其数据结构以及其成员含义，参见下面代码块。对应的实体包括：

实体 | C | Cpp
--- | --- | ---
数据读者 | `DDS_ConcurrentZeroCopyBytesDataReader` | `ConcurrentZeroCopyBytesDataReader` |
数据写者 | `DDS_ConcurrentZeroCopyBytesDataWriter` | `ConcurrentZeroCopyBytesDataWriter` |
类型支持 | `DDS_ConcurrentZeroCopyBytesTypeSupport` | `ConcurrentZeroCopyBytesTypeSupport` |

```c

/**
 * @typedef struct DDS_Buffer
 *
 * @brief   DDS缓冲区。
 */

typedef struct DDS_Buffer
{
    /** @brief   首地址。 */
    char* buffer;
    /** @brief   缓冲区长度。 */
    unsigned int length;
} DDS_Buffer;

/**
 * @typedef struct DDS_ConcurrentZeroCopyBytes
 *
 * @brief   用于多线程并发发送的零拷贝数据结构。
 */

typedef struct DDS_ConcurrentZeroCopyBytes
{
    /** @brief   最大的离散空间个数。 */
    static const DDS_Long S_MAX_FRAG_NUM = 8;
    /** @brief   样本的总长度。 */
    DDS_Long totalLength;
    /**
     * @brief   - 在发送时，设置 #curLength == #totalLength
     *          - 在接收端，当读取新的样本时，应设置为0，
     *          - 在接收端，当继续读取未完整样本时，应保持已接收的样本长度不变；
     *          - 在接收端， #curLength == #totalLength 时表示已经完整。
     */
    DDS_Long curLength;
    /**
     * @brief   - 在发送端，指向需要发送的数据；
     *          - 在接收端, 如果 #contiguous.length > 0 时，将拷贝分片负载到该缓冲区，此时 #contiguous 应由用户提供空间。  
     *          - 在接收端，如果 #contiguous.length == 0 时，分片将以多个缓冲区的形式存储在 #fragments 中；
     */
    DDS_Buffer contiguous;
    /**
     * @brief   - 在发送端，忽略该成员。
     *          - 在接收端，如果用户未提供连续空间，元素依次代表分片（发端将完整的数据切分为多个分片，每个线程负责发送其中一个分片）负载，在回调结束后，该成员指向的空间将失效。
     *          - 在接收端，如果用户提供了连续空间，则只有首个分片有效，并指向用户 #contiguous
     */
    DDS_Buffer fragments[DDS_ConcurrentZeroCopyBytes::S_MAX_FRAG_NUM];
    /** @brief   分片的个数。 */
    DDS_Long fragmentNum;
} DDS_ConcurrentZeroCopyBytes;

```

## QoS配置

涉及到两个QoS配置：

- PublisherQos.asynchronous_publisher.asynchronous_concurrent_thread，设置Publisher实体中的异步发送线程个数；
- DataWriterQos.publish_mode.asynchronous_concurrent_thread，设置DataWriter并发传输的线程个数，等于1时同步发送，且应小于PublisherQos.asynchronous_publisher.asynchronous_concurrent_thread值；
- DataWriterQos.publish_mode.kind，设置为 DDS_ASYNCHRONOUS_PUBLISH_MODE_QOS 时才会启用并发传输；

## 注意事项

- 仅支持DDS_ConcurrentZeroCopyBytes数据类型；
- 仅支持Ping-Pong模式的发送场景，即提交完一包数据后需确认该数据已经成功传输到远程再提交后续的发送任务；
- 当前仅支持take_next_sample函数读取数据；

## 示例代码

参见 examples/ConcurrentWrite。

### 场景描述

- 接收端上线后，向发送端发送空闲标识，并等待接收数据，处理完成后再发送空闲标识；
- 发送端收到空闲标识后，并发传输大块数据到接收端，并等待下一个空闲标识；
- 其中接收端发送空闲标识的使用udp进行通信；
- 发送端使用tcp并行传输进行通信；
- 支持多个接收端；

### 编译

- 将ConcurrentWrite/make.sh中的DDS路径修改为安装路径；
- 执行make.sh可生成concurrent_example程序；

### 运行

- 修改concurrent_example_qos.xml中的IP地址为本机地址；
- ./concurrent_example r 运行接收端；
- ./concurrent_example s 运行发送端；
- 其他可配置参数参见程序的help信息；
