# P11：SWIR / MWIR 红外物理链路修复、民用模型验证与实机交付

## 任务目标与本轮授权

本程序用于红外成像仿真研究。本轮主要完成 SWIR、MWIR 的真实生产成像链路，找出并修复目标红外效果异常的原因；NIR 只保留兼容回归，不再作为主验收波段。采用通用试验几何、民用车辆、民用飞机或受控热源验证，不依赖特定装备的真实热特征拟合。

这是一项实施任务，不是仅写评估报告：阅读证据 → 复现 → 定位实际出图路径 → 修改 → 数值测试 → Windows 出图 → RK3588 部署 → 保存示例 → 回归。

本轮撤销 P10“只改通用图形，不改红外材料、温度、热区、尾焰、主动照明和物理算法”的任务范围限制。可以修改 HwaSimIR.cpp、相关 IR 类、实际着色器、材料与光谱配置、数据处理脚本，以及必要的 Qt 波段选择代码。也不以“原有 49 个文件一个都不能改”为验收目标：确有需要的文件可以增量修改，但必须先识别、备份并保留用户原有改动，不能覆盖或回退用户成果。

仍需保护：CommonData/既有 DDS 与 UDP/TCP 协议布局、身份路由、输入顺序与逐帧对应、控制响应、录像与标注身份、模型原始文件、现有启动方式、可启动的完整回滚包。不要无关重构、整体升级 SDK/驱动、修改系统时间或许可证。原始模型只读，几何修复及转换输出为有来源哈希的派生资产。

先在现有工具链上完成任务，不迁移引擎，不把“换 Vulkan / 换全部驱动 / 重做 UI”当作红外修复前提。开发机可下载经许可的公共资料和资产，交付包与 RK3588 运行不得依赖互联网。

### 2. 记录基线，先复现再修改

P10 的正确结论是：正常启动示例为 NIR 0.7–1.1 μm；MWIR 图形/profile 检查不等于目标辐射正确；SWIR 尚未接通。P10 正常图中的目标只有几十像素且带标注，不能作为材料细节验收样本。

当前可重点检查的具体问题，必须在最新源码上重新确认：

1. `IR/IRRadianceModelV2.cpp::bandAveragePlanckRadianceWm2SrUm` 对非 MWIR 仍走中心波长；不能把 SWIR 1.80 μm 单点当完整 SWIR 波段积分。
2. `evaluateComponents` 的旧 `reflectedRadiance` 是 reflectance、solarStrength、ndotl、textureLuma、solarReflectanceWeight 的无量纲乘积，却被加到物理辐亮度。当前 CPU 的 M1 MWIR 分支仍包含它；另算出的 solarReflectedRadiance、skyReflectedRadiance 未在这个分支以同样方式使用。查清 GPU 是否另行计算、是否存在 CPU/GPU 双重或不一致的反射。
3. 某条 tauUp 回退把接近零且没有 reason 的透过率改成 1。合法 τ=0 必须表示不透明，不能因为值小就变成完全透明。区分这条旧分支与 M1 的 m1TauUp，确认实际触发条件，禁止仅凭源码存在就认定当前画面已触发。
4. `default_SWIR.json` 为 1.5–2.5 μm，而现有代码固定 1.1–2.5；`default_VIS-SWIR.json` 为 0.5–1.7，而 VIS 固定 0.4–0.7。不能只改名字、放宽比较或回退 NIR 解决。
5. `HwaSimIRRuntime.ini` 中 M1 正式 NIR/MWIR 已开启，旧 Stage3/Stage5 MODTRAN 开关仍可为关闭。必须追踪真实消费链，不要把旧开关全部打开造成重复贡献。
6. `M1RadianceDisplay` 当前 MWIR 公共窗口上限为 2.5 W/(m²·sr·μm)。检查它是在何处缩放、是否不可逆裁剪、是否使热源和机体在 Stage6 前失去动态范围。窗口本身不自动等于算法错误，须用原始值与饱和像素证明。
7. `Stage5AeroThermal/ApplyAeroToRadiance=false`；`ActiveIlluminator` 默认 NIR、0.85 μm、带宽 0.05 μm，当前声明只支持 NIR/MWIR。不能期待这个 NIR 光源直接产生 SWIR/MWIR 带内照明效果，也不能把“计算过气动温升”当“图像已使用”。
8. SWIR/MWIR 的太阳、背景、云雾、热源、主动光、传感器与显示，是否真正使用同一套已解析的光谱定义和单位。

输出完整数据流：协议/配置 → 模型和材质 → 温度/照明 → 大气查询 → CPU 分量 → shader 输入 → GPU 原始辐射附件 → 显示窗口/AGC/AA → 编码 → 接收 PNG。

针对实际异常帧至少完成一次 CPU 数值、shader uniform、选定表面像素读回三方对照。每个根因给出文件/函数/行号、触发配置、修复前数值、修复后数值、对应图像；能独立关闭或恢复旧项时做单因素消融。不要只列“可能因为材质/温度/大气”等猜测，也不要只改一处日志计算器。

## 二、先用可解释的模型建立数值基准，再接生产链

### 1. 模型与材质

建立少量用途明确的场景：

- 自建黑体/灰体平板、球体、多个材料样片和可控热源：温度、发射率、反射率、光照、距离均已知，用于数值真值。
- 民用车辆：优先检查仓库 GMC_Van_White 的 FLT 版本、外部引用和本机可用导入器，尝试受支持的 flt2egg/既有转换工具。必须检查转换后的尺寸、法线、UV、材质分区和贴图路径；几何转换成功不代表 Ondulus 的材料语义已迁移。
- FLT 工具确实不兼容时，改用可合法下载的公开民用车辆及民用飞机，或自建简化民用几何，不在 FLT 转换上无限停留。记录下载来源、许可、作者、哈希和转换过程；运行时优先用离线预转换资产。
- 尾焰/羽流先用受控热气体或燃烧器代理验证，不把通用代理称为真实特定发动机标定。

几何模型不会自动携带可靠的红外物性。为车漆、金属、橡胶、玻璃、热源建立显式分区和材料映射，记录光谱反射率/发射率/透射率、热容、厚度、导热或等效热参数的来源；未知值明确标为工程假设。禁止根据可见光 RGB 灰度直接认定 SWIR 反射率或 MWIR 发射率。

玻璃不使用跨波段同一透明度；不透明表面按所用角度/半球约定检查能量约束；半透明材料必须考虑透射。保留几何、法线、UV、材质 ID、温度图等诊断输出。几何非简单多边形和法线问题在派生副本中修复，原始文件保留。

### 2. 独立 CPU 物理参考

建立小型、双精度、独立于生产 shader 的数值参考，可用 Python 或 C++，禁止原样复制同一错误函数后互相验证。

对明确采用不透明、漫反射近似的表面，以光谱形式实现：

L_surface(λ) = ε(λ) B(λ,T)
             + ρ(λ)/π × [E_sun_normal(λ) max(n·s,0) V_sun
                         + E_sky_surface(λ)
                         + E_active_surface(λ)]

L_sensor(λ) = τ_LOS(λ) L_surface(λ) + L_path(λ)

上式的天空和主动光项已是抵达该表面的辐照度，不得再次无条件乘同一余弦或大气透过率。需要镜面/方向效应时引入有定义、能量受约束的 BRDF，而不是加任意亮边。

波段结果必须按真实有效响应 R(λ) 积分；分清谱辐亮度 W/(m²·sr·μm)、波段积分 W/(m²·sr) 和响应加权波段平均值，不允许不同量纲相加。若维持现有“波段平均”接口，必须明确分母、响应定义、所有调用处和转换位置。

传感器量子效率、光学透过率、相对能量响应分别定义。只有具备或显式假设了光学/像元/曝光等参数，才计算电子数、满阱和 ADC；使用 QE 时正确做光子能量换算。没有实测器件参数时采用明确命名的理想参考传感器，不冒称完成真实器件标定，也不把 ordinary_sensor_lab 的人工图像当生产验证。

最小数值测试：Planck 与积分收敛、固定材料的温度响应、真空 τ=1/Lpath=0、τ=0 保留路径辐射、低透过率、反射/光源关闭、波段外主动光零重叠、阴影、路径项只加一次、所有有效值有限且单位一致。近零值使用绝对误差，不用失真的相对误差；容差必须在修复前冻结。

对于非零且条件良好的平板 ROI，建议先以生产积分相对高精度参考误差不超过 1%、GPU 相对同语义 CPU 不超过 2% 为工程目标；接近零或有半精度量化时另列明确绝对误差与预算。不得测完后放宽阈值，也不得用该实现误差声称现实测量精度达到 1%/2%。

### 3. 接入正式图像，而不是保留为 debug-only

SWIR、MWIR 必须走正式 INIT/START、模型加载、太阳、主动光、背景/天气、原始辐射、显示、录像和接收链。

建立唯一的波段定义与响应标识，协议数值到内部枚举使用明确映射，不改变既有线协议布局。对 SWIR 范围作一次可追踪决定：存在明确传感器响应时遵循该响应；没有时本轮采用现有代码的 1.1–2.5 μm 作为理想矩形参考，备份旧 1.5–2.5 文件并生成命名明确、schema 正确的正式 profile。不要把扩大范围说成原始器件的真实带宽。MWIR 保持 3–5 μm，除非已有可追溯响应要求不同。

每次 INIT 输出 requested/effective band、范围、响应类型、profile 哈希、大气数据集、材料映射、太阳与主动光状态、物理路径版本、各关键字段“已消费/未消费”的证据。仅 JSON 解析成功不算生效。

旧经验灰度/热斑增益与物理路径隔离。机体、局部热区、热固体尾喷口与空间羽流分别处理，禁止将局部峰值加到整机，禁止羽流既加机体又单独绘制。保留原有业务状态，但物理基础图与人为强调/调试亮斑必须可区分。

恢复温度不是所有表面的瞬时实际温度。速度与高度通过环境温度、换热和热惯性影响表面温度，再影响谱辐射；不得仅乘 Mach 灰度系数。使用简化热模型可以，但说明边界条件、参数、适用范围，不宣称 CFD/实测标定。发动机开关不能瞬间加热整机；太阳转向的反射变化与太阳加热的慢响应分开。

太阳热输入应来自材料吸收的宽谱太阳能，不仅是当前相机 SWIR 或 MWIR 带内能量。保留并审计已有 NaturalSolar、宽谱加热 LUT 和六方向等效热模型，能修复复用就不另造重复链路。

原始浮点辐射在显示窗口前保留动态范围；允许已知、可逆、全场统一的数值缩放，以适配半精度范围，但必须保存比例和单位，禁止不可逆归一化/裁剪后冒称 raw radiance。物理曝光/满阱饱和与任意显示裁剪分别记录。

## 三、MODTRAN：先审计复用，再补跑 SWIR 和缺失工况

现有正式 SI 表是 NIR 1005 行、MWIR 335 行；这是聚合行数，不等于原始执行次数。当前 P10 清单没有 SWIR 正式覆盖。不要误把文件名或已有 0.3–15 μm 旧经验透过率当作完整、已验证的 SWIR MODTRAN 数据。

1. 扫描原始输入/输出、执行清单、processed 光谱表和聚合表，生成可机读覆盖清单：波段/波数、分辨率、太阳角、观测和目标高度、斜距、气溶胶、湿度、能见度、输出列、单位、来源哈希。大文件流式读取，不靠 head/tail 推断整个网格。
2. MWIR 2000–3333 cm⁻¹ 一类原始输出在原场景与实际光谱支持内优先复用；只能重积分已有的真实谱区间，不能外推生成 SWIR。
3. SWIR 按最终有效范围生成新输入。1.1–2.5 μm 对应约 4000–9090.91 cm⁻¹；边界要有足够真实采样支持并按响应精确积分。若使用 1.5–2.5 μm 的真实响应，则按其实际范围计算，不能改标。
4. 输出至少覆盖目标到传感器的 τ_LOS、纯路径热辐射与散射辐射、目标位置的太阳直达光及天空下行辐照度。主动光使用光源→表面与表面→传感器两条真实路径及光源谱形；不能不分几何地统一套 τ²。
5. 对 MODTRAN5/PcModWin5 的实际输出逐列核对。TOT_TRANS、THRML_EM、THRML_SCT、SOL_SCAT 或 SINGLE/MULT、SURF_EMIS、GRND_RFLT、TOTAL_RAD、REF_SOL、SOL@OBS 的语义以本机版本说明和表头为准。TOTAL_RAD 通常不是可直接加到自渲染目标上的纯 Lpath；SURF_EMIS/地表反射若已含目标贡献必须剔除重复项。REF_SOL/SOL@OBS 的参考位置与路径不能混用。
6. 波数谱密度到波长谱密度不能只改横坐标。确认原单位后应用 Jacobian；例如原值为 W/(cm²·sr·cm⁻¹)，转换到 W/(m²·sr·μm) 时含面积 10^4 与 |dσ/dλ|=10^4/λ_um² 两项。若原输出已是每 μm，不能重复乘 Jacobian。用同一条谱在波数域和波长域积分的一致性测试验证转换；不要用任意 10^n 缩放去追平 legacy。
7. 标量波段平均 τ 乘标量平均辐亮度一般不等于谱内乘积积分；在线近似必须对不同温度、材料、太阳/主动光谱验证误差。均匀化气溶胶的简单长度缩放不能替代未验证的气体带内透过计算。
8. 天空入射辐照度不是传感器 LOS 的一个 sky_radiance 标量。审计方向积分/角度采样与单位；若采用简化天空模型，明确其近似、场景支持和验证方式。
9. 现有样例出现太阳天顶角 45°，这不证明多太阳角已覆盖。核查完整清单，缺失的太阳角、地面民用车辆近地工况、必要高度/距离、湿度/能见度要补齐。只生成物理可行的高度—斜距组合，越界不能静默钳制冒充有效。
10. 优先利用本机有许可的 PcModWin5/MODTRAN5、既有模板和可执行入口。先跑少量标准工况，检查原始表头、量纲、积分和 CPU 图像，再扩充必要网格；不要先盲跑几千组。保留输入、输出、日志、哈希和失败重试记录。不要调用假设存在的 MODTRAN6 接口。
11. 若本机只能 GUI 操作而无法批处理，生成可导入输入及逐项手工步骤，明确阻塞点与需要用户完成的最少操作；不伪造结果。数据等待期间继续完成解析、CPU 基准、真空场景和可验证的 MWIR 修复，但相关生产数据门禁保持失败。
12. MODTRAN 是大气计算，不会生成模型的材质参数、表面温度或真实尾焰光谱。缺失这些数据应分别处理，不要以“全部重新跑 MODTRAN”掩盖其它模型问题。

RK3588 运行时只读取审计通过的紧凑 LUT/预积分数据。可用离线预积分、少量谱通道和低频状态更新保性能，但必须与 CPU 光谱参考比较误差，不能用 τ平均×L平均且不做误差验证。禁止实时逐帧运行 MODTRAN。

## 四、图像与物理验收：先单因素，再组合

### 1. 输出要求

每个案例同时输出以下文件，按 band/case 分目录，不只给拼图或视频：

- `raw_radiance`：映射前浮点数据，推荐 NPZ/EXR/PFM 中本机实际支持的格式，附单位、波段积分/平均语义、可逆缩放及 mask。
- `fixed_clean.png`：800×800、无标注、固定映射的单独 PNG；同一波段同一比较组保持曝光/窗口/增益一致。
- `auto_clean.png`：同一帧或同一可重放状态的 AGC/正常显示图，记录实际 gain/offset/gamma/percentiles/饱和比例。
- `annotated.png`：同一状态的正常标注成品，不改坐标；同一次采集若无法同时生成清洁与标注图，使用明确标记的确定性重放，不冒称同帧。
- `received.png`：至少关键案例保存经过真实编码、DDS、接收器解码的 PNG，并与生产帧身份关联。
- `case.json` 和分量 CSV：源码/二进制/资产/配置哈希、种子、frameSeq/sourceSeq、实际波段范围、响应、相机/目标位姿、高度/斜距/速度、太阳方位与高度、环境与表面温度、材料参数、太阳/天空/主动/热辐射、τ、Lpath、显示参数和验证等级。

材质诊断拍摄使主体占据约 200–500 像素宽，避免只剩十几像素或被标签覆盖。另存正常工作视距图及明确标识的 ROI 裁图；禁止改变最终输出分辨率来冒充性能达标。

SWIR 与 MWIR 不必强行共用同一数值灰度窗口，因为能量尺度不同；物理比较用 raw 数值与各自已声明响应。不能让 AGC 把本应不同的物理情况重新拉成相同灰度再声称结果正确。

### 2. 必须覆盖的案例矩阵

所有基础物理案例都覆盖 SWIR 与 MWIR。优先复用参考状态，避免把多因素全组合做成几千张无解释图片。

| 主题 | 至少应有的独立对照 | 验证重点 |
|---|---|---|
| 黑体/材料样片 | 已知温度阶梯、发射率/反射率差异、太阳关闭/开启 | Planck、反射、量纲、GPU 数值与材质分区 |
| 民用车辆/民用飞机 | 同几何两波段；冷态/加热态；侧面与能看清热源的视角 | 不再是同一灰度贴图换名字，不是整物体随发动机瞬间变白 |
| 热喷口/尾焰 | 关闭/开启、冷/热、至少两个观察方向 | 固体与气体分离、局部性、光谱依赖、不重复贡献；无测量数据时标代理模型 |
| 太阳方位 | 固定高度角的前/侧/后方照射 | 法线变换、阴影与反射方向；不要同时改变太阳高度和曝光 |
| 太阳高度 | 固定方位、低/中/高太阳高度 | 太阳入射能量与大气路径；对应数据必须有效 |
| 日照热惯性 | 转入阴影/转回日照的时间序列 | 反射立即响应、温度随时间变化，二者分开 |
| 主动照明 | off/on、带内/带外、照到/未照到、遮挡/无遮挡 | 正确谱重叠、两段路径、空间光斑；0.85 μm 照明不作为 SWIR/MWIR 带内验证 |
| 云 | clear；目标在云前/云后；各 cloudId 单独关闭 | 世界空间遮挡、各云实际像素贡献、发射/散射/衰减不重复 |
| 雨/雪 | 各自独立于 clear；固定种子 | 实际空间/图像效果与路径影响分开报告，不能用白点叠加证明天气辐射正确 |
| 能见度/湿度 | 各自单因素多档、固定几何与太阳 | τ 和 Lpath 的数值及目标—背景对比，不要求各波段所有工况灰度同向 |
| 高度 | 民用/通用模型适用域内至少三档 | 明确目标与传感器各自高度、保持可比斜距；分开大气变化与目标热状态变化 |
| 速度 | 合理的至少三档及升/降速时间序列 | 记录 m/s、Mach 和环境温度；区分相对空气速度与地速；热惯性不是瞬时灰度增益 |
| 标注与 AA | 无标注/有标注，AA Off/EdgeAA，近景/正常视距 | 坐标与文件身份不变，细节损失不掩盖温度/材料问题 |

高度、速度与尾焰采用民用/通用研究条件，说明适用范围；不为了“必须有明显区别”人为放大数据。固定温度条件下先隔离大气，再开启简化热状态模型；需要速度影响时保持其它输入一致。

云、雨、雪可沿用已有工程近似并修复链路一致性，不要求本轮升级完整气象微物理。必须标明哪些是几何显示验证、哪些使用了物理消光/发射/散射数据。若 MODTRAN 已包含某段天气消光，局部云雾模块不能对同一介质再算一次。

### 3. 通过标准

先让受控数值测试通过，再让民用模型得到可解释图像，最后验证正常程序入口。不能以“看起来更像红外”代替数值验收，也不能只跑数值脚本而不修正式画面。

至少证明：SWIR 正确消费太阳/天空/带内主动光；MWIR 正确消费温度和材料且未错误遗漏所声明的反射项；带外光不会凭空产生带内反射信号；合法 τ=0 不变成 1；所有贡献只加一次；热区保持局部；目标、背景、云与路径项单位一致；固定映射下结果与 raw 数值一致。

验证等级分开列：解析/公式基准通过、实现一致性通过、受控现象通过、真实测量对比通过。无可追溯真实温度/材料/响应测量时，最后一项写未验证，不影响继续完善前三项，但不得称“已完成真实器件或真实目标标定”。

## 五、P10 遗留问题与性能回归

本轮物理问题优先，不让 MSAA 或 UI 小项占据主体工作。

1. SWIR 范围、schema、正式入口与大气覆盖一起修复。VIS-SWIR 不扩为第三条主链；在 UI/接口/日志明确未支持并保持拒绝，不再把它当 SWIR 或用回退伪装。NIR 保留基本回归。
2. 对 EdgeAA 的细节变软保存 Off/On 同物理输入对照；诊断原始数据不带 AA。不能用整体模糊或锐化“修复”热分布。2×/4× 若实际附件仍为 samples=0，配置/界面必须说明未生效，不将它写为通过；不要为此整体换驱动。补 Windows 原生 FBO 实测或明确保留未测。
3. 检查法线/UV/材质映射，处理影响本轮民用资产的拓扑问题。已有特定模型的非简单多边形提示列明原因和处理结果；不要声称所有原模型均已标定。
4. P10 正常启动估计输出延时最大约 114.18 ms，15 帧超过 80 ms；STOP 开始执行为 0.158375 ms，另有 52.184 ms 排空。分别保留控制开始响应、排空、末帧到达/文件完成等口径，不把 STOP 响应当全链停止耗时。
5. 优化启动/暂态峰值可预加载 LUT、纹理、shader 与缓存，INIT/预热耗时单列；不得移动原有计时起点、删除启动样本或隐去 >80 ms。若仍未达全帧延时要求，单独标失败。
6. 保持 OrderedQueue 的已接受输入逐项处理与保存身份一致；禁止偷偷改为 Latest、覆盖输入、降分辨率、重复图冒充新图来守 FPS。

8. SWIR、MWIR 在 800×800 各做一轮与 P10 同口径的完整 60 秒正常 UI 测试，保留约 60 FPS 目标和已有阈值。报告请求/输入/生产/接收新图 FPS、所有已接受输入—执行—录像映射、队列、启动样本、p95/p99/max 延时和 >80 ms 数量。全量大体积诊断另行采集，日常运行不得逐帧写大文件。
