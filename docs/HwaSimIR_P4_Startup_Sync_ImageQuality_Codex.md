## 二、P4A：启动速度和本地 X11

### 2.1 关闭每次启动的全量文件校验

当前启动器执行 `sha256sum -c deployment_manifest.sha256`，会读取约 5.72 GB Config；这不应是每次正常启动的前置条件。

直接修改并部署启动器：

- 普通 `./run_precise.sh` 默认不做全 Config SHA-256、不做启动器自校验等重型完整性扫描。
- 完整校验保留在部署时；另提供显式 `--verify-full` 或独立校验命令，参数不得误传给 HwaSim_IR。
- 正常启动只保留快速必要项：程序和必需配置存在、本地 Xorg/权限可用、硬件设备存在、性能策略可应用。
- DDS-only 模式不能因为未使用的旧 UDP 8888 端口被占用而拒绝启动；只在实际启用 UDP/both 时检查相应端口。
- 不关闭帧缓冲完整性、配置字段合法性、LUT 单位和关键资源加载错误检测。这些是正确运行所需，不是耗时的全盘文件检查。
- 给启动过程加简短耗时：启动器准备、性能策略、DDS 就绪、图形上下文、资源加载、首个有效视频帧。分别测冷启动和再次启动。不能未经测量就把所有等待都归咎于 SHA。
- 修改脚本后重新生成部署版本记录；不能因为旧清单包含脚本自身哈希而使新脚本无法运行。

### 2.2 默认连接板卡本地 Xorg，不继承 SSH 图形转发

当前代码：

```sh
export DISPLAY=${DISPLAY:-:0}
export XAUTHORITY=${XAUTHORITY:-/root/.Xauthority}
```

会保留 Xshell/SSH 设置的转发 DISPLAY。

生产目标是板卡本地 Mali 离屏渲染，不是向 Windows 转发 X11。改成显式本地设置，例如：

```sh
export DISPLAY="${HWASIMIR_LOCAL_DISPLAY:-:0}"
export XAUTHORITY="${HWASIMIR_LOCAL_XAUTHORITY:-/root/.Xauthority}"
```

核实实际 Xorg 的认证文件和运行用户；上面路径不能代替实机核实。不要用 `xhost +`、关闭认证或更换驱动规避。

在建立图形连接前打印一次 inheritedDisplay / effectiveLocalDisplay / authorityPath；不打印认证内容。

验证：

- SSH 未开图形转发；
- SSH 环境已有转发 DISPLAY；
- DISPLAY 未设置；
- 板卡本地终端或等价非交互启动环境。

四种情况下，普通启动器都连接正确本地 Xorg。Xorg 未启动时，使用既有最小 Xorg 启动方案或明确报错，不能假装设置 DISPLAY 就创建了图形服务。

## 三、P4A：开始后冻结与 GL 0x506

用户流程必须原样复现：

Windows 直接双击 VideoDisplay、DataDrivenTestQT；板端普通 `./run_precise.sh`；手动复位→初始化→开始。不能只用带特殊环境变量的旧自动脚本代替。

错误是 `GL_INVALID_FRAMEBUFFER_OPERATION`。先定位实际发生错误的绘制/复制/回读调用与绑定的帧缓冲，不能先认定是 DDS、性能策略或浮点纹理。

诊断仅在受控开关下启用 `gl-debug #t` 等日志。在有有效 OpenGL ES 上下文的渲染线程上，按当前 GLES 版本支持的 API 检查：

- raw scene、final sensor、体积云合成、深度贴图、窗口/离屏宿主分别对应哪个 GraphicsOutput/FBO；
- 实際颜色/深度附件、尺寸、格式、采样数、绑定纹理和渲染有效状态；
- `glCheckFramebufferStatus` 的具体返回原因；
- INIT/RESET/分辨率变化后是否仍引用已销毁纹理、旧 DisplayRegion 或旧上下文；
- CPU 读回指针是否只证明“有旧图”，并不证明本帧已成功绘制；
- 是否出现同一纹理同时作为本 pass 输出和输入、空附件、GLES 不支持的组合或重建顺序错误。

禁止在无上下文线程调用 GL API，禁止每帧强制 glFinish 作为正式修复。

做最小生命周期/附件修复。渲染失败时不得把旧 RAM 图像打上新输入序号继续当新视频发布；输出状态应反映失败，并保留现场。

验收：NIR/MWIR；800×800 与 640×512；冷启动、连续至少 10 次 RESET/INIT/START/STOP、分辨率变化；数据和目标确实移动；无 0x506；输出图像、标注、元数据一致。若云分支造成问题，临时关闭仅用于定位，最终需修复并恢复世界空间云。

## 四、P4A：同步模式严格一输入一输出

P3 长测为 36000 个 Realtime、42169 个 H264 Sample，不能用“序号连续、FPS 更高”代替同步验收。先记录该旧测试实际 effectiveSimMode，不能假定它当时是同步。

同步模式必须满足：

```text
每个有效 Realtime -> 一次场景快照 -> 一次成功成像 -> 一帧 H264
                   -> 一份 VideoMeta -> 一份 Annotation（启用时）
```

- 同步没有新输入时不产生新的业务视频帧；GUI 重绘同一幅图不计为新业务帧。
- 不因 `MinRealtimeFps=60` 把 20/30 Hz 的同步输入补成 60/70 Hz。
- 不能在渲染前连续应用多条输入、只对最后一条输出一帧。
- 明确区分输入序号、渲染循环次数和输出帧序号；后者连续不代表输入与图像一一对应。
- 图像、姿态、元数据和标注使用同一个不可变输入快照；复位后使用新的回合/代次，防止旧帧混入。
- 同步去重条件绑定成功绘制/采集/入队的业务帧，而不是单纯 `has_ram_image`。
- 保持旧协议 STOP/RESET 语义；停止边界与已接受输入的排空要明确记录。测试先停止 Realtime、等待已接受数据处理完，再发 STOP，避免跨 Topic 顺序混淆测试。
- 异步允许复用状态和不同输出速率；但配置了固定 videoFps 时按该配置调度，不能因追赶逻辑意外长期超发。无限制模式需单独明确。

同步分别测试 20/30/60 Hz，至少 10 秒，另做 60 Hz 60 秒和输入暂停 2 秒再恢复。对同一有效区间核对：

`输入接受数=消费数=业务视频输出数=接收解码新帧数=显示接收新帧数`。

保持 H264 一个 AU 一个 DDS Sample，不把 SPS/PPS NAL 个数当帧数。无丢失、重复、跳序；异步另表统计状态复用，不能混入同步结果。

## 六、P4B：先修 CPU 到 GPU 的辐射分量遗漏

重点检查 `ApplyInfraredShader` 的 M1 MWIR 正式分支。目前该分支直接从 `u_material_temp_K + solar_delta_K` 计算 4 um 机体辐射，没有将前面得到的尾部热斑和头/中亮斑 mask 纳入；CPU `IRRadianceModelV2` 虽包含这些分量，并不代表像素实际使用。

实现并验证：

- 统一正式 CPU/GPU 的分量和单位；明确机体、太阳反射、天空反射、局部热斑、主动反射、路径辐射分别在哪里计算/应用。
- 局部温度热区用真实 mask 改局部温度或正确的辐射面积混合。例如 `L=(1-m)*epsilon_body*B(Tbody)+m*epsilon_hot*B(Thot)`，不能完整机体辐射再无依据叠加完整热点黑体造成重复。
- 头/中“亮斑”按既有协议定义保留，不能把相对强度字段冒充开尔文。
- 独立尾焰是另外节点，检查其单位、透明合成与大气衰减，不重复叠加到机体。
- 检查 `ApplyAeroToRadiance` 等实际生效项与来源；按原有物理约束接入，不能恢复发动机整体机身加热。
- 材料温度、温升、发射率只在应作用的部位生效；不规定整架飞机必须纯白。

保存机体/热斑/尾焰/主动/路径分量的实际 GPU 输出图，不用 CPU 同一个标量复制到多条日志来冒充逐层测量。

## 七、P4B：统一波段定义和空间材料属性

### 7.1 矩形波段也必须正确积分

当前 MODTRAN 是 3–5 um 归一化波段平均，机体/着色器却使用 4 um 单点 Planck。单位外观相同，但不是同一量。

本阶段不要求真实 SRF，先统一：

```text
Lbar = integral(R(lambda)*L(lambda), lambda) / integral(R(lambda), lambda)
```

矩形 R=1。CPU、GPU、目标、路径、天空、主动照明都遵守同一约定。

可用共享的一维温度→波段黑体辐亮度表，避免每片元做昂贵光谱积分。与独立高精度参考对照 250/300/500/1000 K。

另外量化 `mean(tau)*mean(L)` 与 `mean(tau*L)` 的误差；前者不是自动成立的恒等式。先建立独立光谱参考，在误差超过预先说明的工程容差时修正权重或表结构，不必逐像素跑 MODTRAN。

主动照明检查 `IRActiveIlluminator` 目前按光源/传感器重叠宽度归一化的问题：添加到完整传感器波段平均时分母应是完整传感器响应积分。部分重叠还必须按光源谱保留重叠能量，不能仅做布尔判断。窄带光源的透过率应明确是对应光谱权重或受控宽带近似，不把宽带 tau 平方当任何波长均精确。

### 7.2 F35 模型材料专项

先把 F35 做成真实可用的完整样例，再复用管线到其他目标，不先重做所有模型。

检查：

- OBJ 的顶点法线、面朝向、UV、缩放、切线、纹理绑定；不能由 MTL 没 normal map 就断言 OBJ 没有顶点法线。
- 当前 `f35c_mat.tif.xml` 的 4 类材质与贴图覆盖是否准确，涂层是否把大部分机体错误分为裸铝/铁。
- 材料编号纹理必须作为数据纹理读取，不使用颜色 gamma，不通过线性滤波/mipmap 产生不存在的编号。
- 当前 MTL 只有一个可见材质、Ks=0，NIR 正式分支也未用可见纹理或粗糙度。补贴图文件本身不会自动让自定义 shader 出现效果。

增加明确的空间属性入口：NIR 反射率纹理或材质内反射细节、MWIR 发射率/热区 mask、需要时的粗糙度/法线。

优先用可追溯数据。缺实测 NIR 纹理时，允许保留已有可见纹理中的板缝/涂层空间细节作为**可关闭的工程代理**，叠加到有来源标注的材料基准上；标记 `source=visible_detail_proxy`，不要把 RGB 灰度直接声明为真实 NIR 反射率，更不能同样复制成 MWIR 温度图。

NIR 首先保证几何法线和光照方向正确、材料反射有空间差异；金属/玻璃确有需要时才加低成本粗糙镜面项。不得对所有材质统一加“塑料高光”。

## 八、P4B：统一目标和背景的显示尺度

当前目标从 SI 辐亮度映射，天空/地面直接使用经验灰度；M1 分支先 clamp 0..1，再经过经验天气灰度混合，且离屏颜色目前为 8 bit。这是必须检查和改正的混合链路。

目标方案：

```text
表面光学/热状态
-> 出射辐射
-> 大气透过与路径辐射
-> 目标/背景/云在一致的辐射域合成
-> 公共传感器显示范围或曝光映射
-> 白热/黑热
-> 最终 8 bit
-> 标注/视频编码
```

要求：

- 天空视线辐亮度与照到物体表面的向下天空辐照度严格分开，不能互相代用，也不能再用 TOTAL_RAD 冒充不含目标的路径项。
- 首版允许简单天空/地面背景，但参数必须标明是物理输入还是工程背景假设，并映射到同一辐射尺度；不要和任意灰度直接混加后声称辐射正确。
- 检查 MODTRAN 大气与旧雾/对比度压缩是否重复衰减。云的遮挡/透射保留，不以关闭天气通过。
- **允许并要求建立合理、统一、可解释的显示范围/曝光/自动增益。** 这不属于篡改物理。禁止的是为了某张截图偷偷增加温度/灯功率/单个目标专用增益。
- NIR/MWIR 可以各有传感器显示预设，但同一帧目标与背景必须共享映射。先固定范围做物理回归，再做平滑自动范围。
- 不能指望在已截断/量化的 8 bit 图上开启自动增益，恢复之前丢掉的细节。
- 优先测试并选用 Mali 真正支持的浮点辐射中间缓冲；实际验证颜色渲染、深度、过滤及需要的混合能力。不能只依据 API 存在或桌面通过就认为板卡支持。使用当前 GLES 版本支持的格式和能力检测；首个完整性错误必须停止该候选。
- 若浮点中间纹理确不支持，使用有明确范围/误差的高精度编码替代，并量化损失；不能悄悄回到原始每像素 clamp0..1。
- 只最终显示才压到 8 bit，诊断保存浮点/高位深数据和最终 PNG。标注不参与辐射/自动范围统计。

## 九、实际成像验收：必须看到改进

固定 F35 相机、姿态、距离、时间、环境和材料配置，保存修复前/后。

两种观察尺度：

- 细节检查：通过合法距离/FOV 让目标占至少约 100 像素，可辨机体、机翼、座舱及尾部；不改模型真实尺寸。
- 远距离检查：保持原任务的远距离小目标，接受真实像元采样限制，不声称几像素目标能显示板缝。

NIR：日间迎光/背光、姿态变化、材质编号图、反射率图、法线图、日间主动 off/on、夜间主动 off/on/off。

MWIR：机体温度图、太阳方向温差、发动机 off/on/off、头/中亮斑、尾喷口/独立尾焰；侧视和能看到尾部的视角均测试。

独立数值样例：已知温度/发射率平板、冷热背景、零路径/单位透过、受控大气；应亮应暗由辐射差决定，不以整架飞机变白为判据。

实际 GPU 输出至少保存：物理辐射、显示映射前、最终灰度、DDS 接收后的图。统计目标与背景辐亮度、灰度范围、饱和比例、局部差异，并检查高低灰度不是来自标注。

如果物理值正确但实际可见改善不足，继续定位映射、材质和部件分量，不以“QC PASS/没有饱和/帧率足够”结束成像验收。
