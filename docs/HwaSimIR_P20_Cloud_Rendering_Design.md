# P20 云渲染设计与工程边界

基线是 P19 稳定版 `aarch64_24_domains_clean`，ELF `b7e50a1b4d7d919e1e79b99770a5444e4367457ddd758d84f68c7dc14ab103e3`。P20 当前验证候选为 `aarch64_40_prefix_prewarm`，源码/构建回执见同名 `logs/p20/build/`。21加入有界状态组合缓存维护，23整合控制激励TCP_NODELAY，30把透明局部云光程合入已有云附件。原生粗320、精800；正式 current/previous 仍为 P19/P18。各候选性能分别实测，不能引用23的性能作为当前结果。用户视觉验收PENDING。

## 表示、光学和外观

`[Stage7Weather] CloudAlgorithm=PuffHybrid`（环境变量 `HwaSimIRCloudAlgorithm`）启用新表示；默认 `LegacyVolume` 保留。切换后重启。`CloudPuffCount=24` 为候选默认，12仅作为不同形态的实验，没有声称等价。

从原 P17 四个96³密度资产离线拟合每模板24个紧支撑椭球。原资源不改，派生模板具有质量守恒记录、源哈希和形状误差；哈希仅追溯资产，普通激励没有文件名、行数或哈希白名单。每个世界云实例一次实例化提交，几何范围由球面保守代理覆盖，保持原有世界网格、位置、尺度、生命周期和流式管理。

密度为 `rho=A*(1-r²)²`。每个像素求真实椭球射线入口和出口，用实际不透明场景 RGB24 对数深度截断出口；原函数 `F(s,q)=s*(q²-2q*s²/3+s⁴/5)` 给出任意局部光程。相机在云内使用入口0，目标在云内只保留目标之前的光程。没有使用目标ID、标注框清云或中心深度近似。出口代理面剔除入口面，避免近裁剪面截去入口代理导致缺失云；其余场景继续原P17对数深度。

完整射线区间用解析化简 `(16/15)*q²*sqrt(q)`；只有顶点阶段证明整个椭球位于实际far以内且该像素深度为空，才跳过深度裁切运算。目标像素和跨far射线仍使用完整局部表达式。这些是同一密度模型的化简，不是缩减射线积分步数。

每团的入射光衰减在CPU预计算，随模板、环境和光照更新。云的源函数与旧体素多步积分不数值等价。各团按相机方向排序；不同源函数、多个相交介质的合成仍有排序近似，不能把单团光程的解析精确性推广为全部辐射源项精确。

## 共享光学附件

一次原生 RGBA16F 云绘制同时产生 R=物理SI源项、G=白云外观源项、B=物理云源项、A=覆盖率。纯云阶段R=B；透明内容绘制后R还包括已传输的透明SI，B只包含云SI。物理SI合成 `Lout=Lbase*(1-A)+R`。WhiteCloud显示从合成结果分离B后使用原固定映射，再叠加G；白云外观没有被关闭，背景消光只应用一次。正常输出融合于最终映射；AGC、线性SI诊断等真实消费者启用时才物化独立SI合成附件，保留原背景RGB。

实际Mali附件格式为RGBA16F。800视口由驱动/Panda配置分配1024纹理存储，但绘制视口仍是800×800；不存在低分辨率云上采样。共享云使用bit28；透明几何在云场景内独立子节点共享实例，31使用同一云相机/display region；固定绘制顺序将透明内容放在云之后，并保留尾流、核心、雨雪的原相对顺序；旧volume降水通道bit29在透明后合成启用时关闭。Panda相机掩码必须由 `PandaNode::get_all_camera_mask()` 构成，不能包含保留的overall位。

开发中发现两处重复：降水更新重新打开旧云通道；原取反相机掩码包含保留位，云仍进入原SI和深度附件。16修复第一处，18修复第二处。01—17仅是保留的实验证据，不能作为最终共享消光正确的版本。逐帧缓冲计时用于确认绘制归属，强制同步诊断不作为生产FPS。

层云继续采用世界空间分层表面和各层真实深度合成；不透明目标在每层前方时该层被裁掉。没有把整层当成单个中心深度体积。内部每层有限厚度及透明介质交叠的精度边界需要单列，不能以不透明目标夹具替代。

## 更新与缓存失效

不使用屏幕历史图像缓存。每帧更新真实相机变换、局部射线原点、团排序和可见性；世界云描述变化更新模板、位置和尺度。INIT/尺寸变化重新绑定新深度附件；FOV/near/far变化更新镜头与对数深度参数。预计算只缓存模板密度和团内光照数据，不复用旧画面。连续压力fixture包含运动及每600行的明确坐标跳变，单回合不RESET。

## 透明尾焰与雨雪的局部光程

先绘制不透明场景/实际深度和共享云光学附件，再对每个透明贡献使用 `Cprefix(z)+Tprefix(z)*L`。尾焰保留P18形状、密度、噪声、24/40个原气体积分步及alpha，在每步真实深度计算云前缀并按气体透射权重累积；降水使用真实片元深度。后方云保留在背景贡献中，透明源不会再次乘整云透射率。不使用逆透射率补偿、整云中心深度或标注/ID例外。

单次透明绘制输出R=`CprefixSI+Tprefix*L`、G=`CprefixWhite`、B=`CprefixSI`、A=原透明alpha；RGB采用原alpha混合，附件alpha按`a+(1-a)*Aold`累积。合成后物理SI仍为`baseRGB*(1-A)+R`，云物理源为B，白云源为G。所有云后背景贡献在原alpha的剩余部分中保留；透明贡献只经过其真实深度之前的云，不再乘整云透射率。显示白值不会写入物理SI。候选30直接复用已有云附件，不需要28/29新增的全屏透明附件或最终额外采样；正常显示不物化额外SI附件，也不重复绘制透明几何。

气体的实际射线区间不与任何正密度puff支撑或有界层面相交时，云前缀在整个区间严格恒定，只求值一次。相交时仍按原24/40个气体步逐点求前缀。判断使用实际区间，不用整云alpha相近代替局部误差检查，不改变P18密度、形状、噪声或alpha。

描述符保留每条64个R32F标量、前48个有效。标量布局为64列；35的GLES310布局用32列和两倍行数，将每个vec4按下行(w,z)、上行(x,y)打包，一次textureGather取得原始四值。没有插值、量化或降分辨率；Windows保持标量路径，Linux可用 `HwaSimIRPuffPrefixGather=0` 对照。使用高精度采样、直接RAM标量上传，绕开部署版Panda不支持的RGBA浮点转换。原26仅改POT尺寸仍失败，尺寸不是已证实的根因。参数纹理与图像分辨率无关。

云相机遍历原云节点及透明子节点下的原几何共享实例，逐帧复制原父变换/状态并保留业务隐藏；失效实例有界删除。原始透明贡献在旧SI路径抑制，避免重复。云团选择查询实际bit28共享实例路径：原volume父路径只开放bit29，沿原路径查询会错误漏收puffs。实际GPU路径夹具 `logs/p20/shared_cloud_visibility.json` 验证了该区别及hide/show；`transparent_instance_fixture.json`覆盖旋转和父/节点隐藏；生产日志 `[P20TransparentPrefix]`记录实际描述符和可见云数。

Shader在INIT后的正常图形帧排队准备，不跨线程直接调用GL。所有正常性能统计仍包含首帧与结束排空。多个不同源介质的排序近似仍单列，不因透明修复而声称全部源项数值精确。

候选30的共享附件在Mali40步尾流前/中/后检查通过（`logs/p20/board_transparent30_merged_b/result.json`），云关闭与原P18逐像素及alpha差0；30项原生800不透明几何检查含B物理云源通过（`logs/p20/board_optics30/result.json`）。31仅合并相机遍历，shader未改；GPU五种隐藏/旋转/恢复情况下与30双region逐像素差0（`logs/p20/shared_camera31_fixture.json`）。主程序性能/功能仍以对应构建的实际矩阵为准。

## 同步RGB读回及启动准备（38—40）

在最终映射与标注后，使用原生尺寸RGB8同步glReadPixels，再复用既有NEON分量交换写入Panda底行优先BGR RAM；modify_ram_image推进原纹理图像序号。没有跨帧流水/PBO，不增加一帧延迟，输出身份与原capture链不变。`[RenderBackend] DirectRgbReadback=true`启用，环境`HwaSimIRDirectRgbReadback=0`可同ELF对照。库函数来自既有libGLESv2，不替换Panda/驱动。保存恢复读FBO和pack状态。

审计模式`HwaSimIRDirectRgbReadbackAudit=1`与Panda原RTM_copy_ram双读逐字节比较；该模式有双倍读回开销，不用于正式性能。`HwaSimIRDirectRgbTiming=1`仅诊断，分别glFinish等待、RGB读取、转换和状态恢复；正式运行关闭。实际生产类原生800图案夹具、冷启动/切换/每像素/图像序号均PASS，38主链双读审计一致；最终候选回归以机器验收为准。

40在INIT原有的discard-only预热内准备透明云实例，绘制后恢复目标/尾焰场景，再清理一帧。它位于ACK之前，不接受激励、不发送视频，所有业务帧仍计入性能。`HwaSimIRPuffPrewarm=0`用于同ELF原因对照。预热的实际收益不能以代码检查代替实测。

36的CPU保守视锥筛选未带来收益，已撤回生产引用；34状态compose实验也已撤回。当前保留35的R32F精确gather、38同步读回与40启动准备，不将失败实验设为默认。
