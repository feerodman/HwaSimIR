## A：生产身份与实际文件

修复 `processAnnotation()` 丢弃正文和 PTS、`processVideoMeta()` 不消费 PTS，以及视频使用接收器自增号/空标注的问题。每个 H.264 访问单元加入独立版本 SEI，携带生产会话、实例、通道、INIT 代次、回合、frameSeq、sourceSeq、PTS、不可变实时数据和原始标注。保持一访问单元一 DDS Bytes 样本；旧解码器可以忽略 SEI，CommonData/V1 未改。

解码输出按 PTS 关联不可变产品，晚加入、重连、缺失后不按到达顺序重新猜配对。旧会话/旧代次拒收，身份缓存有界。V1 元数据仍被读取、检查，但不代替完整生产身份。

录像直接封装实际收到的 H.264，不再有损编码。每段有 `output.mp4`、`producer_annotations.jsonl`、`frame_index.jsonl`、兼容的 `annotations.txt` / `target_annotations.txt` 和 `recording_status.json`。MP4 时间线采用实际捕获单调时间，协议 PTS 另存。索引保存正文偏移、长度、哈希、产品身份和各阶段时间戳。满队列回压，不静默丢录像；封装/写入/关闭失败明确报告。

`tools/p7_validate_recording.py` 独立从 MP4 读取每个真实样本，解析 SEI，逐帧核对正文字节、哈希、索引和 PTS，再解码全部帧。输出 `all_frame_correspondence.csv`、`decoded_rgb.framemd5`、`validation.json`。不是比较三个 Topic 数量。

## A：真实监测与两个 Qt UI

独立版本 DDS 诊断消息分别报告板端有效 Realtime 入站 Hz、开始执行 Hz、接受至执行等待；视频 FPS 来自接收端实际新解码图。表格/监测以 5 Hz 刷新，视频、正文、保存帧不因此丢弃。GUI 提交信用有界，不恢复 Latest。

输出延时定义为板端接受输入至接收器收到对应完整访问单元。四个单调时间戳和低频往返估计时基；保留 RTT、年龄、漂移裕量及不确定度。可靠显示 `≈`，无效显示 `—`。不改系统时间、不用仿真 time/PTS 代替；也不包含输入在板端应用接受之前的上游等待。

VideoDisplay 同页放场景、传感器、平台、目标和监测，左右等宽。平台 2 行、目标 7 行；传感器 4 组键值列。旧精/粗跟及旧角分辨率显示移除，保留 trackerSensorPixelAngle，simMode/videoFps 来自 trackingInit，0 显示不限帧。视频等比居中，上限 1024×1024 屏幕物理像素，不改 800×800 保存尺寸和标注坐标。

DataDrivenTestQT 用同一类型化字段表构造全部 27 个控件和初始化快照，不再在发送前覆盖宽高、噪声和标注值。发送步长支持小数，独立于异步 videoFps；实时配置只保留步长，保留真实文件来源和旧 UDP 入口，默认 DDS 标题已纠正。27 项控件→构造→实际 DDS 显示赋值通过，见 `sensor_field_roundtrip.csv` 和 `tools/p7_validate_sensor_fields.py`。

## B：Auto、有效 FPS 和排队

Auto 的低对比阈值原先在恒等映射与统计映射间跳变。改为连续置信度过渡，并按仿真经过时间逐帧平滑映射参数，仍用64×64、5Hz统计，INIT清历史，暂停不靠系统时间推进。普通穿云序列最大整幅均值单帧变化：A5为17.215级、B1为7.894、B3为7.340；同路径冻结映射为7.370。全序列和局部曲线在 `B3_display_compare`，不是只看均值或消除真实场景变化。

有效接口 videoFps=0 不再被升到60，有效30不再被覆盖。B4 Windows不限帧240输入/1294视频、板卡241/600，以及20Hz输入/30FPS输出239帧，实际文件通过。早期脚本传simMode=0时发送器按真实配置回退到异步2；最终脚本只允许协议1/2，另测显式2。0仅表示videoFps不限帧。

RGB/BGR→NV12采用与独立整数参考逐字节一致的NEON，保持BT.601 limited取整。现SDK无MPP缓存同步接口，没有强开不存在的能力。预分配普通内存转换后复制原DMA缓冲。同版B4各1800帧A/B：输出线程CPU3转换约8ms，允许CPU4–7后约1.6ms；捕获至编码完成均值10.733→4.257ms。正式INI只增加输出线程CPU集合，P3 governor/nice/频率策略不变。

不能把P6D累计471秒等待写成通过。A5/B1无目标普通双云600秒分别保存36000/36001帧、全部文件通过；满队列累计等待1275.355→0ms，估计延时P99 133.060→74.924ms。这不证明目标+双云+降水60Hz通过。

## C：云、游戏倍率、雨雪

离线云构建使用原PNG alpha选取非对称、多尺度主团、附属团和孔隙，不挤出源RGB背景灰/人工阴影。保留96³、R密度/G明暗系数、零密度边界、P6D合成/深度修复。撤销了第一版小圆团候选，采用`P7-asymmetric-alpha-puffs-2`四缓存与显式清单；公共世界位置/大小/种子/稳定身份和双云预算不变。

冻结显示同输入旧/新缓存录像在`C3_cloud_before_band1`/`C3_cloud_after_band1`。轮廓更不对称，但近景仍偏软，雪雾中局部云与背景对比低。没有以抬白、全屏模糊或单云掩盖。最终按cloudId逐朵隐藏比较公共缩放线性图及DDS局部像素，不仅看visible=2日志。

GameVFX Legacy倍率为1/1/1，Enhanced为长1.12、半径1.12、发光1.10；烟气不套发光倍率。挂点、方向、双喷口间距、32粒子批次、LOD、模型温度/材料/发动机均保留。普通喷口侧面前后片在`C3_vfx_before_side`/`C3_vfx_after_side`，板卡各视角/遮挡为明确测试入口。

原`rain.rgba`/`snow.rgba`实为SGI RGBA图像，alpha有效，原文件未改，检查/哈希/通道图见`weather_source`。一个预分配192四边形批次，风/仿真时间驱动，6–85m近远层、透视尺寸、边缘淡入淡出；雪有独立片形与缓慢旋转。消费既有最大高度/过渡厚度/速度比例，上限处降为零，过渡在上限下方，零上限和非雨雪隐藏。

修正父节点不在离屏路径和雨线绕序反向被剔除的问题，没有用提高透明度掩盖。C3窄视场雨线仍偏粗，C4只收窄几何并调整长度比例，实际接收图已证明更细。雪公共线性源.60为人工美术值，不是温度。近场降水在局部云之后合成，开启不透明深度测试、不写深度；不声称云内完整体积衰减。

逐朵云的真实像素影响：固定显示下，雨场景分别隐藏第一/第二云后，DDS图中超过3级的变化像素为55,029 / 182,832；雪场景179,357 / 237,922。对应公共缩放浮点图、100×100局部块和最大连通变化区域在`visual_pixel_validation.json`及`visual_pixel_tiles.csv`，不是仅有可见列表计数。

降水开关对照：雨在线性图变化11,356像素，但固定gain=1、offset=0下DDS只有2像素超过3级，低对比验收失败，未降低阈值改判。雪DDS有32,128像素超过3级，通过。雨高度跨越案例在输入120时已位于上限之上，开关两幅浮点图完全一致，零降水边界通过。普通Auto与该固定诊断的显示口径不同，不能混为因果A/B。

补充冻结普通Auto对照`D_rain_default_frozen_on/off`：gain=8、offset=-2.571取自正式普通运行第239帧日志的舍入参数，仅在诊断中冻结。开关雨的DDS差异5,609像素超过3级、最大65级，通过；显示前浮点差异10,742像素。它证明正常Auto的显示范围能保留细雨，不能撤销gain=1的失败，也没有修改正式默认。

## 限制和失败试验

- 4K物理实屏未测；无可靠时基的帧延时未测，不填0。
- 近景云偏软、雪雾低对比；既有NIR目标/尾焰亮度仍沿原链路，不能称目标模型已正确。
- 综合场景日志`visiblePlumeCount=2`确认尾焰批次保持启用，但实际雪雾视频里尾焰轮廓难辨。普通喷口独立对照中的增大增亮成立，不能据此宣称综合场景尾焰画质也通过；未调业务温度或材料来掩盖。
- 云内物体和透明天气依旧代理/不透明深度近似，没有完整体积遮挡或全地形阴影。
- 误枚举`D_final_nvg20_pause_init`无效；C2雪窗口曾继承照明诊断环境，无效。成功重测单独命名，脚本已加入枚举校验和环境恢复。
- C3 NVG600秒完整保存18000帧；切换C4时停止了刚启动的C3 MWIR600秒流程，后者不计长测通过。
- C4两波段30Hz长测全文件均已核验；60Hz的排队和NVG上游缺失没有被掩盖。原图、完整MP4、正文、索引、全量对应CSV、计时CSV均在`logs/p7`各案例内。
