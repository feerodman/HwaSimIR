# P17 闪烁证据审查（进行中）

## 已确认：P16 的 parallax 比较没有有效的预期相机运动

检查本地旧运行 `logs/p5/p16_f22_parallax_texture_before`：
`stim.err.log` 记录 `freezeGeometry=1`；`board.log` 的 sourceSeq
1、2、3、120、240、360、480 均记录 `elapsedSec=0.000`。

调用链：`tools/p5_run_case.ps1` 传 `--freeze-geometry`；
`DataDrivenTestQT/mainwindow.cpp` 的冻结分支不递增 dataNum，协议 data.time
取 `realTimeData[dataNum-1].sourceTimeMs`；
`IR/P5GraphicsTest.inl` 的 parallax 位移由 `sin(data.time*.001)` 驱动。
所以该比较预期的连续相机运动没有发生。P17 使用旧 ELF 重跑同类
AIM120 诊断，也观察到 sourceSeq 1..480 的 elapsedSec=0。

这解释了为什么不能把 360 个解码帧和 26/27 种画面称为有效运动样本。
重复状态仍可合法地对应不同 DDS 输入/输出帧；热状态初始化、压缩和静态
收敛也可能产生少量不同画面。unique hash 不能推算渲染 FPS。
旧 11.18% 相邻 MAD 降幅不能作为运动闪烁修复证据。

## P17 有效运动与重投影结果

`p5_run_case.ps1 -AdvanceInputTime` 仅取消测试启动器的冻结参数；不改普通输入语义。
新的 AIM120 颜色诊断 360 个解码产品均不同；材质 ID 诊断有 359 个不同画面。
这些是有效样本计数，不是实际 FPS。静态颜色案例的相邻重复比例为 89.69%，
仍保留所有产品，不用零差帧稀释运动指标。

重投影读取 H.264 内的 generation/sourceSeq/frameSeq 与 simTimeMs，使用原 OBJ
和已知 P5 相机方程。相机仍挂在普通平台父节点下，look_at 的 up 也随父节点 HPR
变换；漏掉这一点会制造约 1 度的错误相机滚转。修正测量方程后，颜色诊断的
几何 mask IoU 最小为 0.99779。该修正只发生在诊断脚本，不改变普通相机语义。

排除前 60 个启动产品、显露/遮挡、2 像素轮廓后，299 对有效移动帧的模型内部
解码灰度残差 P95=2.743、P99=9.447，绝对残差大于 2 的比例为 7.883%。
轮廓 P95=2.953、P99=5.733，大于 2 的比例为 10.074%。这些值仍包含编码和
双线性重投影误差，不能直接写成渲染异常率。静态内部 P95 约 0.0000284、
P99 约 0.000191。细节图保留，未做全屏模糊或历史混合。

材质 ID 图中合法 ID=0 与背景同黑，当前图像阈值无法独立验证几何 mask；其
重投影报告明确 geometryValidated=false，不用于通过判定。正式辐射 P5 案例
因诊断相机/目标高度与距离不一致而触发域外 fail-closed，黑图作废，不能称为稳定。

资产审查未修改原件。AIM120 的粗略重复三角计数主要包含退化面；剔除退化后
只找到一组很小的反向重合三角，尚无证据把它认定为用户纹理闪烁根因。
F35 存在更多反向/重复面，但没有同状态隔离 A/B，亦不据此自动修资产。

未完成：普通辐射链的纯目标平移、单独旋转、FOV/LOD 配对；同次运行四阶段
连续原始材料/辐射、编码前、解码、Qt 呈现对齐；可靠的原始域运动残差和根因
修复 A/B。因此本轮不能声称已修复用户的普通模型纹理闪烁。Qt paint 长尾单独建项。
