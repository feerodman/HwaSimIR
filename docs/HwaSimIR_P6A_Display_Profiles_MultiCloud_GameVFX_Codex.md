## 任务性质与范围

这是代码实施任务，不是再次输出只读检查报告。在保留真实工程上下文、现有文件名和未提交修改的前提下，修改、构建、验证本阶段范围内的通用代码。

本阶段做：
1. 明确每波段 JSON 实际生效的字段，并保留独立波段配置；
2. 用灰阶、普通材料球/平板和生成的普通喷口，验证显示层与游戏特效；

4. 改善非标定游戏喷流的发光核心、软边和烟气层次；
5. 保持现有启动、同步、离屏缓冲、DDS、MPP 和完整配置部署能力。

本阶段不依据真实军机或导弹照片拟合温度场、喷流辐射分布、工况或传感器特征；不改变已有业务目标的温度、局部热区、发动机/气动计算或控制协议；不把通用特效验证描述成上述能力的验收。游戏效果使用独立美术参数和普通测试几何，不将它们伪装成物理测量数据。

保留现有生产行为作为基线。新显示预设先以显式测试配置启用。不能为了画面好看覆盖源辐射或给特定业务目标单独增亮。

## 二、每波段 JSON 保留独立，不合并成巨型 INI

### 2.1 首先交付字段消费清单

为 default_NVG.json/default_MWIR.json 中的字段列出：
- 完整 JSON 路径；
- 是否被解析；
- 存到哪个成员；
- 是否有实际消费者；
- 是正常使用、仅初始化缺省时使用、仅日志记录，还是未实现；
- 覆盖来源与单位。

特别核对：宽高/FOV、光谱范围、DisplayBits/ADCBitNumber、NETD、焦距、像元尺寸、F数、BlackHot、DisplayGamma、GainControlSystem、MTF文件、IntegrationTime、QuamtumEfficiency、WellCapacity。

不要把“字段存在”“JSON加载成功”写成“算法已使用”。不要因为旧文件里 NoiseEffectEnabled 或 Automatic=true 就自动打开未接通的功能。

### 2.2 修复通用配置读取可靠性

当前 IRConfig.cpp 是在整段文本里搜索同名字符串，不是严格按 JSON 层级解析。本轮采用工程已有、兼容现有编译器的 JSON 解析设施，按明确路径读取白名单；不要引入需要板端联网安装的依赖。

要求：
- 无效 JSON、错误类型、非有限值给出明确错误；
- 只有当前波段必需字段验证通过才标记该 profile 有效；
- 每个波段单独记录加载结果，不能一个文件成功就把整个目录标成全部成功；
- 按确定的资源根目录解析路径，不依赖调用终端当前目录；
- 检查多目录加载不会混用不同发布版本的 profile；
- 正常启动不逐帧读取文件。

注意默认 JSON 的 DisplayBits 实际位于 Systems.DisplaySystem；不要继续让日志声称它在 SensorConfigurationSystem。

### 2.3 配置职责

保留以下分工：
- 初始化/实时接口：现有可变几何、波段选择、工作模式等，语义不变；
- 每波段 JSON：该波段的缺省参数与通用显示预设；
- HwaSimIRRuntime.ini：模块开关、资源位置、日志、运行策略及显式临时覆盖；
- Weather/GameVFX：游戏天气和特效参数，不放入相机配置。

本轮最小迁移方案：继续使用 default_NVG.json 与 default_MWIR.json 的文件名；为项目新字段加入明确的 HwaSimIR 专属版本段，不把 Ondulus 遗留系统字段直接当作当前实现。另存原文件存档后再做精简，不能丢失追溯信息。

独立近红外 profile 不等于实现整套 NVG 像增强器。文件名可保持兼容，日志使用实际 Band=NIR，并注明不支持的旧系统。

按字段类别定义优先级，不用一条规则笼统覆盖所有字段：
- 有效接口几何继续优先；profile宽高只作缺省，不能用640×480覆盖有效800×800；
- 新显示字段由波段profile提供默认，显式运行覆盖优先且打印来源；
- 迁移前后用同一测试输入验证默认结果等价；
- 保留旧INI显示键的过渡兼容；新旧都出现时只选一个有效值，并警告；
- 不盲目迁移单位尚不明确的 IntegrationTime、DarkCurrentDensity 等值；
- 光谱范围修改不能悄悄使固定波段数据与profile冲突。本轮仅验证与既有固定波段一致，不重建辐射模型。

日志输出每波段的有效文件、版本、哈希和字段来源。更新 sensorwave_config_usage.md 中已过时的“输入只来自UDP”描述，改成实际DDS/显式兼容输入，不改协议。

## 三、显示质量用独立测试确认，不通过整目标升温修图

保持现有业务源数据不变。建立普通灰階和材料平板场景，包括：暗部连续梯度、中灰细小差异、大面积均匀背景、小面积高亮片。

记录同一测试帧的：
1. 显示处理前的浮点或线性场景值；
2. 显示处理后的编码前RGB8；
3. DDS接收解码后的RGB8。

每张图明确单位和阶段。当前RGB16F保存公共缩放后的线性场景值时，应这样标注，不能称为原始物理辐亮度；解码PNG更不能标成浮点测量图。

核对：
- 线性合成先于gamma，gamma/极性只执行一次；
- 没有意外的重复显示范围缩放、过早截断、RGB/YUV范围不匹配；
- 固定映射单调：较大的输入值不能反而变得更暗；
- 0/1/中间灰阶经编码解码允许量化误差，但不能整段范围错误；
- 数据在显示前已经相等的区域不能靠后处理凭空恢复细节；
- 全局单调映射不能把输入低于背景的表面变成高于背景，报告不要作此承诺。

为独立普通场景提供“固定显示范围”和“通用自动显示”对照。若验证现有自动显示，统计源必须注明处理阶段，避免使用已经套过上一帧增益的输出而形成反馈。不要增加按业务目标框单独增强的逻辑。

本轮重点是配置正确接线、显示处理可解释，不进行真实目标温度场或材料辐射标定。

## 四、多个体积云：先两个，再四个，真实同屏验证

复用现有确定性世界云和普通测试相机，不增加针对业务目标的遮挡/检测能力。

测试矩阵：
- 1个局部云：保留基线；
- 2个局部云：要求同时在画面中形成两个可识别轮廓；
- 4个局部云：质量/性能压力测试；
- 两云视线重叠、相机横移、进入/离开视野；
- 片状云与局部云共存；
- 一个普通遮挡板位于云前/后；
- 大云与小云分别测，不将小云长测结论当大云通过。

“MaxVisibleVolumes=4”或“selected_for_render=4”不是画质证据。必须交付实际接收图，用逐云临时开/关对照证明至少两个云各自影响了画面。最终效果图关闭诊断颜色和标签。

修复重点：
- 多云透明排序及相交限制；
- 摄像机平移时的世界位置稳定、距离淡入淡出；
- 当前远场细碎黑点遮罩：分开检查纹理通道、重复尺度、缩小采样和阈值是否破坏大块云形；
- 普通天空/地面背景的过硬分界，采用可说明的游戏环境过渡，不能用全屏模糊掩盖；
- 同样的公共显示设置下，云不能因切分为多张透明片而无理由改变平均亮度；
- 不恢复P4/P5已失败的自动深度纹理附件方案；继续明确现有代理表面深度的局限。

美术调整允许作用于独立游戏天气参数，但要与原公共显示预设分开保存。不得单独用自动增益把每朵云强制变白，不把近红外和中波的明暗关系假设成相同。

性能测量以同一ELF、同一相机、同一配置、同一时段方法进行。记录云数、投影面积估计、采样质量、绘制调用耗时和接收帧数。不能把P5“一个云约增加1ms”线性外推为四个云必然达标。优先控制屏幕覆盖与透明重叠；禁止仅增加数量上限而不实测。

若四云无法满足原分辨率与60Hz，明确标注压力测试未通过，交付经过验证的两云质量档，不减少有效输入或复制视频凑帧。

## 五、非标定游戏喷流：改善亮核与软外层

仅在生成的普通喷口场景上制作，不依据真实军事目标照片拟合轮廓、温度或工况，不修改既有业务模型的热源。

当前软精灵已消除交叉片，但不等于美术表现完成。制作独立游戏预设，给发光核心和外层稀疏烟气独立控制；用有层次的收束轮廓与软边表达喷射感，不把整条尾迹变成均匀白线，也不让烟气总是压成一团黑斑。

只使用无物理标定含义的美术参数；长度、衰减和亮度变化均标注来源为游戏预设。不要把“靠近喷口更亮、锥状”写成所有真实发动机的统一物理规律。

沿用共享图集、预分配批次和现有LOD。验证：
- 端面、侧面、斜角；
- 近/中/远；
- 只有发光、只有烟气、二者共存；
- 普通几何遮挡；
- 相机环绕时没有十字、矩形片、突然消失或整条特效跟随相机转动；
- 关闭特效恢复基线，未改动相机全局曝光来补偿特效质量。

交付同一显示预设下的改前/改后图与短视频。用户确认画面之前，只写“已实现/已交付待确认”，不要将艺术质量直接标成达到Ondulus。
