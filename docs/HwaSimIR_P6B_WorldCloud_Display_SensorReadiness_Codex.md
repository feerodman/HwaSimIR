## 二、把新云外观接入正常世界网格

保留 `IRWorldCloudStreaming` 作为正常候选生成来源。把 P6 的素材构建、云外观和片云预设提取成小型可复用代码/配置，不复制一套新世界生成器。

正常运行必须满足：

- 不设置 `P6Scene`、`P6ExistingTargets` 等诊断变量，不注入测试相机。
- 沿用接口实际相机位置和视场；不能通过固定 35° 或摆放两朵固定云冒充正常显示。
- 加载中心移动只决定哪些网格需要加载，不带动已生成云的位置。
- 云外观模板由稳定云身份确定；不能使用当前对象池槽号、可见列表序号或目录枚举顺序选择模板。
- 材质模板使用显式有序资源清单，记录资源内容哈希和构建版本。关掉一朵云或释放一个槽位，不改变另一朵云的模板。
- 保留加载/卸载滞回和对象池复用，避免边界反复创建；正常截图应能看到沿路径进入和离开视野的多个不同云形。
- 双云是同屏绘制预算，不表示全世界只有两朵云，也不意味着相机无论朝向哪里都必须强行补两朵云。
- 保留远场片云与局部体积云，迁移时保持各自尺度、遮罩通道和线性合成语义。

配置放 `Config/Weather` 的正式预设中，INI 只选择预设和必要预算。区分云覆盖范围、纹理重复周期、单云半径、密度分辨率、采样数量，不再混成一个尺寸。

先保留旧预设用于对照；新预设在正常相机、双云压力及长测通过后才成为明确的游戏天气默认。不能顺手改业务材料或所有波段显示默认。

## 三、建立独立于进程的云世界身份

按普通三维场景的共享天气需求，明确分为：

1. **世界描述**：哪朵云存在、世界位置、尺寸、模板、密度和方向。
2. **客户端呈现**：该相机是否能看到、画多精细、是否处于资源淡入。

两个相机允许可见集合、采样精度和最终像素不同，但相同世界云的描述不能不同。

必须核对并固定以下输入：

- 云世界/配置版本；
- 明确的公共地理原点或等价的稳定世界坐标约定，含坐标和高度基准；
- 网格大小；
- 随机种子；
- 天气预设及其影响云几何的参数；
- 模板资源清单、顺序、哈希；
- 若存在风移/形变，使用的共同仿真时间基准。

优先采用项目现有地理转换功能；公共天气原点与每个渲染实例自身的局部原点分离。不要为此重做整套全球地理系统。

不得把进程启动时间、进程 ID、线程调度、`rand()` 的调用顺序、第一次看到云的时间，加入物理世界云描述。不同通道名和传感器 ID 不应改变天气种子。

静态云不需要靠系统时间生成；有动画时，从相同的仿真时刻确定状态，不按“本进程运行了几秒”决定风偏移。协议时间格式、跨日和重置含义不清楚时，明确报告，不猜测、不修改系统时钟或协议。先保证静态世界描述一致，再实现有充分时间定义的动画一致性。

保留三种不同结论：相同世界描述、相同相机稳定呈现、最终压缩图像。不能要求 Windows 和 Mali 压缩视频逐字节相同，也不能拿截图近似相同代替描述一致。

## 四、双实例与跨平台验收

先对普通天气场景做自动描述级测试，记录公共区域内按 cloudId 排序的清单：网格编号、公共坐标、尺寸、模板标识及哈希、密度、旋转、时间状态。

至少覆盖：

- 同一配置两次独立启动。
- 两个实例相同世界原点、相同仿真输入。
- 两个实例不同局部渲染原点、不同相机/视场，但观察到同一片公共天气区域。

- 跨多个正/负网格边界，卸载后返回原区域。
- 对象池加载顺序变化、相机方向变化和云暂时被剔除。
- 相同种子应重现；仅修改种子时应确实改变；换 NIR/MWIR 不改变云几何。
- Windows 与 aarch64 对相同云描述的对照。

整数身份、模板键和资源哈希应一致；浮点位置采用预先写明的精度与容差。预处理使用浮点函数时不能声称必然跨平台逐字节相等；需要时仅对有合法部署权限的派生素材做一次预构建、两端使用相同内容。

双进程正确性先在 Windows 或 Windows+板卡分开验证；单块 RK3588 同时两路60 FPS是额外压力项，不由单路通过自动推导。DDS身份保持隔离，天气世界不应因此隔离成两套。

## 六、自动显示的低开销修复

仅修复公共相机显示，不改对象温度、材质或相对辐射关系。

移除正常 Auto 统计对整幅浮点纹理的高频同步CPU读取依赖。保留完整 PFM 导出，但只作为明确请求的诊断动作，不在普通每帧路径执行。

优先复用现有兼容的颜色渲染路径，先在GPU形成较小统计输入或归约结果，再低频读取。候选样本尺寸可为64×64、128×128，最终以误差和板端耗时决定，不声称缩小后一定没有等待。

重要：

- 若算法依赖百分位，普通均值缩小图会改变分布；选择有定义的抽样或直方图近似，测试与完整离线结果的误差。
- 自动曝光统计排除UI，不按业务目标ID、目标框或识别结果进行增亮。
- 没有新统计时复用上次映射，初始化/重置恢复有定义的状态；不要每次缺数据都突然重置黑白范围。
- 单次gamma、白热/黑热、显示前线性值与8bit输出关系不变。
- 不使用低精度读回后的灰度反推已丢失的光谱或绝对辐亮度。

验收用连续灰阶、暗灰阶、小高亮片、普通球体和背景变化；固定模式单调性不变，Auto 的变化应来自已记录的全图统计。

先在独立测试入口确认，再回归通用正式显示路径。只有板端60 Hz及双云组合通过，Auto 才标记为“可实时使用”；默认预设是否改变单独报告，不暗中替换用户选择。

## 八、普通传感器响应的独立离线验证

本轮允许实际实现一个独立命令行测试原型，不只是写资料清单；不链接业务目标、热点、武器状态或跟踪模块，也不向现有目标链路写入校准参数。

仅使用人为定义且有单位的均匀光场、合成光谱/窄带测试输入，配合可合法使用的普通相机示例资源。

分层完成：

1. 曲线加载、单位与有效范围检查，区分相对谱响应和绝对量子效率。
2. 对人工输入做谱加权参考计算；响应包含哪些光学/QE因素必须可追溯，不重复乘算。
3. 对独立的像面光输入做曝光、电荷与数字量的参考测试；有实际数据就使用，缺失则用明确标注的人工参数，不能借其他器件数据冒充目标器件。
4. 校验曝光变化、无光输入、饱和、固定随机种子下的可复现性及噪声统计；各层输出值和单位分别保留。

光子型、热型和像增强器模型不能因为都在一个profile中出现而混成一套。当前中间PFM已是公共缩放线性值，不能把它直接命名为原始光谱输入。已合成成一个波段平均数的输入不能从末端恢复完整光谱，必须有明确的人工分谱或原始谱来源。

交付原型与可运行测试。结论按“人工参数模型已验证”“某条资源已可用”“缺少实测校准”分别写，不把公式或单位测试通过说成真实相机高保真完成。业务目标链路的高保真接入不在本轮范围内。

- 不带P6测试环境变量的普通启动能调用新世界云预设。
- 新云外观来自正常网格列表，不是两朵固定坐标云。
