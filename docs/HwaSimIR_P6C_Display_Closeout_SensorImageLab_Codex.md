# Codex P6C：通用显示定稿与二维传感器参考实验

## 任务目标

在当前工作区实际实施、构建和测试，不再重复 P6B 已完成的世界云重构和全目录资料盘点。

本文件核查基线：`7a55fb545785a01951ad0c0af53ea263d5374206`（2026-09-13 的 main）。若本机有更新，以实际代码为准，记录差异，保留用户全部未提交内容。

本轮有两个独立交付：

1. **通用显示定稿**：用中性平板、灰阶、球形明暗图和人工高亮片，分清输入本身的明暗关系、显示范围压缩、裁剪、编码误差；给出真实生效的波段显示预设与完整验收结果。
2. **二维传感器参考实验**：将已有单像元人工光谱 CLI 扩展为可生成整幅图像和短序列的独立相机实验，实际实现光谱响应、曝光、电荷、噪声及数字化验证，不再只做一轮相同的资源清单。

它们不得混为一项：显示更容易看清不等于温度/材料模型正确；人工传感器程序通过不等于真实相机已标定。

本轮不改变业务目标温度、发射率、气动/发动机模型、热区、尾焰、跟踪或通信协议；不使用真实军机/导弹照片反求温度或传感器参数。独立传感器程序不接入业务目标成像链。工作区的真实名称与上下文保留，不用改名掩盖范围。

## 2. 通用显示：先判定问题所在，而不是直接调亮

使用没有业务目标模块的普通测试场景：

- 连续灰阶与暗部阶梯；
- 预设线性输入的相邻平板；
- 固定值背景，叠加已知明暗图案；
- 少量高亮片与大面积亮区域分别进入、离开画面；
- 无噪声静态图作为数值基准。

为同一输入序号保存：

1. 原测试片的定义值；
2. 公共缩放前后能取得的中间值及其真实单位；
3. 最终映射前的浮点值；
4. 映射后的编码前 RGB8；
5. 实际 DDS 解码 RGB8；
6. 实际生效的 profile 路径、预设名、每项覆盖来源。

只比较确实同一输入、同一相机、同一时间状态的数据。不能用连续两次启动、不同动画相位的截图冒充逐像素 A/B。

把问题分成四类并给出证据：

- 输入已有区别，但被显示范围压缩；
- 输入本来没有空间区别，后处理无法生成缺失细节；
- 重复缩放、提前裁剪或重复极性/gamma；
- 编码、颜色范围或解码差异。

固定映射下，输入较低的测试片不能被悄悄映射成比输入较高的片更亮。动态 Auto 的跨帧比较必须同时记录当前映射参数，另做冻结映射对照。

本轮不要根据已有业务资产图像反求温度，也不要为业务目标 ID、框或类别建立特殊曝光。仅使用通用测试图区作为测试统计范围，不把它做成目标增强功能。

## 3. 通用显示预设真正收口

继续保留每波段 JSON，不把数据重新堆回 INI。

优先整理现有 Legacy / Game / Auto，不为每个问题增加一套互相覆盖的开关。需要增加字段时，必须给出单位、范围、消费位置和迁移规则。

核查 Auto 的统计域：

- 当前直方图的输入是否先被限定到固定范围；
- 大于该范围的高亮样本是否都进入同一桶；
- 统计所得上下界和最终 shader 实际使用的上下界是否在同一个线性域；
- 空场、单色场、极低反差场时如何防止除零、极大增益和闪烁；
- 重新初始化后是否清除了上一回合的统计状态。

发现问题时先用人工测试片复现，再最小修改。不要把64×64抽样说成对所有图像都等价于完整图像百分位。需要改抽样方案时，必须继续测小高亮片、重复条纹和偏离采样格的图案；解释任何近似。

比较三预设的：暗部可区分程度、已知高亮细节、映射单调性、时域稳定性及耗时。允许合理的整画面公共显示变换，不允许整体升温或逐目标补亮。

交付一个“推荐普通使用预设”和一个“固定诊断预设”，二者职责不同。

- 推荐预设通过通用数值、无明显无依据大面积裁剪、正常视频链性能后，才将对应波段 `DefaultPreset` 改为实际验收过的现有预设。
- 明确记录原值、新值及理由，保留 Legacy 随时恢复。
- 无法满足这些条件时，不更改默认，明确是哪项失败；不能为了声称本轮完成而强制选 Auto。
- 无论是否改变默认，都不得把该结果称为业务目标的温度或热特征已修复。

新默认一旦选择，必须用无测试环境变量、无临时显示覆写的普通启动验证；不能只让测试器打开它。

## 4. 不再用“代码高保真”替代“器件高保真”

在独立实验文档中分清四级状态：

- `synthetic_reference`：人工参数、可解析验证；
- `documented_example`：软件或厂商示例，单位已核清但不是指定器件的完整测量；
- `device_characterized`：一套有器件归属、工况与测量来源的数据；
- `device_validated`：程序输出与独立实测数据在声明范围内对照通过。

本轮主要交付第一类的二维扩展。若真有后两类数据，单独登记，不让某一个有来源的参数给整份配置“认证”。

不同波段不能混用器件：像增强器阴极 QE 不直接作 CMOS 或中波探测器 QE；光子型模型和热型探测器模型不能仅更换波长就视为同一模型。

## 5. 在已有单像元代码上实现二维普通传感器实验

沿用 `experiments/ordinary_sensor_lab`，不要从零重写已经验证的单位、曲线和光电子核心。

输入只来自人工谱、普通光源/测试图，不能从 HwaSimIR 的公共显示 PFM 或最终8位图反推光谱。

建议新增：

- 可表达二维人工光场的场景描述；
- NIR 和 MWIR 的人工数学测试配置，名称明确含 `synthetic`；
- 整图/短序列 CLI；
- 分层输出与可重复测试；
- 普通器件数据的校验接口和一个缺项模板。

人工 NIR/MWIR 只是检查单位、积分和波段覆盖，不代表真实器件曲线。原有400–700 nm基准必须继续通过。

为控制内存，可以用“若干人工光谱基底 × 对应的二维强度图”，或按图块流式计算；不能为了实现方便，偷偷把所有光谱替换成一个中心波长。

至少支持人工场景：均匀场、阶梯、亮暗边界、相同总能量但不同谱分布的两个区域、曝光过程中可控变化的图案。它们均为相机实验图表，不加载业务模型或状态。

## 6. 输入含义与单位不可含糊

每份配置明确：

- 输入参考面；
- 谱变量及单位；
- 输入是谱辐照度还是谱辐亮度；
- 响应是绝对 QE、绝对系统效率还是相对响应；
- 是否已经包含光学透过率、QE、波长对应的光子能量因素；
- 输出是期望电子数、带噪电子数、数字码值还是仅供查看的8位预览。

当前已支持谱辐照度的路径优先复用。没有实现成像光学时拒绝谱辐亮度输入，不通过乘一个任意系数把两者互换。

保留拒绝重复 QE/透过率、未知单位、外推、非有限数和非法波长顺序的检查。

规则：

- 已在像面给出的辐照度不再重复乘前段镜头透过率。
- 相对 SRF 只能提供相对响应，不能无依据生成绝对电子数。
- 响应已经包含某因素时不再重复乘算。
- 曝光微秒与秒必须显式转换。
- 数字转换增益明确写电子/码值或码值/电子，不能只叫 Gain。
- 暗电流密度与单像元暗电子率不得直接互换。

## 7. 二维模型按层实现与验证

先实现无噪声二维期望信号，与旧单像元参考逐点一致；然后逐层加入已有随机模型。避免一次加完后只能看一张噪声图。

本轮按数据与时间允许，完成下列明确层次：

1. 光谱加权和曝光后的二维期望电荷；
2. 光电子和暗电子的随机起伏；
3. 饱和容量、读出噪声与数字化；
4. 人工指定的像元响应差异和暗信号差异；
5. 有明确含义的空间模糊测试接口。

固定像元差异在一个实验回合中保持不变，逐帧噪声每帧变化。随机种子与生成器版本写入结果，图块处理顺序不能悄悄改变固定空间图案；无法保证跨版本逐字节复现时如实标注。

空间模糊先用明确的人工点扩散函数测试，保持直流增益/总量定义一致，光学模糊与读出后图像模糊不能混称。只有已实现输入完整 MTF 所需的约定，才接受 MTF 文件；否则拒绝并给出原因，不把随意高斯模糊称为已导入实测 MTF。

读出噪声、暗电流温度模型缺少测量数据时使用明确人工参数。不要拟合真实军事目标图像获取它们。

本轮无需实时运行这个独立二维参考模型，更不要求在RK3588业务视频中每帧执行。先正确实现和验证，再另行判断通用相机实验的加速需求。

## 8. 实际输出，不止新增测试数量

独立 CLI 至少输出：

- 输入光谱/场景身份、单位、哈希；
- 期望光电子图；
- 暗信号与带噪电荷图；
- 未做显示增强的原始数字码值图；
- 明确标记为预览的8位图；
- 一段具有固定像元差异和逐帧噪声的人工短序列；
- 分层启停的对照图和可复算统计。

浮点图使用合适的数据容器；ADC不超过16位时可用16位容器存实际码值，同时写明有效位数。不要把14位码值为好看拉满16位后仍称为原始数据。

至少交付一组800×800人工成像结果；Monte Carlo统计可用较小图和更多帧，写明样本数，不把单帧图当噪声统计验证。

保留原28项测试，并新增能证明二维实现的测试：

- 同一人工像元与原参考相同；
- 无噪声曝光线性；
- 单位变换等价；
- 等波段总能量、不同谱分布，在非平坦响应下给出不同结果；
- 零输入、零曝光、负值拒绝；
- 固定空间图案不逐帧跳变；
- 随机噪声均值、方差与人工定义在统计置信范围内一致；
- 像素/图块边界没有拼接伪影；
- 饱和容量和数字化各自裁剪位置正确；
- 原始码值与预览分离；
- 非标定相对曲线不能进入绝对电子数路径。

不得只用被测代码计算自己的“黄金值”；沿用解析基准，并增加独立高精度积分或独立公式对照。
