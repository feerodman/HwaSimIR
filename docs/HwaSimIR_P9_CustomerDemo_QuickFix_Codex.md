## 2. 视频显示：默认不放大，1024 只是上限

用户要求：源图多少像素，空间足够时就占多少屏幕实际像素；仅当源图超过 1024 上限或窗口空间不足时等比缩小。

示例（可用区域足够）：
- 640×480 → 640×480
- 800×800 → 800×800，不自动放大到 1024
- 1024×1024 → 1024×1024
- 1280×1024 → 最大 1024×819 左右，保持比例

以解码 QImage 的真实宽高为第一依据；没有新图时才用已确认的视频状态几何，不能使用固定的默认宽高覆盖实际图。

设源像素为 Ws、Hs，视频可用区域的屏幕物理像素为 Wp、Hp：

`s = min(1, 1024/Ws, 1024/Hs, Wp/Ws, Hp/Hs)`

显示尺寸为源尺寸乘 s，按安全方向取整并居中。沿用左右 50%/50% 布局，不占用数据区。

高 DPI 要求：
- 控件逻辑坐标与屏幕物理像素只转换一次，依据当前窗口的 devicePixelRatio。
- 800 像素源图在 DPR=2 时可对应约 400 逻辑像素，但图像仍应有 800 像素的采样数据。
- 不先把图片降到控件逻辑尺寸，再让 Qt 放大回物理尺寸。
- 检查 centerVideoLabel、每帧更新及跨屏/窗口缩放路径，避免后一个 setPixmap 再覆盖正确尺寸。
- 不改编码、录像源尺寸或 JSON 标注坐标。已有标注显示与视频使用同一变换。

用接收端生成的静态测试图快速测 640×480、800×800、1024×1024 和超上限尺寸；无需为这些尺寸分别跑板端长测。最终实机仍为 800×800。

## 3. “指令处理”改为 Control 命令的响应耗时与等效频率

### 3.1 明确测量对象

只测合法并路由到本实例的 `ControlP2cX1ObjTrackingCmd`：
- 复位
- 开始
- 停止

不把 Realtime 的每秒消费数量放进这块显示。
`InitP2cObjectTrackingCmd` 是另一种消息，本轮不混入 Control 统计。

计时边界：
- tReceive：完整 Control 样本首次进入应用接收回调的时刻，位于实际路由/排队之前；最后仅对验证及路由接受的命令形成有效结果。
- tExecute：实际主业务控制处理函数/对应分支开始执行的第一处，位于可能很慢的复位清理、停止排空等工作之前。
- 使用 HwaSim_IR 同一进程、同一单调时钟的高分辨率时间。接收线程的时间戳随队列项传递，不能在执行入口重新生成“接收时间”。

`responseMs = (tExecute - tReceive) / 1e6`

`equivalentHz = 1e9 / (tExecuteNs - tReceiveNs)`

这是“接收至开始执行响应耗时的倒数”，不是实际发送频率，也不是证明程序能完成这么多条命令/秒。

按这一显示口径，10 ms 对应 100 Hz；5 ms 对应 200 Hz。验收阈值用未舍入的耗时 `responseMs <= 10`。超过就如实显示，不强行修成合格。

若时间差小于可靠分辨率，显示“低于计时分辨率”，等效频率为 `—`；禁止用除零保护常量捏造超大频率。丢弃、非法、非本实例或重复去重命令单独记录，不冒充已执行。

### 3.2 显示行为

运行监测原第三项改为两行，例如：

`控制指令响应（等效） 250.0 Hz`
`接收→开始执行 4.00 ms｜最近：开始`

布局空间不足可将“等效”解释放 tooltip，但毫秒耗时与最近命令应可见。

- 没收到任何 Control：显示 `— / 尚无控制指令`。
- 接受新 Control 后可显示“待执行”；开始执行后更新该命令的结果。
- 保持最近一次结果，直到下一条被接受的 Control 开始执行。
- Realtime 20/30/60 Hz、视频刷新、普通每秒统计清零不能覆盖此值。
- INIT 不把此结果误更新为初始化耗时；RESET 自身的最终响应结果不能被 RESET 清理代码马上清空。
- 新生产进程/新会话应避免沿用旧进程结果；断线可标记旧结果，不冒充新结果。

复用现有独立 DDS 诊断通路增加带命令身份和版本的最后结果，不能改 CommonData 或 V1 业务结构。若现诊断是可扩展 JSON，添加可选字段并兼容旧端；若是固定格式，按实际契约版本化，不能无版本改变二进制布局。

STOP 后即使没有视频也要能传出并保留该结果；不能等下一帧视频携带。无需新建第二套通信系统。

原 Realtime 接收Hz、视频FPS和输出延时统计保留。Realtime 执行Hz/队列等待仍可留日志，第三块不再显示它们。

### 3.3 快速验证

人工单测 5/10/20 ms 分别换算 200/100/50 Hz；这些只是计算测试，不能当实机测量。
实际复位、初始化、开始、停止一轮，保留每个 Control 的 tReceive、tExecute、responseMs、equivalentHz、身份与截图。确认大量 Realtime 与 INIT 到来不会改变最后一次 Control 结果。
本轮不要求以100Hz发送Control，也不要高频循环复位制造压力。

## 4. 近红外统一称 NIR，兼容文件名暂不迁移

正常界面、波段下拉、运行摘要统一显示 `近红外（NIR）`。NIR 是波段名称；NVG 是旧夜视配置/文件命名，不把二者当同义词。

当前 `default_NVG.json` 已有 `HwaSimIR.Band=NIR`，范围约 0.70–1.10 μm。IRConfig 按 NearInfrared 与该 Band/范围验证，未由显示修改实现完整像增强器。

为了本轮快且稳：
- 暂时保留 `default_NVG.json` 的兼容路径和历史归档，不进行全仓库改名。
- 日志可写 `band=NIR profile=default_NVG.json (legacy filename)`。
- 不盲目把旧 SensorType 的 NVG 字符串全局替换，不改历史报告和资源哈希。
- 保留该波段已验证 Auto 默认和现有算法；不借改名称切换传感器模型。
- 从实际 `IRBandFromProtocol`/UI映射核实近红外枚举，不能只依赖旧注释。当前预期值为1，但必须由代码确认。
