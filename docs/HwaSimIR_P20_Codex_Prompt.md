## 1. 已有证据：不要重复走已经否决的路

下列来自 P19 报告，需用一组当前基线确认，不要求全部重复试验：

- 重云片段常常仅一朵云覆盖整个精跟视口；已有共享纹理、世界网格、流式调度、视锥筛选及预建资源，纹理每帧加载数为0。
- 当前同源云纹理被重建为96³密度场。SI物理云与白色外观分支分别积分，重载实例中前者约8步、后者24步。两分支含义和采样规则不同，不可直接把24改8便宣称等价。
- `cloud24_final_tail`：每路600帧，精跟39.22 FPS、最大输入积压216帧、STOP5385.206 ms、输入到解码图像P95约5179 ms。约10秒输入耗约15.3秒处理。末帧结束NAL很快并不能消除前面的5秒积压。
- 仅精跟约40.29 FPS；主线程固定大核约39.72 FPS。温度/频率样本未发现活动期间降频。因此不能先认定粗路竞争或CPU降频是主因。
- 同条件插桩估计：读回前GPU等待约10.7～11.3 ms，GPU已完成之后RGB读回约3.4 ms；插桩改变调度，仅用于定位。不能把所有等待都归咎于CPU内存复制。
- RGBA缓冲、RGBA读取、同帧PBO、提前flush等候选更慢或无改善，已撤回。
- 云长宽减半/减至四分之一分别有小目标附近最大约96/95灰度误差；所谓全分辨率ROI补算候选整帧MAE约21.91，也失败。

**本轮不默认启用低分辨率云附件再上采样；不把关闭白云外观、提高near裁剪、增加队列容量或减少保留帧作为优化。** 已失败方向只有出现新的明确根因或不同实现依据时才允许做受控对照，且必须标明区别。

可确认的是标准Vega 3D云有透明纹理puffs、朝向处理、光照/穿透因子、排序、入云过渡和资源管理。不能写成所有Presagis云都不积分，更不能声称已跑过Presagis实机性能基准。

### 3.2 云团表示、光照与开销控制

- 沿用已有四张合法源纹理和世界云描述；允许从现有密度/轮廓派生puffs、光照表、光学厚度表或分层缓存。保留种子、世界锚定、云层位置/厚度/覆盖的业务含义，不通过换远处稀薄场景减负。
- 不允许机械周期重复排列、明显同形贴片、纸片侧面、矩形边界。面片朝向必须连续，深度排序稳定；跨云交叠不能仅按云中心粗排就假定正确。
- 复用纹理/atlas、持久缓冲和对象池；先确认已有能力，避免每帧重建/加载。批处理须兼顾透明排序，不以破坏顺序换少量draw call。
- 控制每像素透明层数和片元面积。透明面片不是零成本，不能把8+24次积分改成几十层满屏alpha overdraw后便声称更快。
- 可预计算稳定的光照、透射或云内方向性参数；每帧只做必要插值/近似。不要求用精确体积积分实现每个puff，但必须记录工程近似及限制。
- 灰度外观不能简单套可见光纯白值代替正式SWIR/MWIR源项。保留当前波段区分、云温/照明输入及固定显示映射；真实标定仍为NOT_VERIFIED_CALIBRATION。

### 3.3 首先检查重复计算，但不要混淆物理与显示

已核对入口 `HwaSim_IR/HwaSim_IR/IR/IRCloudPresentation.inl`：

- `UpdateCloudPresentation()` 复用世界云几何并明确给外观路径 `u_ray_steps=24`。
- 此分支声明只影响映射后的外观，不改SI原附件。

继续跟踪HwaSimIR.cpp中体积shader、云SI更新和最终合成的实际调用。优先减少重复的几何判断、射线区间、密度/光照采样，或用一次光学评价产生可分别供SI/外观使用的结果。

可以合并重复工作，不能：
- 直接关闭白云外观并把变暗的物理云当作已认可效果；
- 把显示灰度写回SI辐亮度，污染raw物理输出；

- 把24步和8步不同规则的积分未经验证称为同一个结果。

说明清楚新路径的颜色域、单位、alpha是否预乘、覆盖率与透射率的区别、物理/外观两分支的衔接。改表示允许数值近似，不得声称与旧物理模型逐位相同。

### 3.4 小目标遮挡是硬约束，不是后期补丁

最终精跟始终原生800×800，粗跟原生320×320。必须每帧使用当前相机和真实场景深度处理云/不透明物体关系，并保持现有对数深度及视口/纹理存储尺寸变换一致。

必须分别正确处理：目标在整朵云前、云中、云后；目标跨云边缘；多个目标处于不同深度；多个云互相重叠；尾焰等透明内容与云交叠。

特别禁止：
- 把整朵云缓存成一张带总alpha的图，然后只按云中心或一层深度测试判断前后。
- 为了避免遮挡错误，把标注框内所有云清掉、给目标加亮/加黑，或只对特定目标ID修补。
- 在目标处于云中时错误使用整条射线总光学厚度；应只使用相机到该像素不透明表面之前的云贡献。
- 把“关掉depth write、打开depth test”当作所有体积相交问题已解决的证明。

可选实现包括有界厚度的puff解析/查表截断、前后分层/深度切分的光学缓存、局部实时求值或其它可验证表示。需要保留足够深度信息；单张总alpha无法恢复任意目标深度对应的部分光程。

局部回退必须按所有真实不透明几何、相机和深度判断工作，不能依赖标注开关或目标类别。多个半透明云的次序、源项和透射必须一致，不可重复混合。极热尾焰在低透射率下仍可能有可见贡献，早停阈值须考虑实际动态范围，不能仅以固定alpha接近1就无条件丢弃剩余贡献。

### 3.5 近距、穿云和可选impostor缓存

允许远/中距使用puffs或impostor，近距/入云改用分层、解析光程、预积分或有限实时积分。按实际画面误差与成本选择，不强制每一处都零积分。

- 入云/穿出需平滑、具有厚度感，不能突然消失、贴脸卡片、相机旋转时整朵云跟屏幕转。
- 缓存优先存云自身光学量，不把当时机体和最终背景烘焙进去；新目标进入视野不能留下旧影。
- 缓存失效至少覆盖相机位姿/投影/分辨率、云位置/形状/天气/风、光照/源项/波段、资源或配置变化。
- 投影误差、相机位移与云距离同时考虑。仅视线角变化很小不保证近距平移没有视差。
- 稳态命中、全冷缓存、大角度转向、跨LOD、同时多缓存失效都实测；不要只报静止相机命中时FPS。
- 插值/交叉淡入不能形成双重消光、光晕或延迟目标遮挡。每帧真实场景深度仍要参与。
- 预计算和更新纳入内存/启动/峰值帧时间预算。有界分摊缓存更新工作可以，故意降低输出新帧频率不可以。

不得重演P19“低分辨率光学附件上采样+目标框补丁”。源纹理/atlas/impostor的内部尺寸可依据其表示设计和投影误差选择，不能与最终传感器分辨率混为一谈；必须证明不是以损失目标邻域遮挡和云细节掩盖降质。

## 4. P20-C：硬件调度与其它耗时，按因果A/B实施

### 4.1 调度先读拓扑与有效状态

读取实际CPU在线集合、可用亲和掩码、大小核/频率policy、当前进程与线程的CPU放置、CPU/GPU/DDR可用频点和governor、温度/热限制、内存压力、GPU/MPP与网络活动。路径和功能以目标内核实际暴露为准。

当前仓库已有 `[VideoOutput] WorkerCpuList=4,5,6,7`，不意味着其对当前板端所有线程均生效，更不意味着把整个进程钉到某一颗大核会更快。核对继承关系，记录关键线程实际affinity，而不是只打印请求值。

CPUFreq按policy管理；不得假设每颗核有独立调频控制。不得硬编码其它板型sysfs路径、CPU编号或DDR寄存器。

### 4.2 至少做四种可比组合，拆开算法收益与调度收益

- P19算法 + 原有效调度。
- P20候选算法 + 原有效调度。
- P19算法 + 调度候选。
- P20候选算法 + 同一调度候选。

无收益的组合无需扩成长测，但记录否决原因。候选可包含关键渲染/输出线程在不同大核或核组的合理放置、日志/管理线程分离、已支持的CPU/GPU performance请求及内存带宽策略。

只采用实测降低关键路径或抖动、且长时间没有热退化的组合。记录请求频率和可获得的实际状态；`scaling_cur_freq`并非在所有驱动上都等于瞬时硬件频率。

不关闭温控、不超频/改电压、不靠SCHED_FIFO长期霸占、不降低系统安全性，不修改内核或替换GPU/MPP驱动作为默认方案。IRQ/RPS等只有真实网络热点证据时做可恢复诊断，不盲目迁移所有中断。

两个renderer共用GPU和系统调频资源。临时全局调度策略应由统一测试控制器管理：第一路退出时不能把第二路仍需要的策略恢复。脚本必须保存原值，在正常退出、失败/中断后恢复并读回；无法设置的项明确记录。最终交付可选、可关闭的performance运行配置，默认与启用时各自真实指标均给出。

### 4.3 其它优化只处理证据明确的问题

检查GPU过度绘制/FBO切换、状态/uniform重复设置、读回等待与真实拷贝、CPU像素转换、每帧分配、日志/审计、同步锁和编码/发送工作重复。

- 日志与完整审计可在性能测试中低频/可配置；关键错误、计数和帧身份不能消失。
- 原彩色视频与客户灰度视频不当然能共享同一个编码AU；仅输入、像素语义、参数、时间一致时复用。减少重复转换或编码必须有实际计数证明。
- 最终云提速后重新测读回，不能照搬RGBA“对齐必更快”或同帧PBO“异步必更快”的假设。
- 真正跨帧异步读回/缓冲环只有在驱动支持且测得净收益时考虑；写清帧号配对、额外延迟、缓冲所有权、STOP排空和尺寸切换。不在同帧等待fence后宣称消除同步。
- 不通过把队列从32/120/4096继续加大掩盖慢生产。需要处理的是消费速度和帧年龄。
- 保留Xorg/Mali硬件路径及已验证MPP设置；HeadlessOffscreen不等于移除图形上下文。不得以llvmpipe或软件编码回退冒充实机PASS。

## 5. P20-D：DDS域已经独立实现，本轮核验与说明

### 5.1 当前事实，不再沿用早期08覆盖行为

最新P19已实现同一进程级Factory、按域复用/创建Participant：

| 键 | 链路 | 仓库默认 |
|---|---|---|
| `[DdsProtocol] DomainId` | Control/INIT/Realtime输入、InitAck、供激励观察的VideoStatus | 150 |
| `[DdsVideo] DomainId` | 原视频/SEI、Meta、Annotation、VideoStatus、原视频侧诊断和时钟 | 150 |
| `[CustomerDdsVideo] DomainId` | 四个客户TX视频Topic | -1，继承DdsVideo |

仓库客户输出默认Enable=false。P19报告记录的实际部署INI为150/1/1，不要与仓库默认150/150/-1混淆；接板后以当前实际文件和 `[DdsDomains]` 为准。

本项目校验域范围0..232；只有客户项可-1。相同域只复用一个Participant，不同域不重复全局Init/Finalize。VideoStatus分域时在原视频域发布，并在控制域镜像；同域只发一次。客户链仍不新增Status/Meta Topic。

### 5.2 配置与使用必须讲清楚

- `HWASIMIR_RUNTIME_CONFIG`决定实际runtime INI。
- 域环境变量 `HwaSimIRDdsProtocolDomainId` / `HwaSimIRDdsVideoDomainId` / `HwaSimIRCustomerDomainId` 优先于INI。
- 一次全局Factory仍加载一套QoS XML，三个域独立不等于三份任意XML可以各自加载。控制启用时以DdsProtocol.QosFile为共同文件；其他请求路径的处理和实际日志核实，不允许静默覆盖不解释。
- 修改域配置需要重启相应进程，STOP/RESET不会迁移已创建Participant。
- DataDrivenTestQT域对齐控制域；VideoDisplay的NetworkConfig/`--dds-domain`对齐原视频域；客户Demo的`--domain`对齐客户域。
- 三个域是通信路由，不是platID/sensorID，也不会隔离两个renderer对GPU的竞争。
- 固定TX Topic没有平台身份字段，不要在相同Domain/Partition/Topic上同时运行两个同角色生产者。

提供直接可用的全150、全1、150/1/1、150/150/1配置片段/示例，并注明哪些是保存的示例、哪些是当前实际部署。保留已有150/1/2诊断配置；不要为了性能修改用户当前实际域。

读取并核验以下现有实现，不另造一套：
- `DDS/Runtime/DdsRuntimeManager.{h,cpp}`：`participantForDomain`、start/shutdown。
- `DDS/Protocol/HwaSimIRProtocolEndpoint.{h,cpp}`：输入/ACK域、视频辅助域及Status镜像。
- `DDS/Runtime/BoardTelemetryService.h`：旧视频诊断/时钟域。
- 两个视频Publisher的Participant选择。
- `DataDrivenTestQT/DualSensorPanel.*` 三域显示、导出及校验。

若代码已经正确，只补齐用户操作说明、有效配置可视性和必要回归；不要把已有功能重新包装为P20新增重大开发。发现导出/实际加载不一致才最小修复。

## 6. 验收：外观、性能、功能分别判定

### 6.1 图像验收矩阵

SWIR、MWIR分别覆盖：Clear/Cloudy/Overcast；少量及大面积重云；云上/云下/侧视/接近/进入/穿出；相机静止/平移/旋转/FOV变化；目标位于云前/云中/云后及跨边缘；多个目标与多云交叠；尾焰开/关与云交叠。

至少有1～3像素和5～10像素量级小目标的诊断样例，并保留普通FOV生产视频。诊断可使用明确标识的独立相机/几何fixture；不要偷偷放大生产目标、提高温度或抬near让问题消失。

正式SWIR/MWIR场景保持在当前大气/LUT支持域；若已有云穿越场景超域，做不冒充正式物理验收的独立几何/光学fixture，明确记录覆盖范围。不得为获得通过直接关闭域检查或外推LUT。

图像证据：固定映射、同相机/目标实际几何的before/after全帧与ROI、未经增强的生产MP4；保存选定raw光学/源项诊断。换表示后整图MAE/SSIM只是辅助，不能一律要求旧图字节相同，也不能用“好看”掩盖遮挡错误。

硬正确性门槛：无NaN/Inf；合法透射率范围；无错误的云后目标穿透、云前目标误消隐、矩形截断/光晕、明显面片翻转/排序跳变、LOD爆闪和缓存残影；标注关闭时遮挡仍正确；云关闭时其它成像路径不退化。

先定义并保存基准几何、参考光程/遮挡位置及允许误差，再测试。对于更换云内部形态后的非逐像素可比区域，给出类别化外观评审，而不是事后挑一个整图误差阈值把结果判PASS。用户视觉确认单列PENDING，不代签。

### 6.2 性能矩阵与统计

1. 重云offset3000/600帧筛选：相同条件下原算法/新算法、默认调度/候选调度分离；记录原生raw对照及生产组合。
2. 正式同板双路：粗320×320 Gray8 raw到TX/LDecode，精800×800灰度H264到TX/HD264；同源输入、两INIT/两ACK、同时输出。SWIR与MWIR分别运行，原DDS视频保留。
3. 最新候选完整原始1.txt回放，源行语义不变；普通可替换数据源继续可用，无输入哈希白名单。
4. 至少一次不短于5分钟的重云/运动/缓存失效持续压力，使用单独标识的有效fixture或明确分回合重复；不把重复回合首尾重置当作消除长时间积压。
5. 新路径冷缓存、暖缓存、快速相机变化/尺寸切换及START/STOP峰值必须包含，不能只统计缓存命中时段。

主基线和最终候选至少进行三次可比复跑；诊断候选无需全部长测。每路分别统计输入、接受、执行、新帧、发送AU/Sample/字节、接收、解码、保存；压缩Sample数不是帧数。

指标至少：平均及1秒窗口FPS，P50/P95/P99/max帧时与输入到解码时间，超过80ms比例，队列/帧年龄随时间曲线，STOP已接受输入排空、客户结束NAL到末帧解码、MP4完成分开计时；CPU/GPU/DDR可用状态、温度、内存及调度设置。

跨机器时钟未经校准不得相减。Windows激励和Windows接收可用同机steady_clock明确配对；不向客户流增加私有SEI/时间戳做测量。不把解码QImage或GUI提交时间称为屏幕呈现时间。

性能结论必须回答：**重云时是否还持续欠帧、是否存在秒级积压；预算到底省在哪；收益依赖哪种调度配置；最差缓存更新帧怎样。** 由39升到50仍是未解决。小数FPS与已有轻微延迟偏差披露，不用挑统计区间、丢样本或改统计终点获得达标。

### 6.3 P19回归不能丢

- 正常H264结束、短流/分片边界/暂停/两回合；结束NAL收到后的尾帧迅速解码，前端排空与封装另计。
- 客户故障Reader退出后同PID STOP/RESET/INIT/ACK/START恢复；initCount=1。
- 原VideoDisplay与客户同时工作；原SEI/实时数据/标注/录像继续；客户0个HwaSim私有SEI。
- 无VideoDisplay、禁用旧视频时客户独立输出。
- 任意合法身份/角色、同平台Control提示、普通文件无输入SHA准入、三域导出不退化。
- 分域主配置150/1/1和全150烟测；至少一次150/150/1或150/1/2证实三域互不被静默覆盖，错误域零接收。
- 四客户Topic至少短测；raw整Sample、640000容量保护、Gray8/RGB顺序、H264Baseline/GOP/正常结束保持。
- 雨雪、尾焰、稳定数字坐标标注、对数深度及固定HDR做代表性回归，不在本阶段另开无关美术优化。

客户现场raw最初内部码7根因、真实客户最终互通、客户硬件解码、真实辐射标定和屏幕延迟仍各自标NOT_VERIFIED，不因本轮云提速自动关闭。
