# Codex P5：模型材料验证、云层显示与游戏喷流特效

## 使用范围

用户说明本轮需求用于飞机游戏画面。本任务实质限定为通用模型资源检查、材料绑定验证、天气云的图形显示，以及非标定的游戏发光/烟气特效。保留仓库真实文件名和已有工程上下文，不隐瞒资源类型，不要求绕过模型或工具的限制。

不新增现实设备的特征标定、光谱指纹、识别或业务控制能力；不推导特定型号的真实温度、喷流参数或空间热特征。对现有资产只验证通用几何、法线、UV、材质映射和图形效果。

这是代码实施任务。完成本范围内的修改、构建、测试、部署与图像交付；需要工具权限时按流程申请。单项确实不能实施时说明具体限制，并继续可独立完成的其他项，不把只读检查当成完成。

## 一、目标与已核对的问题

P4 已解决启动全目录扫描、SSH 图形环境继承、体积云深度附件错误，以及同步模式旧帧/重复帧问题。保留这些修复，不重新开展一轮泛化性能排查。

本轮按顺序完成：

1. 检查另外三个资产目录的材料是否真正进入最终像素。
2. 修复云看不到、大小尺度不合适、片状云与体积云明暗不一致的问题。
3. 将两张交叉平面暴露出来的“X”形改为通用游戏喷流特效。
4. 保持正常启动、DDS、同步一输入一输出和实机性能。
5. 盘点下一阶段普通相机响应实验所需数据，不在本轮加入完整探测器模型。

已经从当前代码确认、需要进一步验证的事实：

- 运行材料库优先来自 `Config/Materials/MaterialDatabase.csv`；根目录 `materials` 是兼容/开发副本。
- `IRSceneMaterialMapper` 读取材质编号纹理与 XML，再绑定数据库参数；当前着色器参数槽上限为 8，存在超过上限被截断的风险，需检查实际三个模型是否触发。
- `IRMaterialBandOptics::resolve` 优先使用显式波段反射率，缺失时回退至太阳吸收率或热发射率的近似；这些近似不能标成实测波段属性。
- 云层总覆盖边长当前 30000 m，纹理世界尺度/网格相关参数为 5000 m；这不等于每一朵云直径 30 km。
- 体积云中心高度当前 2200–4200 m，水平半径 350–1000 m，最多可见 1 个；高空、窄视场或无有效加载中心时可能看不到云。
- 片状云的 MWIR 明暗已使用公共显示范围，但体积云更新仍调用 `IRWeatherEffects::cloudEmissionGray`，需要统一口径。不要仅凭 RGB16F 格式推断缓冲值就是未经缩放的物理辐亮度。

## 二、三个模型：证明材质表确实生效，不重新制作 f35

本轮检查以下三个现有资产目录，保留真实资源名称：

- `Config/TargetLib/models/f22`
- `Config/TargetLib/models/aim120`
- `Config/TargetLib/models/aim9x`

不重新绘制 `f35` 的材质编号贴图；可以保留它作为旧图回归样例。

### 2.1 资源与绑定

逐模型记录实际加载的：

- 几何、可见纹理、材质编号纹理、XML 的绝对路径和哈希；
- 顶点法线、UV、缩放、朝向和模型边界；
- 材质编号纹理的实际通道、位深、采样方式；
- XML 材质数量、数据库匹配数量、GPU 实际绑定数量、未知编号比例；
- 每种材质在纹理中的占比；有条件时另统计可见像素占比，不能把两者混为一谈。

确认运行时用的是 `.tif`、`.png` 还是其他格式，不能只修改未被加载的预览 PNG。

材质编号属于数据，不作 sRGB 颜色转换，不采用会混出新编号的普通线性过滤/平均 mipmap。无 UV、法线退化、翻面或纹理槽不一致时做最小资源导入修复，不靠全局 abs(NdotL) 掩盖错误。

当前最多 8 个材质槽：先查三个模型是否超限。未超限不无故重构；超限必须明确报错或实现经验证的数据查表方案，不静默只保留前 8 项，也不擅自合并不同材料。

### 2.2 “文件存在”不是“材质生效”

增加专用测试配置，不改用户正式材料数据：

1. 普通球体/平板使用两个明显不同、且明确为人工测试值的材料。
2. 固定几何、光照与公共显示范围，只修改一个测试材料属性。
3. 验证对应编号区域的 GPU 输出发生预期变化，其他区域不被错误改动。
4. 复用该检查方式验证三个资产的材质绑定。

分别记录：已读取、已传 GPU、GPU 确实使用、尚未使用。尤其粗糙度不能因为放进参数数组就标成“已实现粗糙镜面反射”。本轮不为了列满表格新增复杂材料模型。

核对 CSV 比热的单位转换；使用既有单位定义，不凭外观改物性值。保留所有数据来源与回退标识。

交付三个资产的普通着色预览、UV/法线诊断图、材质编号图、现有 NIR/MWIR 显示图。预览可以设置便于检查的相机位置，但不得修改模型真实缩放或正式传感器视场并隐瞒。

## 三、云：先证明在视野里，再统一显示尺度

### 3.1 先建立可重复的云场景

使用普通地面、立方体或其他中性遮挡物建立确定性天气测试，不依赖特定业务目标才出现云。

保留已有业务兼容入口；通用天气渲染模块应能接收独立的加载中心，测试时由相机/测试场景显式提供。

至少覆盖：

- 远场片状云；
- 单个局部体积云；
- 远场片状云与局部体积云共存；
- 相机在云下、云旁、云上；
- 相机移动造成的空间视差；
- 云位于普通物体前面/后面；
- 无有效业务目标时，天空天气的规定行为。

“加载中心移动”只能控制哪些固定世界云块进入对象池，不能让整朵云跟着相机或目标平移。固定随机种子，同一个世界网格的云形可重复。

### 3.2 为什么看不到云：逐项给出证据

低频记录以下状态，不逐帧刷长日志：

- 配置路径与有效天气类型；
- 是否允许显示云、当前加载中心是否有效；
- 候选云数量、活动数量、真正提交绘制数量；
- 相机高度、云高度、距离、视场与云的屏幕投影大小；
- 被剔除的原因：不在视野、太远、屏幕太小、密度/透明度为零、数量预算等。

必须区分：没有生成 / 生成但没画 / 画了但被遮挡 / 已显示但对比度很低。

不要把“云启用=true”或对象池数量大于零当成可见性通过。

### 3.3 云大小

保留大范围远场覆盖，不把总覆盖边长当作单朵云尺寸。

分清并尽量独立控制：

- 远场覆盖范围；
- 纹理重复的世界尺度；
- 单个体积云的尺寸；
- 密度噪声的特征尺度；
- 屏幕投影大小和可见数量。

先做明确标注的“小尺度游戏云团预设”，与当前大云预设对照。不全局把云搬到相机高度，也不强行在每帧视野中心生成云。

若 INI 的变量同时决定网格吸附和纹理重复，可在证实需要后作最小拆分；避免为一个尺寸问题增加大量互相覆盖的开关。

### 3.4 实际查看纹理与参考图

在本机实际打开 `ondulus ir 红外图片示例` 中的云图，仅比较块状/层状结构、边缘、内部层次、稀疏程度和遮挡；不宣称反推了对方软件内部算法。

检查 `Config/Weather/Textures` 真实文件的透明通道、灰度范围、翻转、位深和已存在的许可/来源说明。不要把有相同文件名当成加载到相同算法的证明。

至少检查 `cloud_scattered`、`cloud_overcast`、`cloud_cumulus` 的实际用途。输出纹理原图、遮罩预览和当前有效纹理路径。

需要从灰度得到透明遮罩时离线生成可追溯缓存，不每帧处理，不硬套同一个阈值到所有纹理；不得修改原图覆盖来源。

### 3.5 片状云、体积云、背景共用显示口径

重点审计：

- `UpdateStage7SkyHorizon` 的公共 MWIR 显示范围；
- 体积云仍调用的 `cloudEmissionGray`；
- `u_cloud_gray` / `u_stage7_cloud_gray` 的真正含义；
- Stage5 RGB16F 到 Stage6 的数值范围、缩放、gamma 和截断位置。

给每个写入位置注明：原始物理量、公共线性缩放值，还是最终显示灰度。

RGB16F 只是存储格式，不自动代表任何单位。不能把已归一化的云灰度与另一种数值范围的背景直接混合，也不能片状云用一条曲线、体积云再用另一条经验曲线。

优先作最小统一修复，不重新改造已验证的大气或材料物理模块。非标定的游戏近似必须明确标识为视觉近似，不称作实测结果。

透明合成在统一线性域内进行；gamma/极性等最终显示变换只应用一次。用已知常量图层验证混合，例如两个测试值等权混合应得到中间值。

不要把纹理白色直接等同于任意物理辐射值；纹理先服务于云形、覆盖和密度。不要为了“云应该亮”给所有天气统一抬白。

### 3.6 保留 P4 图形兼容性

继续使用 P4 已验证的原生深度附件路径。不得重新引入在板卡上失败的深度附件替换/拷贝，也不得出现一边采样一边写同一纹理。

透明代理表面能做深度测试，不等于已经完成沿整条体积光线的精确遮挡。先用普通遮挡物验证当前近似的范围，并如实记录限制；本轮不扩展全地形阴影。

避免片状远场云与局部体积云在同一处重复叠加变成厚灰幕。通过明确的覆盖/淡出策略解决，不靠长期关闭一整类云通过。

## 四、“X”形改为通用游戏喷流效果

本项只修复发光/烟气几何的美术表现，不改变既有机体材料、热区定义或控制协议，也不拟合任何现实装备的真实喷流特征。

### 4.1 先保留诊断对照

用普通喷口测试几何展示旧交叉片，从端面、侧面、斜角观察，证明交叉平面是伪影来源。

不要通过增亮、放大、关闭深度测试或隐藏端面观察方式掩盖“X”。

### 4.2 推荐实现

首选少量、共享纹理、批量绘制的软边精灵粒子。可使用 Panda3D 的 SpriteParticleRenderer，或 C++ MeshDrawer 的 billboard/particle 路径；先核对本地 Panda 版本的实际接口。

“面向相机的粒子”用于单个软片，不是让整个喷流系统失去固定的发射方向。

要求：

- 保留固定发射方向；
- 单个粒子软边，沿生命期淡入/淡出，不显示矩形边；
- 从端面观察不出现两片相交的十字；
- 普通不透明模型仍能遮住它，不能穿透模型画在最上层；
- 近、中、远距离平滑切换复杂度；
- 图集和粒子池预加载，不逐粒子新建 NodePath；
- 粒子数量/质量档变化不应无理由导致整体亮度翻倍；
- 发光部分与烟气部分使用各自合适的透明合成，不能把整个效果简单叠到纯白；
- 在现有公共线性合成域中处理，不与最终 gamma 灰度混用。

可先以每个效果 32–64 个、全场 256 个粒子作为测试预算起点。它只是可调整的工程预算，不是物理参数或最终性能保证。

不要直接升级为高采样体积求解。只有精灵方案经过实际端面/遮挡对照仍不满足时，再评估一个低面数、软边透明的通用体积外形；选择实机效果和耗时更合适的一种。

### 4.3 动画与性能

以仿真经过时间推进动画，不以日志次数、回调次数或渲染循环次数代替时间。同步20/30/60 Hz下动画速度一致；暂停/重新初始化按既有规则恢复，不能造成旧粒子串回合。

用现有启停接口或独立特效测试开关验证，不新增业务控制字段，不调整实际控制逻辑。

首版不引入新的 Python 运行依赖。若现有工程未链接完整粒子库，优先使用已可用的 C++ 批绘制方式，避免为了一个效果扩大部署依赖。

### 5.2 性能与同步

沿用800×800、DDS默认通信、OrderedQueue、Mali和MPP及P3性能策略。

记录改前/改后场景更新、绘制、回读、编码、发布的耗时；对云和粒子特别记录屏幕覆盖及透明重叠成本。

不得降低分辨率、跳过有效输入、减少业务场景内容或复制旧帧来通过。

性能报告分清平均值、P95和最大值；没有实际采样分位数时不虚构P95。

最终至少：

- 同步20/30/60 Hz回归，按同一有效回合独立统计输入、采集、编码、发布、接收；
- 暂停输入、重置、初始化、天气切换；
- 含实际可见云与开启游戏特效的60秒混合场景；
- 该混合场景10分钟长测。

必须至少一组真实存在局部体积云并参与绘制，不能拿visibleCloudVolumes=0的测试证明体积云性能。

同步60 Hz按有效输入一一输出，显示速率名义60 Hz；统计窗口差异如实解释。没有多余业务帧、遗漏、旧帧、覆盖、溢出、持续排队或GL/DDS/MPP错误。异步结果单列。

如果新特效超过预算，优先降低透明重叠、合并绘制、复用对象及屏幕尺度分级；降低特效质量时明确记录，不隐藏取舍。

## 七、下一阶段的相机响应准备

本轮只列数据清单，不实现高保真探测器。

规划下一阶段为普通相机响应实验：

1. 先验证现有曝光/显示范围、MTF模糊、噪声各自实际作用，使用灰阶、棋盘和普通场景。
2. 再加入可追溯的SRF光谱响应；无实测曲线时继续清楚标记矩形响应或人工测试曲线，不能称为高保真。
3. 最后评估QE、曝光时间、读出噪声、暗电流、饱和容量和数字化模型，限普通传感器实验，不做现实装备性能标定。

列出缺什么数据、哪些本地文件已有、来源和单位是否明确。检查SRF是否已经包含QE/光学透过等权重，避免以后重复乘算。
