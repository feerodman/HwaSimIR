## 一、对 P20M 结果的判断

P20M 已完成有价值的解析、UTC 解析、索引、诊断和构建工作，但原来“客户输入超出 LUT、目标与背景异常”的问题仍未完成修复。新候选明确使用 `UNCHANGED_P14` 数据；客户轨迹计数守恒不代表正式物理结果有效。

本次核对了 GitHub 执行报告和源码、用户提供的 `code_validation_01.zip`。包内 manifest 列出的 64 项文件大小和 SHA-256 全部一致；报告、生成器、索引等与上述仓库提交一致，`HwaSimIR.cpp` 在统一 CRLF/LF 后一致。ZIP 不包含逐 case 的原始输入卡、tape6/tape7/flx 和完整逐帧性能文件，最终物理归因仍应在本机读取这些证据。本次没有运行 Windows 官方 MODTRAN、重新构建或操作板卡。

1. 每组或分量带数值、单位、状态、数据身份、单元/case来源和输入快照；区分 `VALID`、`ANALYTIC_BOUNDARY`、`OCCLUDED_PHYSICAL_ZERO`、`OUT_OF_DOMAIN`、`NUMERICAL_FAILURE`、`NOT_VERIFIED`。整体结果另报 `COMPLETE/PARTIAL/INVALID`。
2. 已知传播值可保留为明确标识的部分结果/诊断；未知太阳项不填零后标 COMPLETE。明确正常夜间暗画面与失败关闭黑画面的不同状态。
3. 相对太阳方位接入生成器、schema、查询参数和缓存键；将按正确方向查询出的分量送入 Shader 合成，避免再次施加同一方位因子。已有开发样本 SWIR 路径散射在标注0°与90°间相差约32.7%，省略此轴不满足任意方向。对称压缩必须由所选大气/边界条件证明；极点、竖直LOS、太阳在天顶等退化情况用稳定向量处理。
4. 移除正式链路中“用SZA45取得传播”“太阳高度<=0直接关闭所有相关项”等旧补丁，改用A–E独立查询及物理边界状态。UTC无效时太阳分量失效；不得从旧环境角得到部分有效太阳值又标完整M1。传播不依赖UTC的部分保持独立。
5. 背景不再读取 `latest_valid_target_los`。天空使用方向辐亮度，半球天空辐照度用于表面照明，二者单位与几何不同。地面包含海平面/地面高度，相机视线到地平线或大气顶的路径按独立域处理，不受目标50 km上限截断。

7. 至少一个具有全部所需节点的新连续单元及其非节点查询通过，两个成像波段、宽带加热、独立背景均有真实来源。另接通零路径/正短距和晨昏边界的集成用例。小单元仅作端到端门槛，不能替代3–20 km/0–50 km目标。

### E. G3：完整合法域、实际生成和独立精度验收

1. 选择并实现能证明覆盖的参数化或合法单元网格。不要从 `(h_obs,h_target,r)` 笛卡尔网格中删除非法节点后，仍声称整个包围盒可插值。
2. 可评估正距离 `(h_obs,r,u)` 参数化：`h_lo=max(3,h_obs-r)`、`h_hi=min(20,h_obs+r)`、`h_target=h_lo+u*(h_hi-h_lo)`，`u∈[0,1]`，`r=0` 独立。它只是减少不合法节点的一种候选；须在统一海拔、球形/WGS84、实际直线/折射映射后证明适用。上下限拐点、近竖直、近水平、太阳遮挡面须分区/加密。也可使用有显式边界和邻接关系的有效网格。
3. 生成 `domain/cells` 清单：单元边界、顶点/节点、所需case、合法区域、邻接、插值规则、精度状态。运行时返回真实 `cellId`，仅在已声明有效单元内插值。删除缺失中间节点后不能跨更大间隔自动变成另一有效单元。结构检查独立于随机查询。
4. 太阳有效域处理完整0–180°以及相对方位周期；白昼、晨昏、深夜、解析遮挡分别有依据。任何未验证区间准确保留状态，不把补0算全域完成。地理范围与气象假设分开声明。
5. 在单元/schema闭环通过后，输出去重后的分量任务数、按实际模式计时的ETA、磁盘估计、失败恢复规则，然后运行完整批次。A不重复乘太阳维度，B/D不重复乘观察端维度；复用仅限计算身份与谱精度兼容。按数据清单checkpoint，持续执行到目标域完整或出现可证实的外部阻塞/工具能力限制。
6. 保持旧域回归，发布新域新增行与实际接受行数一致；旧335行无效历史条目单独归档统计。新manifest绑定实际数据hash、引擎/数据库、模板、谱响应、各组件域、单元数、QC身份和生成来源，不沿用P14上界声明。
7. 先做开发加密验证，之后冻结误差预算，再保留至少200个独立分层物理状态、每个检查SWIR/MWIR及相应分量。覆盖节点间高度/距离/能见度/RH/太阳角/方位、0与近场边界、上下视/竖直/水平、晨昏和深夜；背景域另做方向/地平线样本，不能只验证目标。
8. 按上一阶段工程门槛：τ绝对误差≤0.01；其它分量 `abs(test-ref) <= A_component + 0.05*abs(ref)`，已有更严格合同则采用更严格者。`A_component` 按波段、物理分量、日照状态结合数值分辨率和最终图像误差预算在holdout前冻结，不能用白昼最大值给夜间宽松兜底。最终AGC前辐亮度和目标-背景对比另设明确预算并验证。上述是工程近似验收，不是实测标定。
9. 用作加密的失败验证点转入开发集；最终holdout仍保持独立，保存固定种子、输入、原始官方参考、误差明细和最坏点。对官方工具无法稳定出参考的近场边界，明确解析/近似依据和重叠验证，不能用同一近似生成自己的真值。

### F. G4：统一仿真时间，完成目标、背景和输入契约验收

1. 复用已修的UTC解析，补统一 `SimulationClock` 语义：太阳天文位置使用协议UTC；热积分、气动热/局部热源和其它带历史的物理状态使用协议仿真相对时间与dt；steady clock用于性能计时。逐一审阅仍用 `ClockObject::get_frame_time()` 的材质加热、Stage4、背景/遮挡缓存节拍，按真实职责修正，不盲目全局替换显示动画。
2. `UnixEpochMs` 分支目前的单调性处理与日内毫秒不同。明确在会话接收层处理重复、倒退、乱序、暂停恢复、RESET/INIT、跨日、变速回放和大时间跳变。合法离线随机查询与有历史的流式演化分开；大dt按数值积分要求细分/明确重置，不靠简单夹到1秒悄悄丢失物理时间。
3. 当前IR更新stride由INIT `videoFps/IRUpdateHz`算，实际物理节拍还取决于输入时间和发包速度。改为按仿真时间、状态变化和误差预算管理昂贵更新/缓存，在本轮60 Hz输入下实测；每帧相机/目标几何、有效性和时序配对保持准确。跨单元、快速运动、太阳遮挡和环境变化及时失效缓存，不能以降低响应换通过。
4. 同一带时间戳输入在不超过60 Hz的不同发送速率下，以及故意延迟处理并最终排空时，对齐同一仿真时间，比较温度、各辐射分量和AGC前输出，应符合冻结的误差预算。保留原始协议时间；这项是时钟一致性验证，不是100 Hz性能测试。随机天气效果使用可复现种子或隔离随机分量进行对照。
5. 相机完整键不匹配目前只是记录后return。读取客户目标类型、platId、targetId契约，查明0x33/0x22含义和配置来源；仅在已证实的正式协议映射下修映射。无匹配、无有效视线或重合方向时发布显式帧/诊断状态，接收端可识别；保留旧相机方向不能当有效图像。尊重客户固定线协议，状态扩展须兼容，不能私改payload布局。
6. 测试无目标、有目标、删除/新增、ViewValid切换、A有效/B无效、有效→域外→恢复、错误引用→恢复、RESET/START/STOP、UTC无效/跨日、经度±180°、高纬、3/20 km、0/50 km边界。合法状态物理有效；非法状态被明确分类且不污染其它目标/背景。
7. 三份客户CSV全量与旧ordinary回放均通过生产stim预检和正式渲染路径；独立DDS发端用于接收链路复核。客户文件中的非有效View/非法引用不强求普通成像PASS，而应有正确的状态数量和预期行为。不要删行/夹高度距离/固定旧日期以绕过预检。
8. 保存足够精度的AGC前线性ROI或帧、目标温度、A–E分量、物理有效性、相机姿态及目标-背景差，与官方参考/已验证合成值对比。固定显示设置仅用于可视检查，不能靠调增益、加整体温度或输出黑图证明物理正确。
9. 逐字段对照实际客户INIT/realtime：分辨率、波段、simMode、时间字段、目标完整键、气象、domain/QoS等。已保存协议证据能核查的先核查；模拟发端不等同客户软件现场互通，真实软件未运行保持 `NOT_RUN`。
