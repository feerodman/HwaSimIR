本轮优先顺序：

1. 恢复使用原始 `DataDrivenTestQT/1.txt`，普通三个程序能够通过 DDS 回放；不再将低空受控 demo 当成原轨迹。
2. 审计并补齐 SWIR/MWIR 的通用大气数据与查询能力，面向用户声明的最远约 50 km 范围。先覆盖实际文件需要的合法查询，再验证额外范围；两者分开报告。
3. 图像走正常物理材质通路，解决已发现的诊断图冒充物理效果证据、通用尾部热源未实际绘制等问题；保留 P12 已做好的云雨雪和玻璃。
4. 保存不同波段、多因素混合测试的独立图片与实际 DDS 接收端视频，而不只是孤立组件图、法线图或拼图。
5. 补最终版本冷启动/长测、普通按钮操作、STOP 完成与诊断开销问题。

本轮使用现有资产检验通用几何、明确的合成材料和普通成像流程。温度、材料、热源、气动响应等物理基准用可审计普通样件/民用模型；不反演或调优具体武器的材料、推进、尾焰或飞行红外特征，不将工程结果称为真实装备探测/识别能力。无需再为通用模型测试更换全部资产。

允许为这些目标增量修改三端代码、实际 shader、必要配置、LUT 工具和测试。保护用户已有修改、原始模型和原始 1.txt；保留 P12 完整回滚。不无关升级 Panda3D/Qt/FFmpeg/Mali/SDK，不迁移图形后端，不修改系统时钟或许可证。板端离线，开发机已有许可 MODTRAN 可离线生成数据。

## 2. P13A：原始输入审计和普通回放口径

### 2.1 原文件与字段

找到实际普通程序使用的 `1.txt`，记录绝对路径、SHA-256、大小、表头、有效数据行数。原文件字节不得修改，不以普通 demo 覆盖/改名，不重新生成一个不同几何的文件仍叫 1.txt。

按生产解析器的字段映射，扫描全部输入，输出 `input_1_audit.json` 与简明报告：

- 源行号、原始时间列、文件距离列；
- 真正消费的 observer/target 位置、高度、姿态、速度及单位；
- 由生产同语义坐标转换得到的斜距，而不直接信任文件距离列；
- 高度、距离、时间间隔的 min/max 和异常行；
- 全键目标身份以及有效性/状态字段的实际来源；
- 所请求的波段、环境、太阳日期/时刻和主动光参数来源。

先明确“原文件实际覆盖”与“额外要求到约50 km”是两件事。不能仅看到首行22 km就声称文件覆盖50 km，也不能只测50 km端点就声称整个范围可用。

### 2.2 解析错误与时间基准

核查 `readData()`：明确跳过已识别表头和空行；真实缺列、非法数、NaN、坏单位要报告准确行号/字段且不悄悄变成0。保持协议字段映射，不引入损伤/制导等新语义。检查第一/最后有效行、START/STOP/重置时索引边界。

原文件开头时间间隔10 ms，而当前可能60 Hz逐行发送；读取器未保留第一列时间，step自身按1/inputHz推进。必须把 sourceTime、simulationTime、sendWallTime、videoPTS 分清并写入审计。

保留用户要求的输入逐项对应。不要为凑60 Hz在引擎中跳行、篡改速度或更换原几何。若沿用逐行60 Hz播放，明确它与源时间尺度的关系并让物理时间消费保持明确一致；确需发送前重采样时，必须采用显式、可追溯的派生策略并保留原行映射，不能把重采样说成逐原行无损回放。不要静默改变既有回放口径。

### 2.3 普通启动

在数据覆盖补齐后，将最终交付 sidecar 和运行目录恢复为原 `1.txt`。`ordinary_demo_1km.txt` 留作明确命名的诊断样例，不是默认替代品。输入缺失/越域时显示具体原因，不自动切换样例。

控制 UI 至少能看见当前输入文件名/路径、所用波段和覆盖状态。日常仍用三个程序和现有 RK launcher，不要求用户手工拼多条启动参数或测试环境变量。

## 3. P13B：通用 SWIR/MWIR 大气覆盖与共享查询契约

### 3.1 不再用硬编码试验范围代表真实数据能力

用现有正式查询器、或由发布器生成且绑定 LUT SHA 的覆盖 manifest，作为控制端预检和渲染器的共同依据。尽量复用现有实现，不平行写两套容易漂移的插值逻辑。

控制端不是只看 CSV 各列 min/max：必须考虑必需分量、响应、湿度 profile、几何合法性和实际插值单元。渲染端始终做权威运行检查，控制端 sidecar 的表身份与板端发布不一致要明确指出。不要为了覆盖常数方便而改现有协议布局；优先利用已存在的状态/诊断机制与原子发布同源元数据。

显式 fixture 的绕过不能作用于普通 1.txt。允许真实支持的夜间零太阳项，但不能把缺失数据填0冒充夜间/有效值。未覆盖条件维持明确拒绝；不要写死更大的上限假装数据已经存在。

### 3.2 数据需求以实际输入和通用范围为准

盘点已有原始 MODTRAN 光谱、单位转换与发布表：保留已审计的 MWIR 远距透过率/路径分量；不全部推倒重跑。SWIR 必须有自己的实际覆盖波段数据。

先对全部 1.txt 生成 query manifest，列出当前可查询、缺分量、缺几何、越界、无合法插值单元的具体条件，再生成最小补数计划。第一批先让该文件合法查询得到完整支持。之后按用户通用场景声明扩展到约50 km，并给出明确的高度/环境/太阳角适用域，不声称所有排列组合均支持。

几何要区别传感器与目标高度、水平距离/斜距、观察方向、地球曲率与路径是否相交地面，不能继续用等高水平路径代替不等高斜程。几何不成立的组合不生成/不插值。太阳散射要核对相对方位等输入；现有表未记录的几何假设必须进入元数据，不能用仅SZA的旧表宣称任意太阳方位都已验证。

humidity_profile 标签与高空实际RH不是一回事；记录当前协议湿度如何映射到模型大气，不能把海平面缩放标签当成整条路径恒定局部RH。

### 3.3 生成和校验

使用本机已许可 PcModWin5/MODTRAN5、P11/P12已有脚本和模板。先小批pilot核对输入/输出，再按已计算的缺口分批扩展。保存输入卡、实际输出、单位、响应、case id和哈希，支持断点继续；没有变化的case不重复跑。

至少按当前模型消费核对：

- 目标→传感器透过率；
- LOS热路径和太阳散射路径分量；
- 目标位置太阳直射与天空漫射辐照度；
- 宽谱太阳加热表所需高度/太阳角；
- 主动照明路径与传感器路径的数据来源及波段重叠。

不把TOTAL_RAD不加区分地当path叠加到自渲染目标；不重复包含表面贡献。不把band-mean透过率简单按距离幂次外推，不拿1/2 km的Lpath线性放大到50 km。保留谱单位/Jacobian检查、能量与零值语义。

离线以独立受控样片参考核对光谱积分与运行时波段近似；按已冻结误差门处理，近零量用合理绝对误差和相对误差组合，不能后改阈值追求PASS。数据齐全、CPU查表正确、GPU正常材质输出是三个独立门。

长距离扩表可能放大运行时查表成本：加载时建索引/复用缓存，避免每目标每帧线性扫描全表。测量实际查询开销，索引和插值不得改变物理语义。

通过后原子发布表与覆盖manifest，Windows/板端一致；覆盖全部原文件合法查询，并单独做通用50 km边界与中间点、越界拒绝、波段切换测试。板端运行不调用MODTRAN程序。

## 4. P13C：正式成像、通用热源和天气组合

### 4.1 正常图与诊断图不能混为一谈

对 `TargetLib/models` 现有资产逐个使用正常业务加载路径和通用合成材料出SWIR/MWIR图。检查有效环境/Shader状态：P5MaterialView=0，正常 M1 已实际启用，调试颜色/UV/法线/material-ID/强制灰度视图全部退出正常图。

诊断图可以额外生成并明确标注，但不能作为正常物理图；测试工具如发现诊断分支仍激活，应拒绝将该案例判为“正常材质通过”。`raw` 元数据也要区分SI物理值与人为编码诊断值。

正常图继续检查：单位、浮点缓冲、法线和轴向、缩放、材料ID、UV/透明度、局部热区绑定、反射/发射分量、世界和局部坐标一致性。修通用实现缺陷，不根据特定装备图片调反推真实材料/温度。

给出修复前后同输入对比。不能用大范围加热、逐目标增益、最低灰度地板、硬描边或整屏锐化去掩盖错误。固定映射用于因果和数值对照，正常AGC用于观看；两者都保存，不用“固定窗口全黑”或“AGC很亮”单独判定物理对错。

### 4.2 通用尾部热源/羽流的未显示问题必须定位

先在普通受控热源/民用样件的当前正式链复现附件所见 formalTauReady=0 / coreVisible=0 状态。按顺序给出数据和像素证据：

- 真实输入状态是否要求源开启，profile/节点是否加载且属于正确全键对象；
- 正式大气查询为何未就绪，是测试几何越域、缓存、初始化时序还是其它原因；
- 节点是否进入实际draw，位置/尺度/方向/深度/裁剪是否正确；
- 是否先经过合法的线性贡献合成，再进入公共映射/AA/编码；
- on/off配对是否在受控区域产生预期贡献，后处理/编码是否才使差异不可见。

`EnableEnginePlume=1`、CPU分量非零、对象计数非零都不是实际像素贡献证明。真实tau=0与“缺数据”必须区分，不得用tau=1绕过。

保持单独羽流与尾部表面热区各自来源，不把羽流加热整个模型。已有通用形态和动画可保留；缺陷修复在受控样件上证明，现有模型仅做同一通用效果的绑定/坐标兼容性回归。不要新增具体装备的推进/尾焰标定或探测优化。

“看得到/够亮”不是唯一门：对已声明应当可见的近景普通测试检查贡献；远景如投影面积或遮挡导致不明显，要报告原因，不扩大模型/羽流来伪造远距离细节。

### 4.3 保留P12天气，增加普通轨迹下的组合验证

沿用稳定cloudId、世界空间流式云、云前后和Batch雨雪。普通1.txt的高空相机未必位于原低空云层，不得为了截图好看把云粘到目标上。记录真实云对象、相机/目标/云相对关系、视线进入/离开与屏幕覆盖。

在普通成像场景检查天气合成的遮挡、线性贡献和背景；避免同一段大气既通过LUT又被天气层重复计算。保留P12通过的单云隐藏/恢复和玻璃最小回归，不重写已通过模块。

雨雪要有合理空间范围；高空原轨迹没有雨雪穿过相机时，另建明确标记的普通低空天气组合样例，不伪装成原文件几何。允许演示场景，但物理假设、实际气象分区与示例用途必须标明。

太阳角、主动光、能见度、高度/速度变化先用简短受控对照隔离通用原因，然后进入混合段。主动光不在传感器带内时正确零贡献是PASS，不强制所有波段都变亮。原轨迹的速度/姿态列不因演示效果而改写；温度时间响应基准仍用普通样件。

## 6. P13E：最终性能、普通操作、部署

### 普通启动与按钮

全Windows与Windows+RK用交付sidecar和实际输入文件测试，无强制Topic/identity测试参数。保留正确的自动发现、严格过滤、晚启动/接收端重启、同进程SWIR→MWIR→SWIR、STOP后再START和数据空档恢复。

### 冷启动/长测

修最终SWIR冷启动3帧超80ms；区分输入受理→writer、网络到达、解码、Qt呈现、录像完成。跨机使用已有校时估计及误差，不直接相减不同机器steady clock。

沿用READY前预热思路时，说明实际预热了哪些资源；不能消费第一条真实输入、不发布假帧、不推进热状态，记录启动→READY时间，不能无限延迟READY把开销藏起来。

最终同一个ELF/配置上：两波段各60s普通完整链，另至少一个300s最复杂天气组合长测；SWIR最终冷启动及混合复测不可用MWIR结果代替。原始全轮与稳态分别报告，原80ms硬门不删启动样本。保留输出新产品数、接收/解码/录像守恒、GUI统计窗口及max gap。

P12的300s轮属于旧ELF，不能作为P13最终长测通过。最终版本每个证据都绑定真实运行的ELF/EXE与配置哈希，而不只读取过期deployment_version中的expected值。

### STOP和诊断开销

分析约5s DDS drain/约10s完整结束：区分固定sleep、ACK timeout、真正队列排空、线程join和录像flush。能事件驱动就不固定等待；不更改既有可靠交付语义，不在末帧完成前杀进程。

已有PFM异步writer保留；剩余GPU wait/readback和CPU拷贝按测量决定是否优化。GL操作遵守上下文与线程归属，不能将所有GL读回随意扔到后台线程。采集与普通性能分两轮，采集满队列明确报错，不丢证据冒充完整。

### 打包与回滚

成套交付Windows三程序、RK ELF/launcher、正式配置/数据/资产以及原1.txt，排除许可证、口令和无关历史巨量文件。核对包内原1.txt与工作区原文件SHA一致。至少保留P12完整可恢复快照；实际回滚后有新DDS图，再恢复P13且身份一致。

## 7. 错误处理与完成定义

建立 error ledger，按类记录：

- 原文件解析/时间/单位；
- 大气缺数据/无效几何/查询身份；
- GL格式/读回/上下文；
- shader正常/诊断模式混用；
- DDS发现/解码/GUI/录制；
- 测试脚本的帧身份/基线版本/阈值问题。

每项给出最小复现、实际根因、修复位置、前后证据、最终版本。处理旧失败时保留原结果及superseded原因；不能把错误一概归为AI模型问题，也不能关闭检查消除日志。

只有以下同时满足才可将工程交付项判为完成：原1.txt普通DDS回放；所声明的通用大气范围有实际数据/查询证据；正常物理材质而非法线图；通用热源与混合天气有实际像素贡献；视频真的在包中；最终版本性能/生命周期/回滚状态真实。
