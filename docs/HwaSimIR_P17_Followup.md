## 2026-09-22 深度根因复测

实际普通协议配置为 near=1 m、far=200000 m（原录像 Stage0 `viewMinMax=1/200000`）；无有效协议值时的代码回退为 1/100000 m，不能混称原录像参数。仅作隔离的近裁剪面对照为 1000/200000 m。

用户的判断成立：远距离透视深度精度是大片三角碎斑的实质根因之一。约 4902 m 距离处，传统 D24、near=1 m 的单级深度间隔约 1.43 m，足以使普通机体前后表面争用深度。提高 near 后改善是因果线索；同构图、同模型、同输入、同 ELF 的线性/对数深度对照进一步验证了它。

修复对全部场景深度着色器使用一致的对数深度，保留协议 near/far，不以抬高近裁剪面裁掉近场内容。离屏体积相机单独设置相同深度参数。`P17LinearDepthReference=1` 仅用于整个场景的线性基线对照。

四段板端录像 `aim120_{linear,log}_v4`、`f22_{linear,log}_v4` 均完整回放原 4318 行。窄视场分别为 0.5/2 µrad，明确属于细节诊断。对 sourceSeq 3600..3615 和 4200..4203 保存原浮点、编码前图像及实际几何矩阵；20 对几何 JSON 完全一致，18 个连续移动帧对均无重复帧。排除轮廓 3 像素后，按实际模型表面重投影得到：

| 实际模型 | 编码前内部差值 P95（灰阶） | 编码前内部差值 P99（灰阶） | 浮点内部差值 P99 |
|---|---:|---:|---:|
| AIM120 | 3.4421 → 1.8212 | 33.2129 → 9.0000 | 93.5440 → 8.6259 |
| F22 | 0.9439 → 0.7034 | 6.0000 → 4.0000 | 0.5385 → 0.5050 |

浮点单位为 W/(m² sr µm)。这些差值还包括重采样、覆盖变化和物理变化，不能当作纯闪烁指标，更不能声明全部闪烁归零。大面积深度碎斑显著消除；剩余轮廓/细纹理变化仍需区分。证据及精确方法：`logs/p17/review/inspection/depth_comparison.json`。

## 云重整与验收记录

重整包括：共享密度缓存保留原密度、追加上下光程列及 mip；正式 SI 源中仅对既有反射照明施加云内衰减；RGB24 对数深度预通道在光线积分处截断不透明遮挡；普通平面云保留输入 alpha 的软边，取消二次阈值造成的硬岛状轮廓。缓存检查 `tools/p17_cloud_cache_check.py` 验证四个模板密度逐字节不变，光程列误差不超过半个量化级。

穿云复测另外定位到离屏缓冲重建后的纹理绑定缺陷：INIT/尺寸改变重建深度纹理，池中已有云节点却仍持有启动阶段空纹理或旧纹理。修复统一在 composite 设置阶段重绑定深度纹理及视口，启动阶段不再设置空纹理输入。

继续复测确认，修复绑定后仍有独立崩溃。完整 core 显示 GLES 上传期间读越界；只记录、不改参数的 `tools/p17_gl_upload_audit.c` 截获板端实际调用：一级上传 48×48×96，而对应 RAM 只有 48³ RGBA；后续级别的 Z 也错误保持 96。错误 mip 链还使正常体积纹理无有效像素，不能把两个未崩溃的 v6 录像称为云效果通过。板端库虽报告 1.10.15，实测上传行为才是本结论依据，不推断所有官方版本都有此问题。

兼容修复在 Linux 仅上传原始 96³ 基层，用 GLES 一次生成正确 3D mip 链；Windows 保留 CPU mip 链。密度、尺度、光源和滤波均保留。另将 RGB 深度取样坐标改为像素坐标除以实际 `textureSize`，避免 800 视口配上扩展纹理时读到 padding，造成 625 像素边界的矩形截断。越界证据见 `logs/p7/p17_cloud_upload_audit_v2/board.log`，崩溃记录见 `logs/p17/review/inspection/core_v6.log`。

云验收的普通协议相机轨迹由 `tools/p17_cloud_camera_fixture.py` 生成，依次覆盖既有 CustomerDemo 世界云的云下、云上、接近、进入、穿出。只改变相机输入，不改云位置、尺度、密度和亮度。它是独立相机场景，不能冒充原始 1.txt。调试器下跑通的 `p17_cloud_views_gdb` 仅供定位；最终验收必须用不带调试器的完整录像。

`p17_cloud_wide_v6` 曾请求 1000 µrad，但普通传感器规则钳制为 200 µrad，故不作为新的宽视场证据。最终相机场景明确请求有效范围内的 200 µrad。相机轨迹按刺激器时间运行，逐帧位置应以发送记录/板端实际几何为准，不能把不同运行中的同一 sourceSeq 当作严格同相机状态。
