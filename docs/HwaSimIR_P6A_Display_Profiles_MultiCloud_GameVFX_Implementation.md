# P6A 显示配置、多云、游戏特效与接收界面实施记录

本文记录已实施的代码、部署和实际 RK3588→MPP→DDS→Windows 证据。选定双云档的同步、暂停、重新初始化、60 秒与 10 分钟计划测试完成；四云稳定 60 Hz 未通过。艺术效果已交付可复核原图和视频，局部采样条带、片云低对比等限制单独列出，不以帧率代替画质结论。

用户后续补充的工作也纳入本轮：直接使用 Weather 的现有云素材；接收界面实时 FPS、中文标题和小窗口布局；平台与目标数据同页；按各模型喷口绑定尾焰位置和尺寸。最后一项只改变渲染挂点和游戏几何尺寸，不改变温度、热区、发动机响应、气动参数或协议。

## 2. 每波段配置的真实消费链

保留 `Config/SensorWave/default_NVG.json`（NIR）和 `default_MWIR.json`（MWIR）。原文件逐字节存放于 `SensorWave/Archive/P5`；当前文件保留已接线字段及明确的 HwaSimIR 命名空间。旧文件中的字段不能因存放在 JSON 中就算算法已实现。

完整盘点见 [逐字段清单](HwaSimIR_P6A_Profile_Field_Usage.md)，机器可读版本为 `logs/p6/profile_fields.json`，共 324 行，包括归档的未实现字段。

| 路径 | 存储与消费 |
|---|---|
| Systems.SensorConfigurationSystem.Width / Height / FOVH | profile 缺省；有效接口几何优先，800×800 不被覆盖；缺省 FOVH 反推仍经过已有接口校验和上限 |
| Systems.SensorConfigurationSystem.SpectralResponseRangeLow / High | 与固定波段范围一致性校验及既有诊断输入；不是新 SRF 积分 |
| Systems.SensorConfigurationSystem.FOVV、FocalLength、DetectorPitch、LensFnumber、ADCBitNumber、NETD | 解析、保存、日志；未接入完整探测器或光学模型 |
| Systems.DisplaySystem.DisplayBits | 精确读取此路径；日志元数据；当前视频仍为 RGB8/H264 |
| Systems.SensorConfigurationSystem.BlackHot | 遗留元数据；实际极性使用 HwaSimIR.Display 的 WhiteHot |
| HwaSimIR.Display.Presets.*.Gamma / Gain / OffsetGray / WhiteHot / Mode | 保存为 IRDisplayPreset，进入 ApplyStage6DisplayConfig、公共最终显示 shader 或 AGC |
| 归档的 QE、曝光、井容量、MTF、局部 AGC、图像融合等 | 未实现；不据这些数值宣称探测器已接线 |

`IRJson::Document` 用已链接的 OpenCV JSON 树按明确路径读取，并在前面验证 JSON 词法、布尔/数字类型、重复键、有限数、层级和尾部内容。错误使该波段整份回退，不留下半份有效状态；选择一个发布目录后不从其他目录混用文件。当前模式不支持转义后的 schema 键名，日志明确报错。NIR/MWIR 为本轮要求的有效配置；遗留 VIS/SWIR 文件的范围冲突会被记录并回退，未扩展那些波段。

每个显示字段的优先级为：显式环境变量 → 旧 INI 显式键 → 当前波段预设 → 代码缺省。冲突记录 `[DisplayEffective][WARN]`，给出唯一有效来源。INI 中原有五个显示键保留注释过渡示例，避免旧键悄悄遮住 JSON。

Legacy 为默认固定映射，gamma=1、gain=1、offset=0、白热；Game 为 gamma=1.8 的固定映射；Black 使用同一 gamma 的黑热极性；Auto 为显式自动映射。OffsetGray 的单位是 8 bit 灰度级，Gain 无量纲。配置校验结果在 `logs/p6/config_check.log`，包含异常类型/路径、缺文件、波段冲突、跨目录隔离和有效 800×800 几何。

## 3. 线性显示与真实编码验证

独立测试图包含连续灰阶、暗灰阶、相邻中灰阶、普通中性平板、小面积 1.5 高亮片和解析球形明暗测试片。球形部分是 shader 中的通用球形明暗图案，不作为三维材质 BRDF 或物理相机标定证据。

同一 sourceSeq 保存：显示前 `linear.pfm`（共同缩放的线性场景值，**不是物理辐亮度单位**）、编码前 `linear_rgb8.png`、Windows DDS 解码的 `received.png`。PFM 只保留真实 800×800 视口，不把底层 1024 分配区当图像。

修复了固定增益经手动 AGC 再应用一次的问题。固定映射依次为公共 gain/offset、最终截断、单次 gamma、极性；不针对某个业务目标加增益。自动映射统计直接读显示前浮点缓冲，避免从已经截断、量化的 RGB8 反推。

RK 的通用 Panda 浮点纹理抽取曾请求 GLES 不支持的 HALF_FLOAT 读回并产生 0x502，旧失败目录保留。改为临时 READ FBO 挂接已有颜色纹理，以 RGBA/FLOAT 读回，再恢复 FBO 和 pack 状态；没有替换场景颜色/深度附件，没有读回深度，没有恢复 P4 失败的自动深度纹理方案。[GLES 3.2 读回规范](https://registry.khronos.org/OpenGL/specs/es/3.2/es_spec_3.2.pdf) 是该传输类型选择的依据。

首轮实机显示结果：原始最高值为 1.5，固定映射梯度单调违例为 0；Legacy 的浮点→RGB8 平均差为 0.188 灰度级，MPP/DDS 解码与编码前 RGB8 平均差为 0.323，99% 误差不超过 1 级，灰阶端点保持 0/255。Game/NIR gamma 与黑热的固定公式平均差约 0.295 级，gain=0.5 约 0.177 级。完整逐点数值在 `logs/p6/evidence.json`。

Windows 软件编码的旧测试存在约 2.70 灰度级平均偏差；独立 FFmpeg 解码与接收程序 PNG 完全一致，偏差不由接收 UI 重复 gamma 造成。此项如实保留，不能把板端 MPP 的误差数字当成 Windows 软件编码的结果。灰阶测试也不替代彩色原色矩阵标定。

Auto 的整幅浮点读回有明显额外开销，最终约 51.42 ms/次统计，请求 20 Hz 时实测 14.80 FPS，性能未通过。首轮 Auto 的 120 帧已收到，但 STOP/最终计数未闭合；发送器原来在 STOP 后 500 ms 就退出。修复应用停止确认后，最终 120 帧全部闭合，详见第 7 节；不将首轮记录计为稳定性通过。

另以原 P5 mixed 场景、Legacy gamma=1、800×800 重跑迁移对照。实际 DDS 图片平均差 0.041 级灰度，最大局部差 11 级；旧版首输入丢失导致动画相位并非逐帧相同，不能称为位级一致。旧版成功接受/输出 599，新版为 600；稳态区间 renderMs 从 14.123 到 14.253，FPS 从 60.009 到 59.989。证据为 `logs/p6/migration_evidence.json` 和 `rk_legacy_migration_comparison.png`。此项验证兼容映射，不是新天气美术对照。

## 4. 现有 Weather 纹理与多云

实际打开并检查了本机素材，纹理通道盘点图为 `logs/p6/weather_inventory.png`。`cloud3d_001...027.png` 是带 alpha 的二维云外观图，不是真正的三维密度切片；不能直接当作 Texture3D 使用。当前选用 001、002、014、020 的 alpha 和亮度，初始化时生成四份 96³ RGBA8 艺术密度/明暗体，再沿真实视线体积采样。原 PNG 未改写。它们提供不同轮廓，替代测试中规律的椭球外形；厚度、侧向变形属于游戏构造。

片云最终直接使用 `cloud_scattered.png` 的 alpha：该图 RGB 基本恒白，读取亮度会丢失形状。此前用 `cloud_overcast.png` 亮度形成的片层在实机只有约 1 级灰度差，未当成画质通过；改用有明显空隙的原始透明遮罩及独立光学深度缩放。Repeat sampler 负责重复，保留连续 UV 导数供 mip 过滤，避免 fract 断点破坏缩小采样。

| 参数 | 本轮选定游戏档 | 含义 |
|---|---:|---|
| 片云覆盖边长 | 30000 m | 沿用覆盖范围，不与纹理重复周期混为一谈 |
| 片云纹理世界周期 | 9000 m | 直接使用现有 alpha 素材，减少远处细碎点 |
| 局部云水平/垂直半径 | 240 / 180 m | 单朵体积尺寸；大云压力测试另乘 2 |
| 体积采样 | 8 步 | 四种密度模板，共同线性合成 |
| 常用局部云数 | 2 | 1/2/4 在同一 ELF 下分别实测 |
| 显示/视角 | Game、800×800、35° | 明确的诊断视角，不推广为任意业务视场 |

片云、局部云和背景先在线性空间 source-over 合成，再进入同一个公共显示映射。NIR/MWIR 的游戏源值分别配置，不强制两波段具有相同明暗关系。背景是可说明的游戏天空/地面渐变，没有全屏模糊。

最终发布配置下，两云逐个关闭的实机 RGB8 对照分别改变上部云区 53,421 和 41,373 个超过 2 级的像素，证明两朵云各自产生像素影响；不是仅依据 selected_for_render 日志。证据目录为 `rk_release_two_pixels/off1/off2`，关闭一个云不重新编号另一个云的模板。

首版完整矩阵中的 1/2 云平均渲染约 59.88/59.96 FPS；4 云约 57.18 FPS，**未通过 60 Hz 性能档**。放大两云约 57.14 FPS，放大四云约 46.89 FPS；放大四云旧发送器的最终计数也未闭合。最终交付选定普通两云档，后面的发布版复验和长测单独列数值。

已测试分离、重叠、横移、进出视野、普通板位于云前/后、片云与局部云共存。仍采用整朵远近排序；互相穿插的体积没有逐像素合并光程。原生深度测试代理表面，不能正确截断云内部穿过物体的每条光线。这些限制保留；8 步也仍可见局部条带/采样纹理，艺术质量待确认。

最终版横移和进出视野视频各 240 帧、8 秒，检查了 0/2/4/6 秒实际解码帧；云在屏幕边缘裁切、离开并重新出现。旧环境/新 Weather 美术采用同一 Game 显示设置和相机，分别为 `rk_release_legacy_art` 与 `rk_release2_cloud2`：平均 renderMs 14.859→16.029，约增加 1.171 ms；FPS 60.03→60.01。图像中原来的规则暗团和细碎遮罩变为不同的云轮廓与更疏的片云，仍存在上述采样和低对比限制。

## 5. 普通喷口特效与实际模型挂点

普通喷口美术仅在 `ordinary_nozzle.json` 中配置：集中亮核、软主体、较长稀疏烟气分层，沿用共享 `soft_sprite_atlas.png`、固定批次和 LOD。相机移动时粒子面朝向视点，但发射轴与粒子中心留在模型空间。比较使用相同 Game 显示和背景；没有改变模型温度掩盖几何问题。

`rk_plume_before_orbit/received.mp4` 与 `rk_plume_smoke2_orbit/received.mp4` 是同一发布程序的旧/最终普通喷口美术预设，均为 800×800、240 帧、8 秒，Game gamma=1.8、gain=1、offset=0、白热。端面和侧面可见新预设的集中亮核，主体边界仍为软边，绕行过程中没有交叉片 X。`temporal_review.png` 从原视频取 0/2/4/6 秒帧供检查，不是效果生成图。烟气刻意较弱；最终艺术接受仍由用户确认。

| 同条件普通喷口 | 改前 renderMs | 改后 renderMs | 解释 |
|---|---:|---:|---|
| 侧面，30 Hz / 8 s | 17.734 | 18.378 | 新亮核增加一层批次，约增加 0.645 ms |
| 环绕，30 Hz / 8 s | 18.450 | 18.406 | 区间差异接近波动范围，不声称性能提升 |

以上为各 3 个日志区间的平均，不是逐帧 GPU 查询或 P95；美术改善没有被写成免费的性能优化。

普通方板遮挡场景把方板放在喷口朝向相机一侧 3 m：喷口和近端被挡，延伸到方板前面的粒子仍然可见，因此该图不是“整条喷流全遮挡”的证据。粒子保留深度测试、不写深度；实际模型三角度图另外检查自身几何与喷流的关系。

烟气单独开启时，初版与关闭图最多只差 2 级灰度，视觉过弱，未作为独立层次达标。最终普通美术配置修订为 `P6A-game-2-smoke-contrast`，仅将 Smoke.LinearSource 从 0.24 改为 0.08，保持密度、批次、LOD 和业务目标热状态不变。烟气用更暗的低对比颜色呈现；预览实际解码对照约 13,254 个像素超过 2 级，最大差 7 级。最终新配置的图像和长测另用 `smoke2` 命名，不混用初版记录。

用户后续明确要求各目标尾焰对准喷口，因此另加 `GameVFX/nozzle_attachments.json`，作用于正常运行。以下坐标来自仓库 OBJ 的喷口边缘，末端略向外偏移以避免插入端盖；长度是独立游戏尺寸选择，不是现实发动机参数。

| 资产 | 喷口中心（模型局部 X/Y/Z） | 开口半径 X/Z | 核心/外层长度 |
|---|---|---|---|
| f35/F35C.obj | 0 / −6.84 / 1.0878 | 0.4395 / 0.4395 | 3 / 7 |
| f22/f22.obj | ±0.6815 / −6.86 / −0.96385，两个 | 0.5812 / 0.23345 | 3.4 / 8 |
| aim120/AIM120.obj | 0 / −1.83 / 0 | 0.080 / 0.080 | 0.9 / 2.4 |
| aim9x/aim9x.obj | 0.00005 / −1.515 / 0 | 0.052 / 0.052 | 0.75 / 2 |

这些数值使用项目现有模型单位。所有发射轴沿模型局部 −Y，随模型姿态变换。f35 原几何挂点在模型原点附近，缺少喷口的 Z 偏移；f22 需要双喷口。普通模型几何检查图在 `logs/p6/nozzle_mesh`，仅用于检查本项目资产，不能替代实机接收图。

双喷口在同一预分配批次中使用两个发射点，LOD 的全局预算按实际发射点数分摊。修复了 INIT 按资产顺序分配时后面的机型拿不到尾焰节点的问题：复用未绑定目标的预留批次，保持原节点上限。热模型仍输出原有温度、亮度和透明度；只在渲染层设置挂点、宽高和长度。

四种资产的端面、侧面、斜角共 12 组板卡接收图已逐项检查；另有同显示条件的 F35 旧挂点对照。F35 亮核从机体下方的旧挂点移到实际喷口；F22 端面可见两个分离亮核；两个小模型使用独立较小半径和长度。侧视小尺寸粒子仍有颗粒感，柔边淡入带来轻微软过渡，不以材质或热区补亮掩盖。这些视图验证当前资产和姿态，未宣称所有资产、所有距离的审美都已通过。

## 6. 接收端 UI

界面标题采用明确 UTF-8 转换，显示“数据显示 · DDS 全链路”。平台和目标放在同一页，上下各一张表，可拖动分隔；场景参数另页滚动。表格不再强制等分压缩到不可读，保留可拖动列宽、横向和纵向滚动。小窗口中侧栏与视频一起调整比例，视频按实际可用尺寸等比缩放。

实时 FPS 使用单调时钟统计最近 1000 ms 的有效解码图像 GUI 更新，250 ms 更新标签，单独显示请求 Hz 和真实图像分辨率。它不是显示器垂直刷新率，也不把元数据通知计为视频帧；暂停、停止或断流后窗口内帧自然清空到 0，INIT 清除上一回合统计。

`logs/p6/rk_nozzle_f35_oblique/ui_800x600_tab1.png` 是接收真实 RK/MPP 视频期间的 800×600 同页界面截图，包含两张有数据的表；标题、页签和数据中文已目视检查。窗口缩放只影响屏幕呈现，保存的无标注 DDS 图仍为原始 800×800。自动截图仅为显式测试入口，正常运行不自动改窗口大小。该截图过程中窗口调整会使 GUI 短时积压后集中更新，因此瞬时标签可高于请求 Hz；稳态 FPS 取无窗口截图操作的独立性能场景。

## 7. 同步、部署和最终实机回归

发现并修复 INIT ACK 后、主线程处理 START 前到达的首个输入被 START 清队列丢弃的问题。已由 INIT 准备的新回合在 START 保留这些输入；没有恢复 Latest 覆盖。每个回合对照发送器成功写入、板端 DDS 收到、业务接受、唯一新视频、元数据与标注关联，旧帧拒发继续保留。

慢速 Auto 场景还复现了另一项结束缺口：发送器退出前 DDS writer 返回 ACK=0，但板端应用没有收到 STOP。只等待传输 ACK 不足以证明应用完成。DataDrivenTestQT 现在订阅既有 VideoStatus，按平台、传感器、回合和通道匹配；观察到本回合运行后，再等待 STOP 对应的 running=false，最多 30 秒，超时明确报错。确认后再等待 writer ACK 并关闭。不重发 STOP，不更改 IDL、控制指令或 Latest 策略。
