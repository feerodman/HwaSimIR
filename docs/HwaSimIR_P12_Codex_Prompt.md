## 一、任务目标和边界

P11 已修复 SWIR/MWIR 主要公式及生产链并完成 RK3588 DDS 测试。P12 不推倒重做，主体是：

1. 首先修复“用户普通启动三个程序，但显示端没有图像”。
2. 对 P11 遇到的成像问题逐项核销；区分修好了、只通过单元测试、历史失败、最终缺少图像证据。

4. 保留原有尾焰/云雨雪的可用实现和外观；定位集成与测试场景问题后作必要修复，不因物理改动就整体重写天气。
5. 补云前/云后与单云 ID 元数据、真实 2 km 路径数据、板端受控玻璃证据；分开测普通运行与诊断抓图性能。
6. 用最终成套版本实际出图、部署、回滚，交付普通人能启动的程序与独立示例图片。

正式收发验收继续 DDS-only。不要重跑 UDP/TCP 全矩阵，不把其旧证据迁移成 DDS PASS。NIR 只保留兼容；VIS-SWIR 不扩展，继续明确拒绝。

允许修改必要的三端源码、INI/JSON、DDS 配置解析和状态发现、实际 shader、通用材料绑定、天气元数据、诊断/测试脚本和文档。保持用户已有改动，先备份再增量修改；不要求原 49 个文件字节完全不变。禁止重置工作区、覆盖原始模型、无关重构、擅自 commit/push、整体升级 SDK/驱动、改系统时间或许可。

指定目录中的 aim120/aim9x/f22/f35 资产用于普通网格渲染和合成材料显示回归，不开展真实武器/装备红外特征还原、实测特征调参或探测性能优化。尾焰/气动/照明物理的数值与因果基准使用普通样件、民用目标或明确的合成热源，参数不得冒称对应真实装备。

## 二、先复核的具体证据，不要从零猜原因

读取附件 `HwaSimIR_P12_P11_Audit.md`，并在当前源码/日志中确认以下线索；线索不是允许跳过复现的最终结论。

### A. 普通启动与自动化路径不同

P11 `p11_rk3588_band_acceptance.ps1` 给显示端明确传入：

```text
--receive-transport=dds --stream-role=direct
--plat-id=1001 --sensor-id=2 --dds-domain=150
--dds-topic=HwaSimIR.Video.1001.2.H264
--dds-codec=h264 --dds-width=800 --dds-height=800 --dds-fps=60
--dds-qos=<明确的 Windows QoS 路径>
```

测试还指定 working directory、生成的 INI、诊断环境变量，并隐藏窗口。这不能覆盖普通双击启动。

当前 VideoDisplay 从 EXE 同目录读取 NetworkConfig.ini；缺 Identity 时得到 0/0，VideoStatusListener 严格按 ID 过滤。显式 topic/codec/尺寸参数会关闭自动 VideoStatus 发现。缺省 Topic/Runbook 的 `Video.precise.H264` 与正式测试 `Video.1001.2.H264` 又不同。不要因此盲目删除 ID 过滤；需查当次有效配置和订阅状态。

### B. P11 长尾可能主要受采集干扰

两轮 60 秒 PFM 在 sourceSeq=180、900、1800、2700、3540 保存；这些帧 captureTaskMs 约 86–102 ms，邻帧约 0.65 ms，并与启动后延时尖峰对应。首帧 doFrameMs 约 219–225 ms。

先拆出首次资源准备、GPU 读回、CPU copy、PFM 序列化/写盘，不要直接认定是物理 shader 贵或全是硬盘慢。P11 latency 是板端受理到 output 打点，不是跨机显示端到端；FPS 还剔除了头尾。80 ms 在旧分析器里仅被统计，不会自动使总体 FAIL。

### C. 有 cloud case 不代表画面里真的有云

P11 cloud 测试的相机/目标都在 500 m，实际板端日志云体高度为 9400–10600 m，FOV 约 9.17 度。应优先验证视线内的真实云几何与投影，而不是重写云算法。

雨雪 Batch 日志有 particles=128/draws=1；另一条 Overlay active=0 不能单独证明 Batch 没有绘制。检查真实粒子位置/alpha/深度及屏幕像素。

Representative 中的 plume_on、active_on、太阳一个角度、速度一个值，不能替代效果 on/off 和多条件因果对照。

### D. 大气数据的“存在”不等于查询可用

P11 LUT 1628 行：SWIR144、MWIR479、NIR1005。SWIR 和新 MWIR 各144条完整列数据的高度坐标是0.001/1km、距离0.1/0.5/1km；旧MWIR335行虽有2km和高空坐标，但缺新完整链所需部分太阳/天空/散射列。

2 km blocker 指视线路径距离，不是高度。不得拿旧行的某个2km字段直接清除此 blocker；必须匹配全部环境和五分量契约。普通手动旧轨迹若超出有效域，也应有明确物理错误，而不是静默黑屏。

## 三、执行方式：四个可独立验收的里程碑

按 P12A→P12B→P12C→P12D 执行，每阶段完成即保存状态和小结，再继续，不等到几十小时之后才提供第一个可用结果。仅遇真实外部阻塞时暂停被阻塞支线，列出日志与最小人工动作；其它独立项继续完成。

建立 `docs/HwaSimIR_P12_Execution_State.md` 与问题台账：问题ID、触发条件、证据等级、修复文件、基线/候选哈希、测试结果和未决项。被测文件或有效配置不变时复用有效结果；依赖改变时只重跑受影响测试。相同失败重现两次后必须提出可检验的新假设，不再无变化重跑完整矩阵。

硬件测试单一所有者：同一 RK3588、DDS identity/topic、运行目录和最终配置不得由多个 agent 同时写入或并行占用。可并行做隔离的只读审计/独立单元测试，不允许并行抢同一板卡污染性能。不要杀死不属于本轮的进程。

### P12A：第一优先级，普通启动必须可见图像

#### A1. 保存实际失败现场

确认用户实际启动的三端路径、版本和拓扑，不要把全 Windows DDS 与 Windows控制/显示+RK3588渲染混为一谈。核查当前桌面快捷方式、EXE所在目录与已有启动器，不只看构建输出目录。

记录三端：

- EXE/ELF 路径、SHA256、工作目录、实际依赖库、编译功能（DDS/编码/解码）。
- 读取的 INI/JSON/QoS 绝对路径、文件存在性及优先级；本轮有效配置快照。
- domain、transport、streamRole、channel、platID/sensorID、视频/状态/标注/元数据 Topic、发布和订阅类型。
- 实际网卡和 QoS 网卡绑定、初始化/应答/开始/实时输入状态；跨机 Windows/RK 的 QoS 不能不检查就互相覆盖。
- INIT 的 band、分辨率、目标可见性、位置/距离与 LUT 有效域。

在原普通入口复现，不注入 P5/P6/P7 测试场景、不强制 --dds-topic 绕开自动发现，不先把配置改到测试值再声称复现成功。

#### A2. 把无图区分为可观察状态

从以下链逐段记录状态和低频计数：

```text
控制UI实际发出INIT/START/Realtime
→ 仿真端接受/执行
→ 已准备好有效物理配置与渲染输出
→ 编码并DDS发布
→ 显示端收到有效VideoStatus并绑定正确流
→ 收到视频样本
→ SPS/PPS/IDR及解码帧
→ GUI槽消费
→ GUI实际显示新帧
```

UI 至少明确显示：等待初始化/状态、身份或配置不匹配、无视频样本、等待关键帧、解码错误、上游波段/大气不支持、正常显示及当前帧号。不要将上一轮旧图静默当成新图；未运行/失联/过期要可识别。

仅在必要位置增加低频诊断，不逐帧刷长文本。不能以 PNG 解码文件非空代替 GUI 可见图像，最终必须有窗口截图/实际绘制帧证据。

#### A3. 修复最小范围，不靠长启动参数

优先解决实际发现的配置缺失/陈旧、0/0过滤、status自动绑定、Topic模式不一致、streamRole误选、QoS路径、编解码依赖和GUI线程问题。

- 统一普通配置的 identity Topic 规则；旧模式显式兼容，禁止固定写死1001/2造成多实例串流。
- 正确处理未配置身份：使用明确配置或UI显式选中已发现流。不得取消ID过滤、订阅任意发布者、混用旧session/generation。
- 接收端晚启动/重启、先启动显示端、同进程re-INIT均能按现有生命周期恢复。
- 普通DDS用户无须额外运行DecodeGateway等第四程序；direct/decoded的要求必须明确，正常三程序路径使用已实现的direct解码。
- 原路径解析从程序目录/既有解析器解决，不依赖测试shell残留环境变量。
- 提供三端正常运行的成套 sidecar INI/JSON/QoS与依赖清单，保留原值备份，统一注释和Runbook。命令行覆盖留作诊断而非日常必需。
- 若不能在该环境自动点击UI，完成后明确列出仅该GUI动作未实测并给最小人工步骤；不能用隐藏窗口脚本结果冒充实际手动验收。

A阶段交付：普通启动无图根因报告、修复后的成套配置、三个程序的准确启动位置/最少操作、真实可见图像。分别验证全Windows DDS与混合RK DDS的必要启动路径；不恢复UDP/TCP验收。

### P12B：实际资产与已有成像效果回归

#### B1. 核销 P11 旧问题

将P11报告和失败日志中的问题映射到最终证据，特别是：SWIR积分/反射单位、tau近零、M1门、显示裁剪、太阳/主动光、局部热状态、RGBA32F/RGBA16F、低对比AGC、图像方向/精确裁切/黑角、模型纹理与材质ID。

区分 `FIXED_WITH_FINAL_EVIDENCE`、`UNIT_ONLY`、`HISTORICAL_FAILURE`、`REGRESSION`、`NEEDS_EFFECT_EVIDENCE`。旧PASS不无故重写，旧FAIL不因排除UDP/TCP就自动变成所有物理现象PASS。

保护P11浮点路径：Windows实际RGBA32F、RK实际RGBA16F/half_float/2-bytecomponent、800×800有效读回。对附件/捕获改动做小范围数值回归，不把关闭天气作为修复 `Failed to convert image` 的手段。

#### B2. 现有models资产真正进入普通程序

遍历 `HwaSim_IR/Bin/Config/TargetLib/models`，至少覆盖实际存在的4套资产；检查加载、导入拓扑警告、法线、单位/轴向/尺度、UV/MTL路径及Linux大小写、包围盒/裁剪/相机视角、材质ID与旧缓存。

原始文件不改写；必要时生成可追溯派生模型，记录几何/纹理源哈希。每个资产在SWIR/MWIR至少各有清楚可见的近景和不同视角图。提供模型在普通控制UI/既有配置里的选择方法，禁止只能通过P6测试注入目标类型才能显示。

本轮使用明确通用/合成材料和温度，用于渲染与材质绑定回归；不宣称对应真实装备物性。不要为“像红外”直接把RGB灰度当光谱反射率或发射率，也不要按名称套用民用车的热区ID。物理校验继续使用P11已知参数民用目标或普通受控样件。

不同高度/速度的指定资产测试用于位置、姿态、视角、投影尺度、更新与身份正确性；按真实大气查询覆盖预检。对高度/速度的热物理变化，用受控普通样件和明确合成参数另做因果测试，不还原具体武器的速度—热特征。

#### B3. 保留已有天气，定位真实贡献

先复现现有世界空间云/雨雪/热气流效果，保留几何、对象池、LOD、世界坐标运动、噪声动画、排序和标注关系。只修改有证据不正确的辐射单位、通道/波段分支、透过/自发射合成、透明度或后处理顺序。

- 云：采用确定性的测试fixture，把实际云体放入镜头，不把跟随目标的假背景作为世界云。保存实际world位置、包围体、种子、稳定cloudId、实际draw/cull状态与投影覆盖。
- 雨/雪：测试高度在天气作用区域内，记录实际Batch粒子数量、可见数量、有效像素覆盖、深度/alpha。明确粒子路径与Overlay诊断含义，修正误导日志；源码残留“UDP”诊断标签不意味着当前传输是UDP。
- 泛用尾焰/热气流：使用民用尾管/受控合成热源做on/off和视角对照，热源局部，不加热整模型；辐亮度与透明度分别处理，不双计路径辐射。不为提高SWIR可见度随意增益，合理微弱响应允许通过物理门，但不能假称视觉明显。
- 采用“近景材质诊断”和“天气空间展示”两套明示相机/FOV，保证所验现象在视野内。不得用错误场景几何的空画面声称云已通过。
- 开/关对比固定相机、仿真时间历程、温度状态、种子和显示窗口；AGC另存。每种天气除了开关日志，还应有真实几何/渲染贡献及对应ROI像素证据。

### P12C：三个coverage blocker与板端样片补齐

#### C1. 云前/云后、单cloudId

优先复用既有对象池和ID；缺稳定ID/元数据则补最小实现。不能用脚本编造不对应实际绘制对象的ID。

为测试记录相机、样件、云体世界坐标与LOS相交区间，分别运行clear、云在观察者与样件之间、云在样件后方。首次只隔离视线遮挡，固定入射照明/云影；再验证耦合，避免把后方云改变天空/太阳照明误判成深度错误。

至少两个可单独辨识云体，从该轮真实返回的ID集合逐个禁用/恢复；其它云ID和几何不变，保存掩码/贡献和原始像素差分。测试结束恢复正常生成配置，不在日常用户配置里残留fixture。

#### C2. 真实2km数据及普通场景覆盖预检

先调用实际查询器输出完整覆盖：波段、观察者高度、目标高度、LOS距离、能见度、湿度、太阳角、分量与单位/响应；不要只枚举某一列min/max就宣称全网格覆盖。

先补低风险普通受控场景确实需要的2km路径数据。使用已安装且获许可的PcModWin5/MODTRAN5和P11可用脚本，保留输入卡、原始输出、列解释、单位/Jacobian、积分响应和QC。只补缺项，原子合并，原未涉及数据逐字节/逐行身份可追溯。

不能夹到1km、用NIR改名、对现有波段均值指数外推、用经验缩放伪造真实MODTRAN。普通用户请求超出有效域时显示具体缺项及合法选项，不静默无图。

板卡运行维持离线；开发机使用本地已有工具。许可/可执行调用真实阻塞时给出日志和可执行的最小人工生成步骤，继续完成其它阶段，不把合成数据标为真实。

#### C3. 受控玻璃DDS与标定等级

保留现有单层直透模型，不扩展折射/Fresnel/多次反射。在板端用普通受控玻璃样件及已知前后背景做SWIR/MWIR、透过开关/背景变化对照，证明实际RGBA16F像素及DDS解码路径，不能以WGL结果替代。

保留 `NOT_VERIFIED_CALIBRATION`：没有真实材料样片光谱、温度和器件SRF/QE/光学/曝光测量，就不能声称真实目标或传感器精度。将工程实现、受控现象、实机链路、性能与真实标定分开，不让“没有真实标定”掩盖可解决工程问题，也不伪造整体验收。

缺失P11原始before图无法事后补拍；可回滚重建同条件基线，但明确标记RECONSTRUCTED_BASELINE。P12自己的修复前后图必须当轮真实保存。

### P12D：抓图开销、普通性能、生命周期和成套交付

#### D1. 先小样A/B，再长测

先用同版本同输入做短轮：普通配置诊断关闭 vs PFM抓取打开。将captureTaskMs细分为GPU等待/读回、CPU拷贝、格式转换、序列化、文件I/O，定位后改最小代码。

可安全异步的CPU存盘移到持有帧数据的有界队列，GL访问遵守上下文和渲染线程契约。必须保存单位、帧身份与配置；capture队列满要明确报告诊断阻塞/失败，不能偷偷丢所需证据或影响协议身份。采集器不替换实际生产DDS/编码输出。

首次绘制/着色器/材质/编码器准备可在READY前预热，但预热不消费真实sourceSeq，不推进真实热状态，不向用户发布假产品。分别报告启动到READY、首个真实输入到首帧与稳态延时；不得只删启动样本使统计好看。

#### D2. 性能门与测量语义

普通生产配置：800×800、DDS、RK MPP、真实Windows接收解码/显示；日常要求的录像、标注、天气保留，PFM和详细诊断默认关闭。不得降分辨率、复制旧图、改Latest、跳过已接受输入或改采样周期保FPS。

分别给出：

- 全轮输出FPS、明确剔除窗口的稳态输出FPS、实际GUI绘制FPS和最大帧间隔。
- 板端accepted→execute→render→output；接收端sample→decode→GUI消费/实际绘制。
- 跨机发送→显示仅在有时钟偏移/不确定度证据时报告，不直接相减不同机器steady clock。
- 冷启动与稳态的mean/P95/P99/max、>80ms数量、有效样本率；STOP开始响应、排空、末帧接收和录像完成分别统计。

保持“约60FPS”既有明确门并打印实测值，不能把59.8写成严格≥60。对原延时≤80ms要求使用独立判据：不因计数守恒PASS就放过超时；冷启动和稳态均完整报告，任一仍超标则相应性能项未通过，不事后改成百分位目标冒充原要求。
