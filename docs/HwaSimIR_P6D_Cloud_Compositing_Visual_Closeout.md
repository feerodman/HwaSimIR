# P6D 正常世界云透明合成与外观收尾

本轮已实施、完成 Windows/aarch64 构建、部署及实机测试。原黑带和零密度接缝已有直接修复证据；NVG 穿云动态显示跳变、近景锐度、代理深度精度和 NVG 严格无积压 60 Hz 仍未全面通过。

源码基线为 `95b810c477a327f44c3ba303dad99971159c6fe3`，与用户参考 HEAD 一致。开始时工作区只有用户未跟踪的 P6D 任务附件；未回退、清理或覆盖用户文件。原始状态、差异与文件哈希保存在 `logs/p6d/baseline/`。

本轮只处理普通世界云及其诊断与验收。NVG 默认 Auto、MWIR 默认 Game、低频 64×64 统计、单次 gamma/极性、DDS/OrderedQueue、MPP、Mali、原生深度附件均保留。没有修改业务目标温度、材料、热区、尾焰、发动机、气动、主动照明或协议，也没有接入独立传感器实验。

## 已经定位的原因

1. **二维人工灰纹先进入 G 通道，再被沿深度挤出。** 同一 NVG 输入序号 90、同一相机和 cloudId，冻结映射为增益 8、偏移 -3.038，保持 R 密度不变，仅令 artLight=1，贯穿黑带消失。缺陷区域为 x=70…669、y=475…579；原显示前公共缩放线性最小值 0.373535，背景约 0.41919。原编码前该区域有 146 个黑像素；关闭人工明暗后为 0。黑带在显示前浮点中已存在，Auto 的低端裁剪把其中一部分变黑；DDS 不是首次产生黑纹的位置。
2. **R 密度本身也是二维轮廓的厚度挤出。** 8/16/32/64 步使用实际 shader 上限 64；高步数减少局部采样噪点，但仍保留平滑的水平带。单云、关闭片云的结果也保留原带状结构，排除了“双云才产生”和“片云导致全部暗带”的解释。
3. **片云存在与真实密度无关的圆形挖空。** 零密度体积云仍按代理半径改变片云透明度，原 NVG/MWIR 的显示前最大差值分别为 0.0048828125 / 0.0101318359375。正常新云路径移除该挖空后，板卡两波段零密度与无体积云的全图浮点最大差值均为 0。

这里的 PFM 是公共缩放线性场景值，不是原始物理或光谱辐亮度。密度/源通道诊断图是可视化输出，源 RG 体切片和最终合成值分别保留。

## 合成正确性

体积 shader 累计预乘贡献，然后除以实际积分透明度，输出**非预乘颜色 + alpha**；Panda 使用 `source_alpha / one_minus_source_alpha`。保留深度测试、关闭深度写入，外部相机仅合成前面、内部相机仅合成背面。没有用更改混合因子掩盖源纹理问题。

每段密度取 R × 云描述密度 × 淡入系数；每段透射率为 exp(−光学厚度系数 × 密度 × 步长)。G 只影响人工源明暗，源色不再乘一次密度。累积颜色使用前段透射率 × 本段不透明度 × 源色，最终除以 1−总透射率得到直色输出。缓存 PNG 的 alpha 用于构建 R，不再作为 GPU 输出 alpha 重复相乘。

实际 GPU 普通数值图验证了背景 0.2、源 0.8、alpha 0.5 得到 0.5；同源背景改变 alpha 不变；同源双层与总透明度等价；不同源按明确前后顺序与 CPU 解析式一致。两波段最大误差均不超过 0.000171875，低于 RGB16F 验收容差 0.001。CPU 期望值来自独立 source-over 算式，不是复制 GPU 结果。

原 shader 的 alpha 上限 0.96 和透射率 0.03 提前停止仍是高光学厚度近似。本次单位源色诊断的双云最大合成透明度约 0.893，单云没有触及这两项门限；它们不能解释本次正常画面的暗带。未把这些有限范围测试宣称为任意光学厚度下的完整物理积分证明。

## 正常路径修改

- 保留正常 `IRWorldCloudStreaming` 的世界原点、网格、种子、概率、位置、尺寸和模板选择。双云是同屏预算。
- 从现有 cloud3d_001/002/014/020 的 alpha 轮廓选择稳定的三维云团中心；每模板 150 个不规则云团，在离线缓存中形成真正三维 R 密度。原 PNG 不修改。
- G 改为由三维密度局部梯度构建的人工明暗系数，不再挤出 PNG 灰背景。新人工系数按 Weather 标称源值归一；没有在显示端抬最低灰度、整体模糊或针对对象增益。
- 正常片云与体积云直接进行透明合成，移除与密度无关的圆形挖空。诊断旧缓存入口保留原算法，供同参数对照。
- Weather 保存投影尺寸质量档和同屏总采样预算。16、12、10 步双云吞吐试验未达稳定 60 Hz，不能标记通过；最终质量档须按以下实测表确认。
- 普通启动增加每回合 CPU `do_frame` 调用均值和最大值。它包括 GPU 等待，排除后续编码调用，不冒充 GPU 时间或 P95。

## 撤销的试验与无效数据

显式纹理 LOD 0 对异常没有改善，已撤销。仅替换 G 而保留挤出 R 仍有水平软带，未作为最终方案。沿竖直方向累积的人工遮光形成新的大片底部阴影，已撤销。保持旧 PNG 加权平均明暗的候选也未达到外观要求，未部署为最终档。

最初 Windows 数值诊断缺少 shader 输入，出现 Panda 断言；修正后重新运行。动态数值分支干扰了 Windows 正常纹理路径，改为启动时编译诊断模式，普通模式不包含数值卡分支。一次并行 Windows 检查错误复用了板卡 DDS 标识；对应重叠区间不用于结论，已用 `verified_b1_*` 重跑，Windows 此后使用 2001/2、2002/2。

最终图像矩阵曾有一次 MWIR 初始化失败：P3 策略要求 CPU policy0 最低频率 1200000 kHz，读回 1600000 kHz，启动器按原检查退出，发送器等待 INIT ACK 超时。记录保存在 `visual_b2_near_failed_init/`，没有成功图像，不纳入通过样本。检查发现测试器此前没有等待远端启动器 EXIT 清理完成，可能使恢复策略与下一次 apply 重叠；本轮只在测试器加入等待启动器退出的串行保障。没有关闭读回检查或修改生产 P3 策略；该偶发读回失败的唯一触发原因没有经故障注入证实。

## 世界一致性

公共原点为 WGS84 北纬 40°、东经 116°、椭球高 0 m；网格 2500 m、种子 12345，Weather 的 World 段逐字义保持。动画为 Static，不以实例启动时间或系统时钟改变云状态。模板清单仍按显式 T0…T3 与稳定 cloudId 选择，部署后的资源哈希随每个云描述输出。

两个实际 Windows 渲染实例使用不同相机与局部原点，第二实例晚启动 6 秒；8 个共同 cloudId 的公共位置、尺寸、密度、旋转、模板、资源哈希和静态状态完全相同。纯世界描述检查覆盖正负网格跨越、返回和反向加载顺序：37 个描述一致。Windows/aarch64 最大数值差 4.547473508864641×10⁻¹³，小于 10⁻⁶ 容差。最终压缩图不要求逐字节一致。

最终 Windows 实际跨网格返回场景产生 40 个 cloudId、55 次激活，重复激活描述没有变化；与启动实例的 8 个共同描述完全一致。最终 RK3588 渲染器与 Windows 渲染器也有 8 个共同描述，最大数值差 1.1368683772161603×10⁻¹³。证据为 `world_actual_return.json`、`world_actual_windows_arm.json`，均位于 `logs/p6d/`。

**NVG 的吞吐余量仍有限。** 600 秒内有 28475 次输入背压，累计回调等待 471344.868 ms；队列触及 16，停止后排空为 0。累计等待是多个输入回调的有界等待总量，不是视频停顿 471 秒。MWIR 同轮背压为 0。NVG 不能写成“持续无积压的严格 60 Hz 通过”；本轮确认的是约 59.77 FPS、最终逐帧完整且不溢出的有界排队运行。DDS 内部积压和跨机端到端延迟没有经独立时基测定，不作推断。

FPS 为约一秒窗口的实际解码／GUI 更新样本，仅省略首尾活动边界窗口；暂停和 INIT 间的内部零窗口保留，因此暂停组的全程均值不表示渲染速度。do_frame 包含 GPU 等待，不包括之后的编码调用；这里没有 GPU query 或逐帧 P95。长测温度来自只读 thermal sysfs；没有校时或改变系统时钟。

### 改前／改后耗时

使用同一普通世界相机、同为 8 步、无完整浮点诊断读取的旧缓存算法参考，60 秒 NVG/MWIR do_frame 分别为 14.022/13.951 ms；最终正常新缓存为 13.995/13.906 ms，差值约 −0.027/−0.045 ms，属于很小的变化，不宣称显著加速。原算法参考使用显式 `P6DLegacyCache=1`，不是伪称旧 ELF 的无覆盖普通启动。所有这些参考与最终普通测试均保留原接收文件。

16、12、10 步双云试验分别约 51.65、55.72、57.56 FPS，没有作为最终 60 Hz 档交付。最终同屏采样预算为 16，双云各 8；单云根据投影尺寸最高 16。不能将 `NearSteps=16` 误读为普通双云每朵 16 步。

## 图像口径与验收边界

主因果对照为每波段自身的输入序号 90、同一 `pair_mid.json` 相机、同一两个 cloudId、同一原 PNG 哈希。NVG 冻结增益 8、偏移 −3.038；MWIR 采用原 Game 固定参数。改变的是派生缓存和明确记录的云算法，未改变天气位置、尺寸和业务材质。不得把两波段之间的差异当成算法因果对照。

新增云团轮廓和内部层次替代了原来的平面挤出纹理。黑纹在编码前已消失，接收图和同路径移动视频也保留该改善；云没有被全部改为白色。近景细节仍偏软，MWIR 固定显示下内部对比仍较弱，交叠云仍是对象级前后排序；这些没有被判为全面画质通过。

### 穿越代理边界：保留失败结论

逐帧复查额外发现 **NVG 正式动态 Auto 在穿云路径有明显亮度跳变，画质未通过**。默认视频第 260→261 帧的 160×160 事件定位图平均差约 15.44 灰度级；已实际查看相邻原解码帧，跳变不是只由汇总数字推断。MWIR 相同路径除首帧建立场景外，最大同口径变化约 0.63，但内部细节也很弱。

为分开采样档切换和显示，另外运行两组恒定 8 步、同路径穿越，仅改变 Auto 是否冻结。动态显示第 261 帧仍有约 15.16 灰度级变化；冻结显示首 30 帧后最大约 1.90，支持动态映射是主要贡献，而不是只由 8／16 步切换造成。序号 262 的实际动态映射为 gain=6.9493588392883989、offset=−2.9220145084704594，统计序号 261；冻结为 8、−3.038。两次运动捕获的显示前浮点最大差为 0.0009765625，**并非逐像素完全相同的运动输入**，这项限制与中景静态同帧因果矩阵分开。

该穿越路径仍有低值裁黑，暗区还包含背景，不能将所有黑色自动称为云几何错误。本轮未为隐藏问题改变 Auto 默认、抬最低灰度或把云整体变白；也没有宣称近常量动态显示已在全部飞行路径定稿。隔离原图／视频、指定帧 PFM 和实际参数见 [穿越隔离结果](../logs/p6d/boundary_display_isolation.json)、[同序号显示对照](../logs/p6d/boundary_display_comparison.png) 及总览页。

## 明确保留的边界

云内物体仍使用代理表面深度近似；没有实现沿每条体积视线的精确物体深度裁剪、完整多重散射或全地形阴影。局部密度资源为 96³，近景仍有柔软和细节有限的问题；不能把黑纹与接缝修复直接等同于全部近景画质完成。

原有独立人工传感器 28 项单像元和 34 项二维测试均已回归通过，未增加功能、写生产参数或声称真实器件标定完成。
