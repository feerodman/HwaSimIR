## 二、必须先复核的已知问题

1. `1.txt` 前 659 数据行 ViewValid=0，第 660 行才为 1；60 Hz 逐行回放约 11 s 后才允许显示目标。首行坐标已有效，显示有效性不等于位置有效性。P13 最终两轮首条带目标标注 sourceSeq=663、PTS=11033 ms。
2. `HwaSimIR.cpp` INIT 的 `initCloudSpatialValid` 只检查有限数/经纬范围，随后设置 `m_isInitReferencePoint=true`；实时原点仅在此标志为 false 时初始化。INIT 位置因此提前成为正式基准，全零经纬高也能通过该初始检查。
3. 实际 `IRGameSpriteBatch::apply()` 以 shader priority=100 安装 `Config/GameVFX/sprite.frag`。该文件仍把 `u_plume_gray` clamp 到 0–1 并再次应用经验 fog；正式 CPU 却向此 uniform 传 SI 辐亮度。不要只改 HwaSimIR.cpp 内另一段未实际使用的尾焰 shader。
4. P13 plume QC 用绝对差，只能证明局部变化。原 ROI 重算 On−Off 均值为 −1.172232/255；78.20 不是辐亮度增加倍数，更不是正确热图证明。
5. DataDrivenTestQT 默认 `targetNumValid=1`，已有十六进制目标类型 QLineEdit 和 INIT 冻结。应改造为可见、好用的下拉框，不重复加一个未绑定的新控件。
6. P13 的 50 km 数据仅覆盖特定高空单元与 visibility=6 km，不能泛化为所有高度/能见度；外部生产不能依赖已知 1.txt 全轨迹。

上述静态线索要通过当前实际运行核实。报告区分“已复现根因”“待验证假设”“正常输入行为”。

## 三、P14A：正式原点必须来自首个有效实时平台位置

### 3.1 原点与生命周期

实现清晰的内部状态（名字可沿用已有设计）：

```text
RESET / 新 INIT
  -> 等待本世代有效实时平台位置
START
  -> 允许接收业务输入；没有有效位置则显示等待状态
首次可消费的有效实时平台位置
  -> 一次性提交正式参考，原子更新依赖，再绘制该业务帧
后续实时位置
  -> 在同一参考中更新，不重新锁原点
```

- INIT 可以提供初始参数和资源预热提示，但不能占用“首有效实时位置”锁。
- 拆开临时预热参考与正式 `m_geoTrans`/参考就绪标志。预热不能推进热状态、消费输入、发布假帧或决定世界云位置。
- 正式提交时同时刷新相机/平台/目标/标注坐标转换、天空地面参考、cloud render-to-world 与有关缓存。世界云使用公共地理坐标、稳定 cloudId；变换原点不能使世界云搬到目标上、重生或改变地理位置。
- 平台位置有效而目标尚未有效时，也能建立平台参考。目标后续使用同一参考，不能再以目标位置改原点。
- RESET、新 INIT/新 generation 清空本轮锁。STOP→START 同世代保持参考，除非既有协议明确定义为新场景；重复 START 不重设。过期/跨世代输入不得污染新参考。
- 合法坐标全部用 double 做地理转换，到渲染局部坐标后才按现有精度要求转换；不要用 INIT 与首包不一致作为修改外部输入的理由。

### 3.2 有效性与占位包：必须独立于 ViewValid

先检查当前 CommonData/IDL/adapter 的真实字段和语义，不凭名称发明协议有效位。

至少拆分：DDS 样本有效、路由身份正确、字段结构正确、平台位置有效、目标位置有效、显示 ViewValid、跟踪/指向有效、气象数据覆盖。

- 全零/无效占位不能建原点，不能查询地球另一边的大气，不能导致相机瞬移。
- `lat=0`、`lon=0`、`alt=0`、速度 0、姿态 0 均可合法；禁止“任一分量为0即无效”或“速度必须>0”。
- 如无独立位置有效位，与外部接口约定并记录“经纬高全零占位”的解释/配置。没有额外语义无法自动区分真实(0,0,0)与占位，要明确兼容方式，不假装检查能无歧义识别。
- NaN/Inf、非法经纬度、坏结构、错误身份需要明确拒绝原因；错误气象覆盖与位置无效分开，合法位置不应因光照数据缺失被换成另一个基准。
- 接收前/后 START 顺序、START后无包、连续占位、有效后再占位，都不能卡死控制响应。
- `ViewValid=0` 但坐标有效的原 1.txt 行仍按原协议处理，不能被当成坏包丢掉。对于几何有效但不显示目标的业务帧，继续正常生成对应背景/帧身份。
- 真正无效占位在业务接受前分类，不要为了维持“收到包数=输出帧数”伪造产品。保持 received、accepted、invalid/rejected 等分项守恒；保留外部原始序号与拒绝原因，不用重排/改号掩盖。
- 无有效输入时默认不制造新的物理产品；窗口明确显示等待/数据陈旧。有效后短暂无效可保持最后有效画面供观看，但不能给它新的采样身份冒称新仿真帧。
- 不改 CommonData/IDL 布局、不放宽 platID/sensorID、不将输入队列换为 Latest。

### 3.3 原 1.txt 开始隐藏的正确处理

原文件 SHA-256 必须保持不变。增加两种测试端显示策略，或者用已有等价机制：

- `FollowInput`：默认、协议回归；保留 ViewValid，预期约第660行才从隐藏转允许显示。
- `ForceVisibleForDemo`：明确的测试端覆盖，仅用于观察首有效几何的模型/热源；记录 inputViewValid 与 effectiveViewValid；不得变成外部生产的全局强制显示。

界面显示原因，例如“已接收有效位置，目标显示标志为0”，区别于“等待有效位置”“超出大气域”“目标在视锥外”。不能通过自动放大模型、改轨迹、改FOV或强制对准去掩盖真正投影问题。

补连续可见性变化即时刷新：ViewValid 从0到1时，节点/标注缓存的延迟要量化；首次允许显示、首次目标 draw、首次非空标注、首次接收图分别留证。目标不足像素时单列投影尺寸，不夸大为物理错误。

### 3.4 独立外部发送者验收（不依赖 DataDrivenTestQT）

复用现有 DDS client 写小型确定性 fixture，不建新控制协议。它不加载 1.txt，分别发送：

1. INIT位置A；START；若干秒无实时包；全零占位；首有效平台位置B（B≠A）与有效目标。
2. INIT位置全零；上述同样序列。
3. 首有效平台位置B，但 targetNumValid=0；后续才有目标有效位置。
4. 有效平台/目标坐标但 ViewValid=0；随后变1。
5. 有效后插入占位/NaN/越界/错误identity，再恢复有效；原点不变，旧画面不冒充新产品。
6. 合法零经度、零纬度、海拔0、静止速度0边界（分别测试），按接口约定处理真实全零地理位置。
7. RESET与新INIT到位置C，核查新锁；STOP/START同世代保持锁。
8. INIT/SWIR→MWIR→SWIR重新初始化与接收端重启，不恢复旧 referenceGeneration。

首个有效平台包在本世代正式消费时锁一次，以具体 input/source identity 记账。READY/INIT ACK 的资源就绪与“实时位置就绪”分别记录，不擅自扩大原ACK语义。未知未来轨迹不能强制通过控制端扫描文件预检。

## 四、P14B：修实际特效渲染，不用增益遮掩

### 4.1 建立全部实际 draw 的量纲表

逐项列出目标、喷口、sprite核心/光晕/烟、体积云、远云切片、Batch雨/雪、天空/地面、雾与主动光：

- 实际 shader 文件/优先级、输入来源、是否有节点继承覆盖；
- RGB单位（SI带平均/带积分/归一化显示）、alpha含义（覆盖率/不透明度/预乘）、blend函数；
- 渲染到raw还是display，实际FBO格式，深度/排序策略；
- 大气tau/path、太阳反射、显示映射分别在哪一层应用。

一张可审计表把单位边界说清，不用“common_linear”同时指两种量。沿用P13现有SI约定，带平均/带积分不可混合。

### 4.2 黑色尾焰的实际修复

先冻结当前场景/种子/温度/背景/极性，保存bug原图、外置shader身份、draw日志和raw；证明当前生产节点到底使用哪支shader。

- 修 `Config/GameVFX/sprite.frag` 与 CPU uniform 契约；正式SI不准clamp物理辐亮度到0–1，也不再走无量纲fog_gray/contrast。Legacy视觉路径如保留，必须显式隔离。
- 不能只改 HwaSimIR.cpp 内另一个 shader；检查priority=100继承、texture缓存、节点批处理与最后部署的外置文件。
- 审计 straight alpha/预乘是否匹配，mask/opacity/源发射是否重复乘，前景path是否被错误抹掉、重复加或多次衰减；核查核心、光晕和吸收烟是否被错误当成一种材料。
- 采用通用发射—吸收介质基准：逐光谱通道、均匀无散射近似下 `L_after = T_medium*L_behind + (1-T_medium)*B_lambda(T)`，再按有效响应积分/平均。若采用更一般源函数或近似，写清假设及单元基准。
- 此公式各项必须在相同光学平面；已有sensor-space背景内含前景path时，不得再整体乘一遍大气。用推导或数值参考保证前景path只计算一次。
- 热介质面对更冷背景、固定白热单调映射时应按基准增亮；冷吸收烟面对较亮背景可以变暗；黑热极性应只改变显示，raw不变。
- 禁止“尾焰永远白”“clamp成1”“全局加热”“改tau=1”“大幅加显示增益”作为修复。不得为真实军用喷流反推参数；使用通用加热气体/民用排气和人工测试温度。
- 模型绑定检查使用卡车排气口/通用喷口的本地坐标与轴向，不把小汽车或其它旧模型尺寸直接套用。需要资产派生则保存来源和改动。

### 4.3 定量门替换绝对差门

使用实际 sprite 管线的受控案例，不只使用另一个 nozzle fixture：

- 两波段，热源off/on/冷吸收，白热/黑热，冷/亮背景，前景遮挡。
- 先以已知光学厚度/温度/光谱响应建立独立CPU基准，再比较GPU raw。
- raw ROI记录mean/on−off/signed error/relative error/positive-negative pixel count；近零值采用绝对误差，不能用不稳定相对误差刷通过。
- 固定映射RGB8、正常AGC、真实DDS decoded分别验收；AGC不用于证明辐亮度大小关系。
- 热源局部贡献和背景控制区同时检查；“像素变了”不是唯一门槛。
- 透明边缘/黑框/背景抹除/排序跳变、NaN/Inf、FBO格式/裁切错误均需专门检查。
- 容差先冻结；参考P11/P13相同数值条件可沿用既有GPU误差门，不能测完后扩大。

### 4.4 天空、地面、云、雨雪一起修正确的单位层

保留已有世界云位置、稳定ID、对象池、LOD与Batch几何；先修其进入新raw域的消费契约，不无依据推倒重写。

- 审计所有外置高优先级特效shader，尤其 `Config/Weather/precipitation.*`，防止仍向SI buffer写0–1经验灰度。
- 正式天空/地面/云与目标使用一致单位和公共显示映射。保留可说明的温度/反射/散射工程近似，不靠整屏固定灰色假装物理背景。
- 云前/后深度、单cloudId隐藏、相机运动视差、穿云连续性维持；参考原点变动不导致云漂移/重生。
- 区分能见度引起的大气传播与显式云/雨/雪粒子；防止MODTRAN与经验雾重复衰减。常数灰度雨雪只能在显式display-only演示层，并明确不当作物理raw证据；正式目标是接入本轮统一物理/可审计近似链。
- 原1.txt高空场景不强行塞入低空云雨雪；另外建立明确的民用地面卡车天气场景。需要人工几何覆盖测试时标注synthetic，不修改原轨迹。
- 不把烟/云/雨/雪都强制做亮；判断基于波段、照明、介质源函数和背景。
- 太阳角影响反射与热惯性分别检查；主动照明检查光谱重叠、开关/指向与两段传播，带外光不应凭标签产生带内亮斑。

## 五、P14C：实际需要哪些MODTRAN数据

现有P13高空50km、原轨迹完整查询和旧近距数据优先复用，不全部重跑。

先生成两个独立覆盖报告：

1. 原1.txt全量生产查询：保持8636条双波段基线，实际环境一致。
2. 通用外部/卡车混合工况：按实际位置、高度差、距离、能见度、RH、太阳角与数据分量查合法单元，不以原轨迹包围盒代替通用域。

本轮至少补足用于混合测试的多档能见度（优先复用现有6/12/23km体系，并按实际所需合法顶点补齐），同时覆盖选定太阳角。高空与地面卡车的数据单元分开生成/复用，不把两者拼成未经验证的完整轴笛卡尔积。

最大50km验证仅在声明的完整环境单元内承诺。项目如继续要求3–20km观察/目标高度，必须在manifest和验收中明确哪些已覆盖、哪些待补；不能把P13约11km的小范围写成3–20km全域。构建稀疏/分块网格与分量复用，避免不必要的全组合爆炸。

- 原始MODTRAN列/单位/Jacobian/响应积分、完整分量、合法几何、插值留出点误差都必须QC。
- 不把带平均tau的距离插值当作普适Beer定律；以新生成中间点验证误差，必要时细化网格。
- 同时检查太阳宽谱加热LUT的高度/太阳条件，不能只补相机波段表。
- CPU与GPU采用相同几何/高度基准。几何位置不能为满足LUT被挪动。
- 板端按外部有效实时样本验证当前查询，未知未来数据不靠1.txt预检兜底。manifest/LUT哈希验证保留，`OriginalInputSha256`只作测试血缘，不成为外部业务必须携带的信息。
- 超域明确告警与状态处理；不外推夹距、不填零、不重用上一合法光照冒充当前物理有效。
- 许可/软件确有外部阻塞时给日志和最小人工步骤，继续其它不依赖该阻塞的修复，不伪造数据。
