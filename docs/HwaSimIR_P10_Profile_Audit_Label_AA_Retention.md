# P10 配置核验、文字避让、AA 与版本保留

本轮从 `c72622cad7802efe8f58a84d86d26855ce9b666b` 的脏工作区实施。开始时记录的 49 个用户文件保持原始字节；未回退提交，未修改模型几何、UV、温度、材料参数、热区、尾焰、主动照明或协议。SWIR/MWIR 是后续优先级，当前生产入口仍只接受已支持的 NIR/MWIR。

## 1. 光谱配置与数据

独立工具 `tools/p10_profile_check.cpp` 链接生产 `IRConfig.cpp`、`IRTypes.cpp` 和现有路径解析器。配置检查、显示支持与大气覆盖分别报告，不能把任一项当作整体 loaded=true。

| 文件 | 实际范围 μm | JSON 解析 | 固定范围校验 | 正式显示/运行入口 | 正式大气覆盖 |
|---|---|---|---|---|---|
| default_VIS-SWIR.json | 0.5–1.7 | 通过 | 失败：现有 VIS 枚举固定 0.4–0.7，亦无 VIS-SWIR 宽谱枚举 | 未支持，旧 schema | 缺失 |
| default_SWIR.json | 1.5–2.5 | 通过 | 失败：代码 SWIR 固定 1.1–2.5 | 未支持，旧 schema | 缺失 |
| default_MWIR.json | 3–5 | 通过 | 通过 | 通过，schema 1 / Game | 已有 3–5 μm 数据 |

范围比较容差为 `1e-4 μm`。旧文件没有显式单位字段时，单位来自既有加载器契约；新增明确的 `HwaSimIR.SpectralUnit` 校验，错误 nm 不会被当成 μm。失败后保留请求文件、原始范围和错误，状态为 `UNAVAILABLE`；不再拿缺省 NIR/MWIR 数据标成失败的请求波段。INIT/START 增加入口保护，CommonData 布局不改。

旧天空构造的 INIT 前日志仍可出现 `band=SWIR`，不能据此声称生产 SWIR 已启用。实际 MWIR 请求的 `init-command` 配置、显示和运行天气日志均为 MWIR；本轮验收取实际 INIT 后消费结果，未扩展启动前天空构造逻辑。

18 项独立进程检查包括三个正式文件、单位、边界容差、缺字段、类型、错层同名字段、缺失显示预设、错误 JSON、重复字段、尾随垃圾和非有限数。检查器逐个输出明确 JSON 路径、类型、消费契约、预设归属与请求配置是否具备使用条件；`eligibleForThisProfileRequest` 不表示运行时已经消费。Width/Height/FOVH 只作无效接口几何的缺省；有效 800×800 不受 profile 宽高覆盖。旧 FXAAEnabled、ReflectionsEnabled、噪声/QE/曝光等 true 或数值不代表模块已运行。

正式 `manifest.csv` 与 SI 波段表已经包含 NIR 0.7–1.1、MWIR 3–5。SI 表为 NIR 1005 行、MWIR 335 行；原始执行清单的 case 数与聚合 LUT 行数不是同一统计量。原始 MWIR 输出元数据为 2000–3333 cm⁻¹，不能扩充为 SWIR 数据。已有逐波数输出只能在实际覆盖及原场景内进一步核查复用，不能用波段均值代替光谱。本轮未运行新的 MODTRAN 网格。

独立 `ordinary_sensor_lab` 仅使用既有 synthetic MWIR 配置完成一次 800×800 人工图像运行。其输入和参数未改，未接生产图像或目标链，不代表真实器件或目标标定。商业示例中的外部资料仅核对 12 条既有引用是否存在，不复制、不分发。详细证据见交付包中的 profile 与 coverage 数据。

## 2. 用户新模型与文字

三个新 OBJ 的 MTL 含旧机器绝对纹理路径，F35 的 JPG 大小写还与 Linux 文件名不同。初次实机预检因此报纹理加载错误。`p10_prepare_portable_models.py` 生成带源 OBJ/MTL 身份的路径派生文件，只改 mtllib/map 路径；所有几何、面索引、UV 与其余材质行保持不变。原始用户文件不改写。运行时按当前源文件 FNV 身份选择离线派生文件，不扫描目录，也不会把更新的 OBJ 配上旧派生文件。部署同时携带源、派生文件与 SHA256 清单。

文字布局使用实际 Panda TextNode 字体包围盒和阴影留量。对象身份排序、近邻候选、边缘约束和细引线只作用于文字位置；点、框、坐标字符串与保存记录保持原值。保留全部必需标签，无省略号。后续帧先保留原位置附近候选，吸收坐标数字变化产生的字体宽度变化。

16 组实际字体测试覆盖重合点、密集点、五组普通对象、四边与角落、800×800、640×480、1024×768、400×400。每组 20 个标签，无重叠/溢出；记录逐字段序列不变；同帧重复和对象重排位置一致。1 像素输入移动的标签最大位移为 8 像素（边缘字宽变化）。初版边缘标签曾跳 717 像素，已撤销只保留候选序号的方案；改为附近位置保持后通过。有限画面无法容纳任意数量/长度的文字，无法排下时明确记录 overflow，不删标签。

## 3. AA 与实机验收

候选包括 Off、2× MSAA、4× MSAA、单帧方向边缘 AA。方向 AA 在文字叠加前、公共映射前执行；平坦区域早退，不使用时间历史。保留 RGB16F、原生深度和 P8 精确读回，输出与标注坐标保持 800×800。

同一个 A7 版本、同一普通几何和 sourceSeq=180 的四档对照如下；显示前公共缩放 PFM 的 SHA256 全部为 `e4386aa4d3c59df598be43ecbbea8bb51f301767ff23114d65d3ac909609185c`。这是公共缩放线性图，不是原始物理谱辐亮度。

| 请求 | Panda 声明 | 实际附件采样 | 编码前相对 Off 改变的像素 | doFrame 中位 ms | 判定 |
|---|---:|---:|---:|---:|---|
| Off | 0 | 0 | 0 | 9.5725 | 基线 |
| 2× MSAA | 2 | 0 | 0 | 8.7325 | 未生效，不通过 |
| 4× MSAA | 4 | 0 | 0 | 9.4803 | 未生效，不通过 |
| EdgeAA | 0 | 0 | 10617 / 640000 | 9.2727 | 通用画质候选通过 |

2×/4× 不仅 PFM 相同，编码前 RGB8 也逐像素等于 Off。不能称为真正多重采样参考，也不据此判断硬件所有路径均不支持 MSAA。原生 FBO 查询前后均完整：`0x8CD5`；颜色 RGB16F `0x881B`，深度 DEPTH24_STENCIL8 `0x88F0`；附件分配 1024×1024，保留既有 800×800 有效视口与精确裁切读回。所有实际 GL 查询 error=0，无 GL 0x506。

EdgeAA 在圆轮廓、斜边和细线处减少像素台阶；低面数球/圆柱的轮廓折线仍在。棋盘细格角部更软，是单帧空间滤波的明确取舍。预先指定的平坦背景、球内平坦 ROI 与 Off 最大差值为 0。没有全屏模糊或锐化后处理。短测的中位耗时差异不足以宣称加速，也未见明显新增成本，故不扩展 3–5 分钟矩阵。正常配置使用 `Render/PostprocessAA=EdgeAA`，`MSAASamples=0`；改回 Off 可撤销 AA。

A7 普通移动/遮挡 60 秒：3600 条发送、接受、执行和保存产品逐一对应；MP4/SEI、正文与索引逐帧通过。包括启动阶段的新图为 59.9667 FPS，实际输入 59.9943 Hz，满队列回压/覆盖/溢出均 0。接收估计延时有效比例 98.80%，有效样本 P99=35.88 ms、最大 39.02 ms；无可靠估计的启动样本不冒充精确延时。板端单机接受至执行最大等待 124.82 ms 仍保留。A8 再测普通图形 60 秒为 3600 产品/59.95 FPS；其 sourceSeq180 的 PFM 与编码前 RGB8 和 A7 EdgeAA 完全相同。

Windows 实测发现新增诊断回调继承 Panda 基类内存池导致尺寸断言，A8 已为派生类声明自身分配池。先行 Windows 构建漏传 `FFMPEG_ROOT`，得到 `ffmpegCompiled=0` 并使额外 Windows 生产端 H264 测试失败。使用仓库既有 `.deps/ffmpeg-n8.1-win64-gpl-shared/ffmpeg-n8.1-latest-win64-gpl-shared-8.1` 重新配置增量构建后，A8 的 241 帧和 A9 的 242 帧 H264、标注、索引均逐帧通过；没有安装或升级 SDK。Windows 实际 GL 附件采样数仍标为未测，不能用 RK3588 的查询值代替。

四角复核还发现早期 EdgeAA 的 12 个边缘像素采到纹理边界色，最大偏差 18/255。A9 将额外采样限制到有效视口的半像素中心边界，消除亮角；Windows 四角与背景均为 RGB(150,150,150)。这是最终 AA 修正，不通过裁切删除边缘。最终交付的 EdgeAA 图和局部对比使用 A9；Off/2×/4× 保留 A7 同帧参考，并以完全相同的显示前 PFM 验证输入一致。版本和原始样本在 CSV 中明确区分。

已有 AIM9X OBJ 导入仍出现两次非简单多边形三角化提示，未在本轮改写其几何。新 F35/F22/AIM120 的旧绝对纹理路径问题已解决；这不等于所有模型拓扑、材质语义或关键点位置已标定。

Panda FrameBufferProperties 声明值不能作为实际采样数。诊断在原始场景 draw callback 前后分别查询真实 GL FBO、附件格式、采样数和完整性；不更换附件，恢复查询触碰的绑定。诊断只按显式入口执行一帧。相关 API 行为参照 [Panda3D 官方 AA 文档](https://docs.panda3d.org/1.10/cpp/programming/render-attributes/antialiasing) 与 [1.10.15 GLGraphicsBuffer 源码](https://github.com/panda3d/panda3d/blob/v1.10.15/panda/src/glstuff/glGraphicsBuffer_src.cxx)，本机实际查询优先于配置推断。
